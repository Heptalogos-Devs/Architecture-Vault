# 认知种子与静态自我档案

## 已确定的设计

Cognitive Seed 是主体初始化来源，不是运行时人格提示词，也不是不可变化的人格权威。它由人类编写、版本化保存，主体创建时绑定精确版本并保留实例快照；后续 Self、Memory、Social 和 Motivation 可以从该来源形成自己的认知对象。

中期实现可以先使用只读的静态 Self Profile：主体创建时把 Seed 中属于 Self 的内容展开为少量结构化 Markdown 文件，在运行时读取但不自动改写。这样能够建立独立 Self 子系统和稳定的人类可编辑入口，又不提前实现复杂的 Self 演化。

## 来源文档与认知状态

Cognitive Seed 的职责是描述主体的初始设定。它保留作者当时写下的原文，因此需要：

- 稳定版本身份；
- 完整内容摘要或快照；
- 作者、导入来源和时间；
- 主体实际采用的是哪一版。

主体后续变化不能修改这份历史来源。Self 演化的是由 Seed 形成的认知，而不是回头重写“主体最初被怎样设定”。

新的 Seed 版本可以用于创建新主体，也可以通过显式导入影响已有主体。后者产生新的来源和认知提案，不能把旧历史伪装成来自新版本。

## 内容组织

Seed 可以是一份带章节的 Markdown，也可以拆成少量文件。逻辑上至少可以覆盖：

- 基本身份和自称；
- 自我认知、能力和局限；
- 人格倾向和互动风格；
- 价值与长期偏好；
- 叙事起点和重要背景；
- 初始经历或知识；
- 初始人物、关系和社会语言约定；
- 初始愿望、关切和期望条件。

这些部分的语义归属并不相同。供给流程根据内容把初始化提案交给对应领域；Seed 自身不拥有一个跨 Self、Memory、Social 和 Motivation 的“超级人格状态”。

## 中期静态 Self Profile

为了 2026-10-27 中期检查，可以先固定 Self 的实现范围，不实现自动人格演化。推荐的实例文件是：

- `identity.md`：名称、自称、基本身份和主要角色；
- `self-concept.md`：主体如何理解自己的能力、特征和局限；
- `personality.md`：人格倾向、表达与互动风格；
- `values.md`：价值取向、稳定偏好和长期重视事项；
- `narrative.md`：主体对自身来历、重要背景和连续性的初始叙事。

这些文件是主体实例对 Seed 的 Self 部分的只读展开。中期运行时可以把它们作为 Self context contribution 使用；不需要为每个文件建立自动学习、修订、冲突合并或数据库对象模型。

如果时间允许，可以给文件保存来源版本、内容摘要和加载记录，使中期展示能够说明 Self 已经独立于 Memory，并且具有确定的初始化来源。

## 对 OpenClaw 文件模式的借鉴

OpenClaw 使用 `SOUL.md` 表达人格、价值和交流风格，使用 `IDENTITY.md` 保存名称、形象等身份信息，并在会话启动时把这些 Markdown 内容加载进运行上下文。这证明了“少量人类可编辑文本文件作为人格/身份入口”在工程上非常直接。OpenClaw 官方文档也明确把 `SOUL.md` 定位为 voice、stance、style，而不是人生历史或安全策略大全。

Nous Wave 借鉴的是文件形态和人类可编辑性，不采用“这些文件本身就是长期人格真值”的运行模型。长期目标仍然是 Self 领域拥有可追溯、可修订的认知对象；静态 Markdown 只是中期实现和未来 Seed 编辑入口。

## 安全职责

Seed 或 Self 文件可以描述主体自己的价值、偏好和表达原则，但不能承担产品安全和管理员强制控制。安全政策、工具权限、对外效果限制和管理员强制行为由 Heptalogos 的规范与行为权威执行。

这样可以允许主体认知自然演化，同时避免“修改人格文件就能解除安全政策”的结构性问题。
