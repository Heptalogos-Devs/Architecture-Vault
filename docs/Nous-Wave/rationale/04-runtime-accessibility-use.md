# 使用事件与可访问性

## 已确定的设计

检索过程日志与长期使用事件分别维护。需要长期保存的使用事件由调用方提供稳定事件标识，并具有幂等语义。

自动可访问性是查询时派生状态，不是长期认知真值；固定年龄阈值不能决定一项认知是否仍然存在。

## 检索轨迹与使用事件

检索系统内部会产生候选生成、召回、排序、过滤和材料展开等过程记录。把这些记录全部写入长期认知事件日志会产生两个问题：

1. 一次查询可能生成数十到数百条内部记录，长期日志被检索实现细节淹没；
2. 检索系统自己的输出可能反向增强未来排序，形成自我强化。

因此，这些记录属于检索轨迹和诊断。

长期使用事件只记录调用方真实发生的认知交互，例如：

- **呈现**：认知确实进入调用方可见上下文；
- **引用**：调用方明确引用或依赖该认知；
- **据此行动**：后续行为基于该认知；
- **结果支持 / 结果反驳**：后续结果支持或反驳这次使用；
- **纠正**：这次使用触发了纠正流程；
- **固定**：显式要求保持可访问。

仅被呈现不等于有意义使用。

## 幂等语义

如果宿主发送“引用记忆 M42”的使用回执后网络超时，再重试同一操作，系统不能把它记成两次真实使用。

每个需要持久记录的事件由调用方生成稳定 `event_id`；批量请求可以另有 `request_id`。持久层至少以 `(subject_id, consumer_id, event_id)` 建立唯一性，并保存规范化事件摘要。

语义如下：

```text
相同 event_id + 相同摘要
→ 返回同一幂等结果

相同 event_id + 不同摘要
→ 返回幂等冲突
```

使用事件和由该事件直接产生的驻留状态或“最近有意义使用”更新需要在同一事务中提交。

## 可访问性与其他状态

长期认知至少需要区分：

- **持久存在性**：认知是否仍由权威层保存；
- **可访问性**：当前线索和上下文下取得它的难易程度；
- **相关性**：它与当前查询的相关程度。

抑制和清除属于另外的管理生命周期。

固定 90 天、365 天一类年龄分档可以作为实验基线，但不能成为目标语义。很久以前形成的认知，在新的精确线索和上下文下仍可能高度相关。

## 可访问性候选模型

一个可用于实验的“时间 + 类型化使用”模型族为：

\[
A(m,t)=\log\left(\epsilon+\sum_i w(k_i)\left(1+\frac{\Delta t_i}{\tau}\right)^{-d}\right)
\]

其中：

- \(m\) 是认知对象；
- \(t\) 是当前时间；
- \(k_i\) 是第 \(i\) 次有意义使用的类型；
- \(w(k_i)\) 是该使用类型的贡献；
- \(\Delta t_i\) 是该事件距当前时间的间隔；
- \(\tau\) 是时间尺度；
- \(d\) 是衰减参数；
- \(\epsilon\) 提供有限的基线项。

这个公式只是候选模型，不属于目标设计。至少应比较：不衰减、仅时间衰减、时间加类型化使用，以及进一步考虑当前线索和上下文的模型。

评测同时记录召回率、错误遗漏、噪声、查询成本和长期稳定性。只有更复杂模型在实际工作负载中持续改善质量—成本关系时，才值得增加长期维护成本。
