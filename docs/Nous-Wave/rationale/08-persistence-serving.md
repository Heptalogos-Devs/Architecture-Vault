# 持久认知与服务投影

## 已确定的设计

长期认知分别使用稳定对象身份、不可变内容修订、对象纪元和主体范围的权威提交序号。检索服务是可重建投影。模型调用和网络访问不放进权威写事务；幂等结果与权威写入在同一事务中提交。

## 对象、修订、纪元与提交序号

把“内容版本”和“对象当前状态”压进同一个版本号，会迫使抑制、恢复等非内容变化制造无意义的内容修订。

目标模型分别使用：

- `object_id`：稳定语义对象身份；
- `revision_id`：不可变内容版本；
- `object_epoch`：当前对象头、生命周期、访问策略等可变状态的并发版本；
- `authority_seq`：同一主体范围内有序的持久提交位置。

例如，抑制和恢复可以改变生命周期与对象纪元，但不需要复制一份内容完全相同的新修订。

## 统一写事务

建议的语义顺序为：

```text
验证请求、操作者和引用
开始事务
  分配主体权威提交序号
  按稳定顺序锁定目标对象
  检查幂等标识
  检查预期对象纪元和当前修订
  重新核验证据、来源、访问控制和生命周期
  写入不可变修订和关系
  更新对象头、生命周期和纪元
  记录权威变化和待发布事件
  保存幂等结果
提交事务
```

模型调用、网络搜索和其他不可控外部操作放在事务之外，避免长事务以及无法重放的外部副作用。

## 服务投影

权威变化记录哪些服务投影类别需要失效或更新，以及对应输入水位。不同投影可以独立重建和发布。

查询最终返回前仍重新核验所选 Authority/revision view、生命周期、当前访问控制以及抑制和清除状态。历史 Serving 按 effective-state digest 复用且不发布为 current，候选生成前的隔离原则见[时间、概念与查询](11-temporal-concept-query.md)。因此，过期索引最多造成召回质量下降或显式失败，不能把旧数据提升为权威认知。

## 不可变对象库

大型材料和二进制对象采用以下写入顺序：

```text
写入临时对象
→ 计算并校验摘要
→ 发布不可变对象
→ 在权威数据库事务中提交引用
```

崩溃留下未被引用的对象可以由垃圾回收清理；已经提交的数据库引用指向不存在的对象则违反可靠性合同。

## 主体分支

分支操作创建新的主体标识。分支点之前的不可变历史可以通过写时复制共享；分支后的对象头、对象纪元、服务代次和管理生命周期独立。

恢复同一主体与创建新分支是两种不同的管理语义，不能只依赖底层快照机制隐式区分。
