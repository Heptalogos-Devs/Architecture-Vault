# 2026-10-27 记忆参考能力交付计划

## 目标

在不提前冻结完整 Self 演化、社会认知和动机实现的前提下，把记忆做成 Nous Wave 第一条完整纵向能力：从观察与证据，到长期记忆、检索、使用回执、生命周期、恢复和来源追溯全部闭环。

该交付用于 10 月 27 日大创中期检查，同时作为后续认知领域下降到规格和代码的工程范式。

中期同时提供一个独立、静态的 Self Profile，使主体具有稳定身份、自我认知、价值和叙事入口。Self Profile 不承担自动学习与演化，不成为记忆系统的一部分。

## 必须完成的语义

- 原始材料、观察事件、证据与来源谱系；
- 记忆对象、不可变修订和对象纪元；
- 认知角色与形成方式；
- 认知指向与来源提及分离；
- 修正、重新解释与矛盾关系；
- 抑制、恢复与清除；
- 幂等的长期使用事件；
- 自动可访问性不依赖硬年龄淘汰；
- 精确、实体、词项和稠密基础检索；
- 固定查询计划、对象级多视图聚合和稳定融合；
- 返回前重新核验权威状态；
- 服务代次、重启恢复和来源追溯。

## 静态 Self Profile

主体创建时从 Cognitive Seed 的实例快照中取得 Self 部分，并展开为少量只读结构化文档。中期推荐：

- `identity.md`：名称、自称、基本身份和主要角色；
- `self-concept.md`：主体如何理解自己的能力、特点和局限；
- `personality.md`：人格倾向、表达和互动风格；
- `values.md`：价值取向、稳定偏好和长期重视事项；
- `narrative.md`：主体对自身来历、重要背景和连续性的初始叙事。

原始 Seed 版本保持不变；主体实例保存采用版本和内容身份。中期运行时可以把这些文件作为 Self context contribution 使用，但不自动改写文件，也不实现 Self 的证据驱动修订、冲突处理和人格学习。

安全政策、工具权限和管理员强制行为不写入这些文件承担执行责任，由 Heptalogos 的行为与规范权威控制。

## 不作为中期硬依赖

- Self 的自动演化、修订和学习；
- 社会认知；
- 动机和期望条件的完整实现；
- Heptalogos 主动追求状态；
- 完整离线认知；
- 完整日记；
- 认知图式的高级形成、拆分和合并；
- 高级联想拓扑；
- 主成分、残差、竞争式传播或 PageRank 成为默认算法。

这些能力继续设计和研究，但不为中期展示降低长期架构质量。

## 执行顺序

### A. 更新代码仓架构与决定

把 Vault 已确定的记忆、使用事件、查询计划、服务投影和权威语义同步到 Nous-Wave 代码仓库的架构与设计决定。旧执行规格不继续作为新施工依据。

同时定义中期静态 Self Profile 的最小加载合同，但不把临时文件实现写成长期 Self Spec。

### B. 记忆语义规格

冻结：

- 对象、修订与对象纪元；
- 认知角色与形成方式；
- 证据、认知指向与时间；
- 陈述性记忆的对象身份连续性；
- 证据来源依赖与独立佐证的表示；
- 矛盾、修订和生命周期；
- 访问策略、抑制与清除；
- 长期使用事件语义。

### C. 检索规格

冻结：

- 认知查询；
- 固定查询计划；
- 检索通道合同；
- 服务视图身份与对象级聚合；
- 参考融合基线；
- 诊断与降级；
- 返回前权威状态核验。

### D. 持久化与接口规格

具体到：

- SQL 数据定义；
- Protobuf / API；
- 事务顺序；
- 幂等语义；
- 比较并交换与对象纪元；
- 服务投影失效；
- 错误语义；
- 恢复与清除。

### E. 实现与资格验证

先关闭语义正确性，再进行高级算法实验。验收覆盖干净安装、重启、重复请求、过期服务投影、抑制、清除、来源追溯和查询稳定性。

## 中期演示主线

1. 创建主体并加载静态 Self Profile；
2. 摄入多条消息或材料，形成观察与证据；
3. 形成多条长期记忆；
4. 新证据触发修正或矛盾关系，同时保留历史和来源；
5. 使用不同表达通过实体、词项和稠密检索找回；
6. 展示“被召回或呈现”不会自动强化；
7. 使用稳定事件标识报告真实引用或据此行动；
8. 重启服务后认知状态、Self Profile 来源和来源谱系保持一致；
9. 执行抑制和恢复；
10. 从记忆精确追溯到观察事件和来源区域。

如果主链提前稳定，可以增加小型社会认知原型作为额外演示，但不得占用记忆正确性的交付预算。
