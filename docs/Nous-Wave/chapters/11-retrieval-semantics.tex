\chapter{检索语义模型}

\section{认知查询表达语义意图}

面向调用方的认知查询（Cognitive Query）表达主体、领域和对象范围，包含硬约束、软偏好、语义线索、时间意图、实体与语义指向、调用方能力组合、计算预算以及所需来源信息和诊断。具体检索算法由查询计划和服务实现选择。\cite{nous-research-package}

硬约束决定候选是否合法及能否返回；软偏好只影响合法候选之间的排序。精确读取直接按身份和当前版本取值，不经过向量检索。检索失败必须能区分：Authority 中不存在、projection stale/unavailable、ACL/lifecycle 过滤、来源不可用、预算不足、线索不足或真实未知。

\section{固定查询计划与检索通道}

QueryPlan 在读取任何候选结果前冻结本次查询的检索通道、各通道预算、融合权重、拓扑预算、重排策略、材料展开预算和一致性要求。某个已计划通道没有产生候选时，其贡献为零；不能因为结果集合中“恰好出现了哪些 evidence family”而改变其他候选的分数尺度。

\section{候选身份与多视图聚合}

候选核心身份由 SubjectId、owner/object id 和 revision id 构成。Serving view 可再带 \texttt{view\_id}、类型、序号和 embedding-space identity。同一 revision 的 canonical、passage、grounded cue 或其他多个 views 是同一个 cognition 的不同检索表示，不构成多份独立证据。

因此各 lane 首先在 object/revision 层聚合 view hits。Reference Profile 可以使用 best-view rank 作为简单基线；若后续需要第二、第三视图贡献，必须使用 capped aggregation 并通过 benchmark 证明收益，不能按 view 数量直接累票。

\section{固定计划的跨通道融合}

强基线采用 weighted reciprocal-rank fusion：
\[
S(o)=\sum_{\ell\in L_{\mathrm{plan}}}
\frac{w_{\ell}}{k+r_{\ell}(o)}
\]
其中 $L_{\mathrm{plan}}$、$w_{\ell}$ 和 $k$ 在生成候选前确定；对象没有某通道结果时贡献为零。如果需要归一化，分母也必须由固定 QueryPlan 推导，而不能依赖本批候选出现了哪些 family。

Topology 作为正常 lane 输出对象级排名，再参与相同 fusion。不得在融合完成后偷偷叠加无法从 QueryPlan 解释的 \texttt{field\_contact}、\texttt{topology\_innovation} 等连续 bonus。若产品需要结果多样性，在 final selection 明确实现 diversity policy，并单独记录其作用。

融合权重不是认知真值；默认取值由目标 corpus 和 workload 的 recall/precision/stability/cost 实验确定。

\section{硬过滤、预算与最终权威校验}

能够下推的 Subject、owner、生命周期、ACL、时间、modality 和 exact identity 条件应尽早过滤。ANN 在过滤条件下使用有界 adaptive over-fetch，并在预算耗尽时显式报告 \texttt{BUDGET\_INSUFFICIENT} 类诊断，而不是把没有找到候选统一解释为“未知”。

候选融合和可选 rerank 后，在 materialization/return 前重新校验当前 revision、object epoch/lifecycle、access policy、ACL、来源有效性和 purge/suppression 状态。Serving generation stale 时可以降级、重建或明确失败，但不能把旧 projection 当成 Cognitive Authority。

\section{Memory Reference Profile 的检索闭环}

10 月 27 日前的工程闭环以 Exact + Entity + Lexical + Dense 四条可靠通道、固定 QueryPlan、object-level aggregation、weighted RRF 和最终 Authority revalidation 为必需能力。Temporal/Runtime 可复用现有能力；高级 topology、EPA、Residual、Wave/PPR 作为实验通道，不成为 Memory 系统能否正确运行和演示的前置条件。

\section{当前代码与目标差距}

当前代码已经有多条候选通道和 query planner，但 \texttt{ranking.rs} 仍根据本批候选实际出现的 EvidenceFamily 动态计算启用集合和分母，并在融合分数外加入 topology bonus；\texttt{QueryPlan} 仍以聚合 candidate limit 为主，没有完整的 per-lane budget/family freeze。目标实现应首先修复这些稳定性和可解释性问题，再开展高级拓扑算法比较。\cite{nous-code-snapshot,nous-research-package}
