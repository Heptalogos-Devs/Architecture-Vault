\section{TypeScript Cognitive Host 与 Rust Cognitive Kernel}

目标实现由 TypeScript Cognitive Host 负责公开 Core/Client orchestration、provider/model invocation、Resource adapters、Focus/Projection/Managed Context policy 以及 offline cognition workflow；Rust Cognitive Kernel 负责 owner validation、Authority transaction、revision/epoch/idempotency、检索 planning/fusion diagnostics、Serving generation/recovery 与可靠 persistence。\cite{nous-research-package,nous-code-snapshot}

Host 与 Kernel 之间使用私有、认证、类型明确的 semantic RPC；公开 API 不泄露 EPA/Wave、USearch 等实现算法/引擎开关。Model/provider call 不放在 PostgreSQL transaction 中；Host 获得 proposal/derived material 后由 Kernel 重新校验 Subject、Evidence、expected revision/epoch 和 owner rules。

\section{本机优先与可替换机制}

主要部署方向为 PC-local：受管理 PostgreSQL、Tantivy、一个稠密检索后端、可重建 AssociativeTopology 与 OpenDAL-backed object repository。本地模型网关与远程 API 遵循同一 capability contract；是否允许远程处理敏感材料由 deployment/privacy policy 决定。

当前不把 USearch + pgvector + Qdrant 同时作为正式长期栈。USearch 是现有代码资产；目标默认 dense backend 在 pgvector/Qdrant 等候选间通过 filtered recall、multi-view、RAM/disk、build/restart、backup/restore 与安装复杂度 benchmark 冻结。

\section{对象库提交边界}

大型/二进制 Artifact 与 DerivedRepresentation 采用不可变内容寻址对象库。可靠提交路径遵循：

\begin{center}
temporary write $\rightarrow$ digest/validation $\rightarrow$ durable publish/rename $\rightarrow$ PostgreSQL commit stable reference
\end{center}

事务失败可留下未引用 orphan，后续 GC；已经提交的 Authority reference 不允许长期指向缺失 material。Provider replacement 生成新的 DerivedRepresentation/ProducerSignature，不原地重写历史解释。

\section{物理实现与语义归属}

Domain owner、进程、crate/package 和数据库表不是一一对应。Memory/Self/Social/Motivation 是 semantic ownership；当前可先共同运行在 Rust Kernel 并共享 cognition foundation。只有独立 deployment/failure/security/scale reason 出现时才拆分物理服务。

同理，一个 owner 可以拥有多个一等 object families：Memory 拥有 Memory/Episode/Journal/CognitiveSchema/Tag，不要求每种对象一个 crate。成熟库负责数据库、向量检索、文件系统、RPC、图结构等 mechanics；项目代码负责 identity、revision、evidence、authority、query semantics 和 lifecycle。

\section{当前代码映射}

Nous Wave 当前源树已经包含 TypeScript Core/Client、Rust Kernel、protobuf、PostgreSQL Authority、Memory service、Cognitive Runtime，以及 Tantivy、USearch、petgraph 等 Serving/algorithm assets。下一轮不是从零搭建物理框架，而是在这些资产上重新对齐 Memory taxonomy、Schema/Anchor、UseEvent、QueryPlan/ranking 与新的 owner boundaries。\cite{nous-code-snapshot}
