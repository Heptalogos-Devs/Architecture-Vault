\chapter{研究对象与问题定义}

\section{研究对象}

Nous Wave 研究跨模型、会话、进程、检索索引和外部资源持续演化的 Subject cognition/personality。系统需要保留可追溯的经历与认知修订，在检索和上下文组装时说明信息来源，并在更换模型或服务后端、纠正数据和恢复运行时维持权限归属一致。\cite{nous-research-package}

主体（Subject）是跨模型和运行进程延续的逻辑身份；模型（Model）提供生成、嵌入、重排或派生等能力。模型、供应商、会话和进程可以变化，主体的认知对象、证据谱系和当前状态由相应的语义所有者管理。核心区分为 \texttt{Subject $\neq$ Model}。

Nous Wave 不是必须完整启用人格才能工作的单体系统。基础组合可以只启用 Memory、Cognitive Runtime、Retrieval 和 Resource capability，作为普通 Agent/RAG 的长期记忆与认知层；完整目标进一步加入 Self、Social、Motivation 及 offline cognition，使同一 Subject 在自我、社会关系、目标和长期经历上持续演化。Persona 是 Self 内部表示，不是模型 prompt 的别名，也不是单独顶层 owner。

\section{对话历史、检索与长期主体状态}

对话记录保存系统接收过的消息；Memory 说明主体当前保留哪些经历、事实或经验性做法，以及这些 cognition 来自什么 evidence、如何修订。Social 说明主体如何理解特定 person/dyad/group/community 的关系和语言惯例；Self 维护主体对自身的长期理解；Motivation 维护愿望、关切和 goal。检索服务只负责在当前 query 下找到候选，不决定这些对象是否真实、是否仍被 owner 接受或是否因此被强化。

外部知识库继续承担文档解析、全文索引和知识源同步；Nous Wave 维护 Resource identity、coverage/access 和 citation，在 Subject 实际接触材料后记录 ObservationOccurrence，再由 owner 决定是否形成长期 cognition。向量相似度、graph centrality、ranking score 和 model confidence 都属于服务/提案证据，不能替代 object identity、epistemic state 或 management authority。\cite{mem0-commit,graphiti-commit,nous-research-package}

\section{与 Heptalogos 的研究边界}

Heptalogos 是现实交互与 agency/runtime authority：它拥有 canonical IM/product facts、Opportunity/Reaction、行为许可、binding Commitment、CommunicationCommit 与外部 Effect。Nous Wave 拥有 cognition/personality。双方共享逻辑 SubjectId，但分别维护 bounded-context state；Goal 可以由 Nous Motivation 提出，是否形成承诺和执行仍由 Heptalogos 判断。

这种分工使 Nous Wave 可以作为独立 memory/cognition system 被其他 Agent 使用，同时避免 Heptalogos Foundation 内部再实现一套 Memory/Social/Self ontology。

\section{研究问题}

当前研究聚焦：

\begin{enumerate}
\item 如何在 Subject identity 与 Model/Session/Process 分离时表达 Observation、Evidence、Aboutness、Revision 与 Lifecycle？
\item 如何让 Memory、Self、Social、Motivation、Runtime 各自拥有明确对象和写入 Authority，同时复用共同的 evidence/revision/proposal foundation？
\item 如何表达 Episode、Journal、CognitiveSchema、RelationshipGraph 与 LanguageConvention，而不把心理学概念机械映射成独立服务？
\item 如何融合 Exact、Entity、Lexical、Dense、Temporal、Runtime、Topology 和 Resource retrieval，同时保持 Authority、Runtime 与 Serving Projection 分离？
\item 如何让 use/outcome feedback、accessibility 与联想学习具有幂等、可解释、无自强化回路的语义？
\item 如何在 offline maintenance 中提出、复核并路由 Hypothesis，由目标 owner 处理认知提案而不越权？
\item 如何与 Heptalogos 在无跨数据库分布式 transaction 的条件下可靠交换 Observation、Context、Goal/Commitment、Use/Outcome 与 Maintenance opportunity？
\end{enumerate}
