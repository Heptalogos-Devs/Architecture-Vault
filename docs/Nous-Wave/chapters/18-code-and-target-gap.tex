\section{10 月 27 日前的 Memory Reference Profile}

中期工程目标不是缩小 Nous Wave 的长期设计，而是在完整架构中选择边界最成熟的 Memory owner 做一条 production-shaped vertical slice。验收范围为：

\begin{enumerate}
\item Artifact/Observation/Evidence/Provenance/Entity aboutness 闭环；
\item MemoryObject/Revision 与正交 taxonomy；
\item correction/reinterpretation/contradiction/derivation 和 lifecycle；
\item explicit/model-assisted formation、suppress/restore/purge 与 AccessPolicy；
\item Exact/Entity/Lexical/Dense，固定 QueryPlan、对象级聚合和 weighted RRF；
\item caller-idempotent UseEvent，明确 retrieved/exposed/referenced/acted-on 区别；
\item CAS/idempotency/projection generation/stale-result validation/restart-recovery；
\item 一组端到端可解释演示：形成、矛盾、检索、真实使用、重启、抑制/恢复和 provenance 回溯。
\end{enumerate}

EPA、Residual、Wave/PPR、advanced accessibility 属于可插拔实验；Episode、Journal、CognitiveSchema、Social、Self、Motivation、Dream 不作为中期系统正确运行的依赖。这个工程顺序不改变它们在目标架构中的地位。

\section{当前执行规格的状态}

仓库中的上一轮 Architecture Rebase Spec 对 TypeScript Host/Rust Kernel、Core/Client、protobuf、Memory semantic closure 等工作具有重要实现价值，但其顶层 scope 仍以 Memory-first MicroSystem、旧 taxonomy、Anchor 和当时的算法默认作为执行背景。新的研究结论已经超出该 Spec 的设计代际。

因此下一次大规模 Coding Agent 工作前，需要按当前报告重写 Architecture、Decision Ledger 和 Memory executable Spec，再制定新的实现 Plan。旧 Spec 可以作为工程事实和迁移参考，不能直接继续授权新的 cognition 设计。
