\chapter{认知运行时与上下文}

\section{运行时的职责}

认知运行时（Cognitive Runtime）把持久认知组织为当前可供推理或调用方使用的状态。运行时状态可失效后重建；权威认知数据由持久化存储维护。会话（Session）表示一次连续运行范围，聊天线程与经历片段分别依照各自语义建模。\cite{nous-research-package}

\begin{description}
\item[活动认知（Active Cognition）] 近期且容易重新激活的认知引用和少量运行时元数据；不以固定 24 小时等 TTL 定义。
\item[工作上下文（WorkContext）] 可暂停、恢复或结束的任务/问题上下文。同一主体可有多个工作上下文；并发行为由宿主/Heptalogos 调度。
\item[驻留集（ResidentSet）] 当前会话或工作上下文可直接访问的认知引用。淘汰只把内容移出工作集，不改变记忆或真值状态。
\item[焦点与前台上下文（Focus/foreground）] 当前显式参与处理的局部上下文；不等价于完整的人类注意模型。
\item[调用方工作集（ConsumerWorkingSet）] 面向特定调用方、能力组合和预算选出的有界认知集合。
\item[受管理上下文（Managed Context）] 对模型调用轨迹的重置（RESET）或追加（APPEND）同步合同，用于上下文缓存。
\end{description}

Active 的退出/降级由任务相关性、Episode closure、容量、meaningful use、inactivity、显式 pin 与对象失效等信号共同决定。具体 policy 可替换，不把某个时间阈值提升为认知 ontology。

\section{注意分配、即时评价与长期倾向}

注意分配是在有限认知预算下动态选择信息；即时评价（Appraisal）根据自我、社会关系、目标或关切解释当前环境。当前目标将这两类过程主要放在 Runtime；稳定且值得长期保留的倾向由 Self、Social 或 Memory 等领域形成修订。评价理论帮助界定动态判断问题，具体实现不因此机械复制心理学模块。\cite{marsella-gratch2009,nous-research-package}

\section{检索过程与长期 UseEvent 分离}

检索引擎内部的 candidate、retrieved、ranked、filtered、materialized 等阶段属于 RetrievalTrace/diagnostics。它们可以为调试、评测或短期观测保存，但不自动进入长期 cognitive-use log，也不改变认知强度。

真正需要跨调用持久记录的是调用方对认知对象产生的类型化 use/outcome，例如：

\begin{itemize}
\item \texttt{Exposed}：认知确实进入调用方可见上下文；
\item \texttt{Referenced}：调用方显式使用、引用或跟随该认知；
\item \texttt{ActedOn}：后续行为基于该认知；
\item \texttt{OutcomeSupported / OutcomeRefuted}：后续结果为该次使用提供支持或反证；
\item \texttt{Corrected}：调用方或后续来源触发了纠正流程；
\item \texttt{Pinned}：显式管理/主体意图要求保持可访问。
\end{itemize}

\texttt{Exposed} 不等于 meaningful use；仅被检索、排名或展示不会增强 Memory、Tag、Schema、Relationship 或 LanguageConvention。真实性仍由 evidence 与 owner revision 维护。

\section{UseEvent 的幂等合同}

UseEvent 会影响未来 accessibility、运行时驻留，未来也可能参与 Social/association/outcome learning，因此重试不能被误记为多次独立认知经历。调用方必须为每个 durable use event 提供稳定 \texttt{event\_id}；批量请求可另有稳定 \texttt{request\_id}。

目标合同包含：

\begin{verbatim}
ReportUseRequest
  subject_id
  consumer_id
  request_id?
  events[]

UseEvent
  event_id
  reference
  kind
  occurred_at
  causal_operation_ref?
  context
\end{verbatim}

持久化唯一性至少绑定 \texttt{(subject\_id, consumer\_id, event\_id)}，同时保存 canonical event digest。相同 event id 与相同 digest 重试返回幂等成功；相同 id 携带不同 payload 返回 idempotency conflict。事件插入与由该事件直接产生的 ResidentSet/last-meaningful-use 更新必须在同一 PostgreSQL transaction 中提交。超时或取消不能被解释为“必然未提交”，调用方用原 event id 查询/重试。

\section{可访问性是查询时决策}

持久 Authority 中保存认知本身及显式 AccessPolicy；AUTO accessibility 在查询时派生，输出类似：

\begin{verbatim}
AccessibilityDecision
  eligible
  retrieval_cost
  reason
\end{verbatim}

它可以考虑年龄、类型化 meaningful use、当前 cue/context、访问策略和查询 effort，但不改变认知真值。当前 90/365 天分档只作为实验性实现基线；目标设计不要求旧对象经过固定天数后只能通过 exact id 找回。Memory Reference Profile 的默认 AUTO 不使用硬年龄淘汰，后续用真实语料比较 no-decay、time-only、time+typed-use 等方案。

\section{受管理上下文的重置与追加}

上下文前缀追加前，核对调用方与服务轨迹、策略、提示前缀、来源修订、访问控制、生命周期和渲染合同；任一条件变化时重建上下文。上下文缓存服务于模型调用，持久记忆和权威数据由认知存储维护。

\section{与 Heptalogos 的运行边界}

Nous Wave 提供认知查询、ContextContribution、使用/结果回执及可恢复的认知运行时状态；Heptalogos 管理 real-IM Opportunity、Reaction、行为 commit 和外部 effect。一个 H Reaction 或 Activity 可以消费多个 Nous WorkContext/ContextContribution，也可以完全不调用模型。两侧运行时不应互相复制 Authority，也不应以某个进程内模型 cache 充当共享认知状态。\cite{heptalogos-code-snapshot}
