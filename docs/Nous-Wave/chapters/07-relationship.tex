\chapter{社会认知：关系图与语言惯例}

\section{Social 领域边界}

目标设计将原先较窄的 Relationship 顶层领域提升为 \textbf{Social Cognition}。原因不是扩大概念范围，而是已经出现两类具有相同社会作用域、证据和修订基础，却不能自然归入“关系边”的长期认知对象：关系图（RelationshipGraph）与语言惯例（LanguageConvention）。Social 仅拥有其语义依赖特定 person、dyad、group、channel 或 community 的 durable cognition；普通世界知识、通用语言知识和外部平台授权不进入该领域。

Social 初期至少包含：

\begin{itemize}
\item \textbf{RelationshipGraph：} 主体视角下对人与人、人与群体、主体与他人之间社会关系的长期认知；
\item \textbf{LanguageConvention：} 在特定个人、二人关系、群体或社区中形成的词义、称呼、黑话和语用约定。
\end{itemize}

这两个对象族共享 EntityRef、Evidence、Provenance、Revision、EpistemicClass、valid time、suppression/purge 等 cognition foundation，但拥有不同的写入和查询语义。Social 不能成为“所有社会相关内容”的垃圾桶；一个对象只有在失去具体社会作用域后语义会改变时，才应由 Social 拥有。

\section{Subject-perspective RelationshipGraph}

关系图不是现实世界的权威社交网络，而是某个 Subject 当前接受的社会关系认知：

\begin{verbatim}
owner Subject S

S     -> Alice
Alice -> Bob
Bob   -> Alice
Alice -> Group42
\end{verbatim}

每一条边表达的是“Subject S 如何认识该关系”，而不是平台、Alice 或 Bob 的客观权威事实。外部平台事实、显式好友关系或群角色可以作为 evidence；主体对亲疏、信任、敌意等社会关系的理解仍是可修订 cognition。

推荐逻辑对象为：

\begin{verbatim}
RelationshipAssertion
  relationship_id
  owner_subject
  from_entity
  relation_kind
  to_entity
  degree?
  epistemic_class
  evidence[]
  valid_time?
  head_revision / epoch
\end{verbatim}

关系默认有向。即使某些关系在日常语言中常被理解为互惠，也不能从 \texttt{Alice -> Bob} 自动制造 \texttt{Bob -> Alice} 的 Authority。IM 平台中的 follow、block、admin/member、trust、close-to 等关系本身也大量非对称。若某 relation kind 需要逆向或对称查询，可在 projection/query layer 提供 inverse view，而不是伪造第二条 evidence-backed assertion。

\section{关系程度与认识确定性正交}

关系“程度/强度”和主体对该判断的认识确定性必须分离。例如“我猜 Alice 和 Bob 的关系非常亲密”可以是强关系程度、低 epistemic certainty；“我确认他们只是普通同学”可以是弱/中性关系程度、高确定性。不得用单一 \texttt{strength=0.8} 同时编码这两个问题。

初始合同优先采用语义明确的 relation kind，并在确有程度语义的关系上使用 ordinal degree，例如 \texttt{weak / moderate / strong}。不同 relation kind 的 degree 不进行无定义算术比较；只有出现具有稳定 operational meaning 的真实测量需求后，才引入连续量。

认识状态继续使用证据与 epistemic semantics 表达，例如 observed/reported/inferred/hypothesized 及对应来源和反证；不得把模型自报置信度当作关系真值。

\section{关系推理、图路径与更新}

图路径是检索和 hypothesis generation 的线索，不是关系传递律。默认不存在：

\begin{verbatim}
Alice friend Bob
Bob friend Carol
therefore Alice friend Carol
\end{verbatim}

同样，频繁互动、共同群聊、相互回复或共同联系人都只能形成 evidence/hypothesis。跨节点结构可以触发：

\begin{center}
path/observation $\rightarrow$ Hypothesis $\rightarrow$ evidence search $\rightarrow$ RelationshipProposal $\rightarrow$ Social owner validation
\end{center}

新 evidence 与当前 relation 冲突时保留来源和历史 revision；不通过删除原消息或修改过去 observation 来制造一致性。

Relationship Authority graph 与检索用 Social/Associative topology 是两类图。前者保存主体接受的关系 cognition，后者根据 relation kind、degree、epistemic state、freshness、query intent 和 fan-out 等生成当前 Serving edge conductance，可随算法重建。

\section{LanguageConvention：社会作用域内的语言学习}

群体黑话、特定朋友的称呼、二人之间形成的简称、社区内词义漂移和语用习惯不应写入一个全局 Dictionary。它们依赖具体社会共同背景，可建模为：

\begin{verbatim}
LanguageConvention
  convention_id
  expression
  scope_kind
  scope_refs[]
  meaning / denotation
  pragmatic_role?
  epistemic_class
  evidence[]
  valid_time?
  revision
\end{verbatim}

作用域可以是 Person、Dyad、Group、Community 或 Channel。初始实现使用 \texttt{scope\_kind + scope\_refs} 即可，不需要提前建立庞大的 SocialScope ontology。会话中的解释优先结合当前参与者和群体作用域，例如 dyad-specific、person-specific、group-specific、community-specific，再到通用语言知识；这种顺序是 retrieval preference，不代表窄作用域能永久覆盖更广作用域的所有含义。

\section{LanguageConvention 的形成证据}

语言惯例的证据按语义强弱处理：

\begin{itemize}
\item 对方显式说明“我们这里 X 表示 Y”或“我说 X 指 Y”时，可产生高质量 formation proposal；
\item 多次使用与相同 referent/meaning 对齐，并出现成功指代、确认或 repair 时，可形成 inferred proposal；
\item 单次上下文猜测只能形成 Hypothesis，不应直接固化为长期 convention。
\end{itemize}

必须阻止自我强化：Subject 学到一个黑话后自己反复使用，不能因此产生多个独立的外部支持来源。Subject 输出可以形成 UseEvent；只有对方继续使用、正确理解、显式确认或新的外部 Observation 才能增加 convention 的独立支持。该规则与 Memory/Tag/Topology 中“retrieved/exposed 不等于 reinforced”的原则一致。

\section{身份与来源}

Social 使用已绑定 EntityRef，不按昵称、显示名称或向量相似度自动合并 Person identity。跨平台身份关联必须有独立 evidence/provenance；来源中的 nickname、account id、group role 和 platform relation 可以保存为来源事实，再由 Social owner 形成关系 cognition。\cite{baldwin1992,nous-research-package}
