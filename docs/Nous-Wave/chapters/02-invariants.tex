\section{分层维护不同事实}

Nous Wave 以语义不变量约束写入权限、检索行为和服务表示。它们优先于某个具体数据库、模型、检索算法或当前代码结构。\cite{nous-research-package}

\section{领域与机制的分工}

Domain owner 由独立 identity、revision、lifecycle、mutation authority 和 query semantics 证明其存在价值，而不是因为心理学存在同名概念。一个 owner 可以有多个一等 object families；Memory 拥有 Memory/CognitiveSchema，Social 拥有 RelationshipAssertion/LanguageConvention。成熟库与数据库负责通用 mechanics；Nous Wave 负责 cognition semantics。

算法 seam 以问题家族命名，不以实现名定义 public architecture。EPA、Residual、Wave、PPR 可以在 narrow internal seam 下替换，但不能把 implementation-specific parameter 暴露成 Cognitive Query 的长期语义。

\section{有限反馈原则}

任何会受到系统自身检索/生成影响的量，都必须检查 self-reinforcement loop。单纯被召回、曝光、主体自己重复输出或成为 graph hub，不能自动制造独立 evidence。Association/Social/LanguageConvention 的长期支持来自外部 observation、明确 owner correction、独立 outcome 或语义定义的 meaningful use；Serving 侧采用 bounded budget、fan/hub normalization 和 provenance dedupe。

\section{状态标签}

全文使用“必需、目标、已实现、已核验、实验、候选、开放”等状态词。一个机制可以同时“已有实现”且“仍是实验候选”；只有当前 semantic contract 与 acceptance proof 都成立时，才能把实现写成当前可靠默认。
