# 行为权威与产品宿主

## 设计问题

模型、认知系统和扩展需要参与行为判断，但它们不能因此获得主体行为权限。产品管理又需要机器级诊断与修复能力；如果这类权限进入日常产品宿主，产品行为与部署维护会共享凭据和故障边界。

## 方案比较

**由模型或认知系统直接执行对外操作。** 这条路径减少一次显式审查，但会让生成内容或可演化认知绕过行为政策、管理员控制和效果记录；重试与不确定响应也难以归属到正式决定。

**由产品宿主统一形成行为与机器运维权限。** 这能集中操作入口，却会让日常产品权限携带部署修复能力。宿主缺陷或凭据暴露可能同时影响用户行为与机器环境。

**分离行为权威与机器运维权威。** Heptalogos 的产品宿主负责对主体和外部世界生效的决定；机器运维平面使用独立凭据和生命周期处理部署修复。系统边界增加了一个管理接口，但能限制权限范围和故障影响。

## 当前选择

模型、认知系统、工具和扩展提供输入或提案。正式对外行为必须经过 Heptalogos 的 Review 与 `DecisionCommit`。消息表达、行动计划和外部效果继续使用各自权威记录。

产品宿主承担正常产品运行和系统级管理。机器运维平面在宿主之外运行，以独立凭据诊断和修复部署环境；运维操作不自动改写 Subject 的产品领域事实。

## 失败模式与设计后果

- 绕过 Review 的模型或工具调用可能违反行为政策。行为副作用只在明确的权威提交后发生。
- 外部响应不确定时，系统不能把超时推断为成功或失败。`EffectOperation` 保留外部效果的不确定状态与恢复边界。
- 产品凭据若同时具有机器维护权限，普通产品缺陷可能升级为环境级操作。分离权限降低单一故障或凭据泄露的影响范围，但要求管理平面与产品宿主分别部署和恢复。
- 管理员限制和安全规则必须由 Heptalogos 的规范权威执行，不能依赖 Nous Wave 的可演化认知。

## 已确定与未决事项

Review、`DecisionCommit`、规范约束与机器运维平面的权威边界已经确定。运维接口的具体部署拓扑和权限授予机制属于 Heptalogos 工程规格，不由 Vault 目标设计预先决定。
