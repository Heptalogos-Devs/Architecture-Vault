# 测试与回放

## 测试层次

### 领域单元测试

验证纯规则和不变量：

- 事件身份与幂等；
- 状态机转移；
- 作用域和敏感度；
- 时间有效期；
- 关系变化上限；
- 记忆冲突和替代；
- ActionPlan 过期与取消；
- 权限和确认。

### 持久化与故障测试

验证：

- migration 和 checksum；
- 事务边界；
- cursor、lease 和 checkpoint；
- 进程在关键窗口崩溃后的恢复；
- request 后 response 前的 `uncertain`；
- 重复读取不会产生重复业务结果；
- 删除传播到索引和缓存。

### 契约测试

每个 Adapter、Provider、Worker 和 API 使用相同契约样本：

- 正常事件；
- 未知字段；
- 乱序和重复；
- 取消；
- 超时；
- 部分流式输出；
- 错误分类；
- 不支持能力；
- 旧 schema 兼容。

### Scenario Test

场景运行真实系统组合，并使用 Fake Adapter、Provider、Clock 和 Capability。至少覆盖：

- 连续补充；
- 撤回；
- 引用和媒体等待；
- 群聊旁观和被打断；
- 私密信息越域；
- 记忆纠正；
- 承诺重启恢复；
- 工具失败和不确定；
- 主动行为关闭；
- 生活时间线冲突。

### Shadow 和长期评估

真实流量不发送，只记录候选和 Trace。用于发现短场景无法覆盖的反馈环、成本、人格漂移和打扰问题。

## 虚拟时间

所有业务时间通过 Clock port：

- `now()`；
- 定时唤醒；
- 安静时段；
- 过期；
- 衰减；
- 日程和生活时间线。

测试中可以推进时间而不真实等待，并精确复现凌晨消息、重启和长期任务。

## 模型测试

不要只断言最终自然语言相等。优先检查：

- 输出 schema；
- BehaviorIntent 类别；
- reason codes；
- 使用的事实与来源；
- 禁止声明；
- 成本和延迟；
- 同一场景多次运行的类别稳定性。

对模型响应进行录制可以用于确定性回放，但录制数据必须脱敏和版本化。

## 消融

重要复杂机制需要可关闭：

- Observation Window；
- 记忆检索；
- 关系状态；
- 轻量情绪；
- Reality Review；
- 日记和反思。

新增机制必须说明要改善什么指标，以及关闭后如何比较。

## 发布门

任何阶段进入主要使用前：

- 相关核心场景通过；
- 重启和取消路径通过；
- 作用域和权限测试通过；
- 无否决级安全错误；
- Schema 和生成制品一致；
- 当前状态和工程文档已同步。
