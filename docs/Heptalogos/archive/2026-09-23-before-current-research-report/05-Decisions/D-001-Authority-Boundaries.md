# D-001：事实、状态、行为与结果分离

## 背景

长期系统需要区分外部实际发生的事情、系统对事实的解释、主体的决定、计划和外部结果。若它们共用一个可覆盖状态，崩溃、重试和模型错误会使系统无法诚实回答“发生了什么”。

## 当前选择

保留以下权威边界：

```text
Evidence
→ Canonical
→ Feed
→ Subject State / Memory
→ BehaviorIntent
→ ActionPlan / DeliveryPlan
→ Outcome
```

它们可以物理共存于同一数据库或进程，但不能合并为一个万能对象。

## 原因

- 原始事实可重新解释；
- 派生状态可重建和纠正；
- 行为与表达可以独立评估；
- 外部副作用可以保留 `uncertain`；
- 模型不能伪造工具或投递成功；
- 回放和故障诊断有明确依据。

## 代价

- 更多表、类型和转换；
- 需要稳定 ID、provenance 和 schema version；
- 开发时不能直接修改“方便的当前对象”。

## 重新考虑条件

只有当某两个边界在长期实现和故障语义上始终完全相同，且合并不会损害重放、纠正或不确定性表达时，才考虑合并。
