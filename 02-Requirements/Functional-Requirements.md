# 功能需求目录

> [!important]
> 本目录从项目目标和 IM 场景推导。状态为设计基线，仍需需求评审和实验验证。

| ID | 需求 | 优先级 | 背后要求 | 验收证据 |
|---|---|---|---|---|
| EVT-001 | 系统必须在规范化前持久化平台输入事件，而不仅是文本消息 | P0 | 事件是回放、重新解释与状态重建的事实基础 | 任一规范化或投递边界崩溃后，原始事件仍可恢复；重复到达仅产生一个规范化事实 |
| EVT-002 | 规范化事件必须保留原始载荷引用、平台账号、平台时间与未知扩展 | P0 | 统一模型不能牺牲平台证据或特有语义 | 可从内部事件定位原始 payload 或不可用原因；未知事件和消息段不会崩溃或静默丢失 |
| EVT-003 | 系统必须处理乱序、重复和延迟到达事件 | P0 | IM 网关和媒体分析天然异步 | 回放乱序样本后状态与预期一致 |
| EVT-004 | 编辑、撤回、删除必须表示为新事件而非覆盖历史 | P0 | 需要审计和时间语义 | 可恢复任意时间点的可见消息状态 |
| EVT-005 | 工具结果、定时器、媒体分析和发送回执必须进入统一事件流 | P0 | 避免隐藏状态通道 | 这些结果可触发同一决策管线 |
| IDN-001 | 内部身份必须区分人物、平台账号、Agent 账号和会话成员关系 | P0 | 跨平台连续性不能依赖单一 user_id | 同一人物可绑定多个平台身份 |
| IDN-002 | 机器人自身身份解析必须平台感知且无默认 QQ 回退 | P0 | 错误回退会污染历史过滤与发送者判断 | 未知平台身份返回未配置而非误判 |
| IDN-003 | 昵称、备注、群名片和历史称呼必须作为带时间的别名管理 | P1 | 称呼是关系和平台上下文的一部分 | 昵称变化不覆盖历史显示 |
| CNV-001 | 同一 Agent 与会话的事件处理必须保持逻辑串行 | P0 | 避免并发生成和状态覆盖 | 压力测试无双重回复或索引回退 |
| CNV-002 | 系统必须支持连续消息的等待、合并和语义边界 | P0 | 用户输入常分多条发送 | 三连消息场景仅产生一个合理决策 |
| CNV-003 | 新事件必须能够取消或修改尚未发送的行动 | P0 | 延迟回复可能过期 | 用户补充或撤回后旧回复不被错误发送 |
| CNV-004 | 群聊和私聊必须使用不同的参与、隐私和响应策略 | P0 | 两种环境社交结构不同 | 相同文本在群聊和私聊产生不同上下文约束 |
| CNV-005 | 沉默消费必须是显式决策并记录原因 | P1 | 不回复不应与故障混淆 | Trace 能区分静默、等待和错误 |
| STA-001 | 系统必须区分角色定义、运行状态、关系状态、会话状态和任务状态 | P0 | 不同生命周期需要不同更新规则 | 任一字段可明确归属和所有者 |
| STA-002 | 状态变更必须携带原因、来源事件和版本 | P0 | 长期系统需审计和回滚 | 可解释某状态为何变化 |
| STA-003 | 关键状态更新必须支持乐观并发或串行保护 | P0 | 跨会话共享状态可能竞争 | 并发更新不会静默丢失 |
| STA-004 | 状态投影必须可由事件重建或有明确不可重建字段 | P1 | 避免快照成为唯一事实 | 重建测试得到等价快照 |
| PER-001 | 角色定义必须版本化，并与运行状态分离 | P0 | 稳定规范不应被瞬时情绪覆盖 | 切换版本可重放对比 |
| PER-002 | 角色行为约束必须在行为选择和输出检查两个阶段生效 | P1 | 单一 Prompt 约束不可靠 | 违规候选在发送前被识别 |
| PER-003 | 表达风格变化不得自动改变长期人格事实 | P1 | 语言模仿不等于人格演化 | 群聊口癖学习不会修改核心边界 |
| REL-001 | 关系状态必须限定作用域到人物、群体或会话 | P0 | 不同场景的关系不可混合 | 私聊亲密度不会直接泄漏到群聊 |
| REL-002 | 关系变化必须缓慢、证据化且可设置上限 | P1 | 防止单次交互造成跳变 | 单事件影响不超过配置阈值 |
| REL-003 | 用户可查看、纠正或关闭影响关系行为的个性化信息 | P1 | 关系模型涉及敏感推断 | 控制面可执行纠正并产生审计事件 |
| MEM-001 | 原始事件、长期记忆和用户画像必须是不同数据产品 | P0 | 画像是视图，不是唯一事实 | 删除画像可从合法证据重建 |
| MEM-002 | 每条长期记忆必须记录来源、时间、置信度、作用域和状态 | P0 | Memory with provenance | 检索结果显示 provenance manifest |
| MEM-003 | 系统必须区分用户明示事实、模型推断和系统统计 | P0 | 不同证据强度不可等价 | 推断不会以事实口吻注入 |
| MEM-004 | 记忆必须支持替代、冲突、纠正、失效和删除 | P0 | 长期信息会变化 | 用户纠正后旧记忆不再作为当前事实 |
| MEM-005 | 记忆检索必须组合结构过滤、时间、语义和关系信号 | P1 | 纯向量相似度不足 | 消融实验可比较各信号贡献 |
| MEM-006 | 记忆写入必须经历候选、验证、合并或拒绝阶段 | P1 | 避免每句对话直接永久化 | 低价值或不确定信息不会直接进入稳定记忆 |
| MEM-007 | 敏感记忆必须支持更严格的保存、注入和删除策略 | P0 | 隐私与安全要求 | 敏感字段不进入群聊上下文 |
| CTX-001 | 上下文必须按本次行为需要动态组装而非全量注入 | P0 | Token 与信息噪声限制 | ContextPacket 包含每块的注入理由 |
| CTX-002 | 上下文块必须携带来源、置信度、新鲜度、敏感级别和成本 | P1 | 支持预算与审计 | Trace 可展示被选中和被排除原因 |
| CTX-003 | 上下文构建不得直接修改记忆或关系状态 | P0 | 避免读路径产生隐式副作用 | 构建过程为只读或显式命令 |
| CTX-004 | 上下文必须检测相互冲突的事实并显式呈现不确定性 | P1 | 错误融合会诱发幻觉 | 冲突记忆不会被静默合并为单一事实 |
| BEH-001 | 系统必须先生成行为意图，再生成表达内容 | P0 | 拟人化首先是行为选择 | 行为 Trace 与最终文本分别可评估 |
| BEH-002 | 候选行为必须包含等待、沉默、反应、回复、工具、取消和主动发言 | P0 | 回复不是唯一动作 | 所有行为可通过统一 Action 类型表示 |
| BEH-003 | 行为策略必须考虑情境、角色、关系、任务、风险和打扰预算 | P1 | 单纯意图分类不足 | 同一消息在不同状态下决策可解释 |
| BEH-004 | 表达生成不得声称未完成的工具行动或不存在的记忆 | P0 | 事实完整性 | 输出检查可验证声明来源 |
| CAP-001 | 能力注册必须描述输入输出、副作用、权限、延迟、成本、可取消性和允许的平台动作 | P0 | 工具不是只有 schema；平台不能暴露任意 API 透传 | 策略可按风险过滤能力，模型无法构造未注册的平台调用 |
| CAP-002 | 高风险或不可逆能力必须支持用户确认与幂等键 | P0 | 防止误操作和重复执行 | 重复请求只执行一次且有确认记录 |
| CAP-003 | 长耗时工具必须作为持久任务运行并异步返回事件 | P0 | 不能阻塞消息管线 | 进程重启后任务可恢复或明确失败 |
| CAP-004 | 工具错误必须转化为可观察结果，不得被模型误认为成功 | P0 | 防止虚假完成 | 失败事件含错误分类和重试信息 |
| CAP-005 | 工具选择和工具返回的表达应保持角色连续性 | P1 | 能力不应破坏人格体验 | 技术错误被转译为符合边界的用户沟通 |
| SCH-001 | 未来唤醒必须持久化，不依赖长时间 sleep | P0 | 进程重启和任务恢复 | 重启后到期任务仍可触发 |
| SCH-002 | 主动机会必须经过行为策略和打扰预算，而非直接发送 | P0 | 受控自主 | 触发原因不等于行动许可 |
| SCH-003 | 系统必须支持安静时段、频率限制、拒绝反馈和用户关闭 | P0 | 减少骚扰风险 | 用户配置即时生效并有审计 |
| OUT-001 | 发送前必须形成可持久化、可取消的 ActionPlan | P0 | 解耦生成与发送 | 计划含最早时间、过期时间和取消策略 |
| OUT-002 | 输出层必须支持平台能力降级 | P1 | 不同平台支持不同动作 | 不支持引用或反应时采用显式降级策略 |
| OUT-003 | 发送必须幂等、限流、按错误分类重试并记录回执或不确定状态 | P0 | 超时可能已产生平台副作用，盲目重试会重复发送 | 每次发送有唯一键；歧义超时进入 `uncertain` 并经对账形成终态 |
| OBS-001 | 每次行为必须记录输入事件、状态版本、上下文、模型、工具、决策和输出 | P0 | 研究与调试基础 | 可重建一次完整行为轨迹 |
| OBS-002 | Trace 必须区分用户可解释信息与内部敏感推理数据 | P0 | 安全和产品边界 | 用户解释不暴露隐藏推理或敏感来源 |
| OBS-003 | 系统必须记录延迟、Token、成本、取消率、错误率和命中率 | P1 | 工程和研究指标 | 仪表板可按场景和版本比较 |
| EVAL-001 | 评估对象必须是模型与运行系统的组合 | P0 | Harness 决定实际行为 | 支持固定系统换模型和固定模型做消融 |
| EVAL-002 | 系统必须支持确定性事件回放与虚拟时间 | P0 | 时机和主动行为依赖时间 | 同一场景可重复运行 |
| EVAL-003 | 评估集必须覆盖成功、边界、对抗和长期反馈环场景 | P0 | 平均体验不能暴露系统性风险 | 每类关键需求至少一个反例 |
| EVAL-004 | 重要架构组件必须可通过消融实验评估贡献 | P1 | 避免无效复杂度 | 关闭组件后可量化变化 |
| GOV-001 | 管理员和用户修正必须形成事件并触发派生状态更新 | P0 | 人工操作也需审计 | 修正可回放并传播到索引 |
| GOV-002 | 数据必须支持导出、删除、保留期和作用域控制 | P0 | 隐私治理 | 删除流程覆盖主存储、索引和缓存 |
| GOV-003 | 实验配置、Prompt、模型和策略必须版本化 | P0 | 结果可复现 | 每条 Trace 能定位完整版本集合 |

## 需求领域

- `EVT` 事件与事实记录
- `IDN` 身份与会话
- `CNV` 消息流与会话运行
- `STA` 持续状态
- `PER` 角色定义与约束
- `REL` 关系连续性
- `MEM` 记忆生命周期
- `CTX` 上下文组装
- `BEH` 行为与表达
- `CAP` 工具、任务和能力
- `SCH` 调度与主动行为
- `OUT` 输出投递
- `OBS` 可观测性
- `EVAL` 评估
- `GOV` 数据与配置治理
