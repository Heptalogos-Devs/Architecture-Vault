# D-005：SQLite 与本地存储优先

## 背景

当前目标是单主体、本机优先、少量联系人和研究型负载。主要需求是事务、可恢复任务、事件回放、时间查询、全文检索和容易备份，而不是跨地域吞吐。

## 当前选择

- 结构化事实、状态、任务、Outbox 和 Trace 优先使用 SQLite WAL；
- 原始媒体和大对象使用本地内容寻址存储；
- 全文检索优先 SQLite FTS；
- 可以按所有权拆多个数据库，也可以在早期物理合并但保持 Repository 边界；
- 向量库、图数据库、消息代理和分布式数据库按实验或负载证据引入。

## 原因

- 单文件、事务和备份简单；
- 适合本地优先部署；
- cursor、lease、checkpoint 和幂等可以直接表达；
- SQL 支持时间、作用域和结构过滤；
- 易于复制场景数据库和进行回放；
- 降低三人团队运维负担。

## 约束

- migration 连续并带校验；
- 数据库身份和所有者明确；
- 关键事实追加保存；
- 投影可以重建；
- 写入路径有事务和并发策略；
- 大对象不直接塞入普通事件表；
- 备份、恢复和完整性检查有自动测试。

## 代价

- 单写入和跨机扩展有限；
- 复杂向量或图查询能力有限；
- 多进程写入需要谨慎设计。

## 重新考虑条件

- 数据规模、写入并发或回放速度超过明确目标；
- 多设备或远程服务成为产品核心；
- 向量/图机制在实验中证明不可由现有方案满足；
- 某个数据域形成独立伸缩、保留或合规边界。
