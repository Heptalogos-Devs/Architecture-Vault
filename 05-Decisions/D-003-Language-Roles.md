# D-003：TypeScript 在线、Python 研究、Rust 执行

## 背景

Heptalogos 的主要推理来自云端 AI 供应商，本地模型只占少数。在线系统的核心问题是长期状态、事件流、流式网络、取消、协议归一化和前后端协作，而不是本地机器学习计算。

## 当前选择

- TypeScript / Node.js：目标在线权威运行时；
- Python：研究、评估、离线候选、本地模型和数据分析；
- Rust：高风险、原生、安全隔离和明确性能边界；
- SQL：事实、状态、任务、记忆、Trace 和检索。

迁移已完成，TypeScript/Node.js 是当前在线权威运行时。

## 原因

- 云模型供应商对 TypeScript 有完整支持；
- TypeScript 的判别联合适合事件和状态机；
- Node 的异步流和 AbortSignal 适合在线取消；
- React 控制面与后端可共享或统一生成契约；
- Python 在评测、数据科学和本地模型上仍最强；
- Rust 适合把危险能力放入独立执行边界。

## 约束

- 不允许 Python 和 TypeScript 共同拥有在线主体状态；
- Python / Rust Worker 只返回候选或执行结果；
- 跨语言契约使用版本化 JSON Schema；
- 不因语言偏好拆服务；
- C++ 只作为外部推理、编解码或硬件依赖。

## 代价

- 需要维护跨语言契约和生成流程；
- 目标运行时迁移需要场景基线；
- 团队需要同时掌握 TypeScript 和 Python。

## 重新考虑条件

- 本地模型成为系统核心；
- 产品明确转向深度 Windows/.NET 集成；
- Node 出现经过测量且无法缓解的可靠性或性能限制；
- Gateway 成为独立、高吞吐的故障域；
- 团队能力或供应商生态发生实质变化。
