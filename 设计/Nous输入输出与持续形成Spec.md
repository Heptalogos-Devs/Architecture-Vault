# Nous 输入输出与持续形成 Spec

[项目宪纲](../项目宪纲.md)定义产品目的；[原生认知设计](Nous原生认知与交互.md)定义 Namespace、模型、事务、检索和引用。本 Spec 确定使用者怎样交付信息、怎样得到结果，以及真实历史怎样成为可持续使用和修订的认识。

## 产品要解决的问题

Nous 服务普通记忆/知识应用，也服务有持续身份的主体。使用者交付真实资料或交互后，应能马上阅读和检索这些内容；在持续工作中取得适用的记忆，形成新的认识，并依据后来信息修订它们。

完整产品需要两项不同能力：保存发生了什么及其来源；理解其中哪些内容对以后有用、与已有认识是什么关系。原始事件、模型输入、当前工作和长期认识各有用途，不能靠多生成几类记录代替这条业务链。

每项机制据以下问题确定归属：解决什么实际问题，接收什么信息，何时工作，返回什么结果，谁会使用或修改它。已有能力能完成时就修改其负责者；同一状态存在多个所有者时直接重组，并迁移全部消费者。

## 接入能力与访问方式

CLI、MCP、HTTP、SDK 是访问方式。接入深度决定宿主能交付哪些真实信息，以及 Nous 能否调整最终模型输入。

| 接入能力 | 调用者交付 | Nous 完成 | 使用者取得 |
| --- | --- | --- | --- |
| 工具式使用 | 问题、资料、可读背景、已知引用和媒体；元数据按实际掌握的内容提供 | 接纳、读取、检索、明确记忆/纠正及所需后台处理 | 正文、必要时间和出处、可继续读取的短引用、处理状态 |
| 接收交互事实 | 真实事件或历史批次、作者/会话/时间、明确的接触事实 | 保存原始历史，更新当前可用信息，组织后台形成 | 原件/事件引用、当前状态、随后形成的认识 |
| 管理模型窗口 | 原生请求、真实新增事件、完整回复与工具结果，以及当前用途 | 自动选取认知、拼装与压缩实际输入，记录调用及后续反馈 | 可直接执行的原生请求、续接状态和可展开来源 |

这些能力可渐进接入，共用同一原生业务和数据。宿主插件可通过 SDK 提供它已掌握的情境；Nous 无需实现每个平台的消息 Hook。只有工具调用时，查询直接使用调用者给出的背景，缺失信息保持未知。普通自然语言始终可查。

## 使用者面对的完整操作

下列目标接口由绑定 Namespace 的客户端使用；HTTP、CLI、MCP 消费对应的同一原生操作，输入与返回由业务定义。宿主适配只转换其掌握的真实格式。

~~~python
ingest(inputs, *, purpose=None, media_strategy=None, wait=False) -> IngestionResult
observe(events, *, context=None, formation="automatic") -> ObservationResult
remember(text, *, source=None) -> Memory
correct(reference, text, *, reason=None, source=None) -> Memory
query(question, *, background=None, references=(), media=(), profile=None) -> QueryResult
read(reference, *, sources=False, region=None, cursor=None) -> ReadResult
runtime.open(session, *, usage, work=None) -> RuntimeBinding
~~~

`IngestionResult` 和 `ObservationResult` 给出当前可读来源、已经采用的认识及待执行工作。异步状态查询完成后返回同一份可用结果，用户无需解开内部 request_id 再猜另一个调用。

工具型输入中的 `background` 是自然语言；`references` 是从之前结果取得的正式引用，两者分别处理。高级 QueryContext 可以承载宿主已知的人物、会话与时间，普通工具无需填写完整机器对象。`observe` 使用共同的事件/接触数据，历史、执行者接触和主体接触保持各自真实归属。

### 导入资料

输入可以是文字、文件、媒体或已接纳的精确来源，附来源说明与本次用途。一次导入负责原件接纳、必要解析、所选形成任务及后续索引，返回原件引用、可用结果和未完成工作。

只保存资料时，不要求先形成 Memory。原文、解析结果和描述可以直接查询与阅读。明确要求提炼记忆或图关系时，程序安排所需模型步骤；媒体的自由描述、直接结构化及先描述后结构化复用同一目的合同。

### 交付真实交互

宿主可以一次交付新内容或已有来源，以及一批相关事件和它们的情境。服务内部处理原件、事件、接触与待形成范围，返回当前可读引用。宿主不用依次创建 Material、Observation、Formation 和投影任务。

### 记忆、纠正和查询

明确 `remember` 保存调用者指定的内容；明确 `correct` 修改所选认识并保存新来源和修订。它们不必经过一次自动语义推断。

普通 `query` 输入问题、可读背景、已有引用及媒体，默认使用配置好的检索 Profile。背景文字与正式引用分别表达，调用者可以只提供自然语言背景。高级算法参数留在配置、SDK 高级合同和主动展开的 trace 中。

查询背景是本次检索线索；普通查询不据此生成主体经历或长期认识。调用者明确提交资料/接触/记忆，或宿主交付实际调用历史时，才由对应操作按其真实来源接纳。

`read` 继续读取上一结果、认识、原件、区域或工作。默认结果包括可用正文、必要归属与时间、出处和下一读取位置。Proquint、qN:n、cN 的作用域沿原生设计；机器 UUID、完整 Schema 和资产详情不占用普通工具结果。

### 接入模型调用

宿主在实际模型调用位置接一次 wrapper/hook。Nous 接收真实请求并返回最终原生输入，随后接纳完整输出和工具结果。SDK 管理内部准备、发送与完成步骤；模型本身无需管理调用状态。

当前消息和工具结果立即参与下一轮输入，前台不等待长期形成。Work 保存目标、决定、进展与待办；窗口压缩由程序选定完整历史范围、来源和预算，模型只总结指定内容。

## 事件、作者与观察者

共同事件合同表达下列信息，具体字段由原生接口统一定义：

| 信息 | 含义与来源 |
| --- | --- |
| 原事件身份与顺序 | 宿主实际 event_id、原始顺序或回复关联；缺少外部身份时保留输入快照中的真实位置 |
| 原内容 | 原始文字/媒体/原生 payload，或已有 Material/Region 引用 |
| 作者 | 谁说过或产生了内容；平台人物、主体、执行者及工具各有真实归属 |
| 情境 | 会话/群体/频道、实际参与者与听众、当前 Work 及已知背景 |
| 事件时间 | 原事件何时发生及其时域；未知时保持未知 |
| 观察与接触 | 谁在何时真正取得了哪些内容；按宿主声明及真实模型发送边界记录 |
| 接纳时间 | Nous 实际保存内容的时刻，由服务生成 |

`caller` 是可信访问身份，`role` 是模型协议位置，作者是内容归属，观察者是实际知情者。它们分别表达。后台执行者读取资料只形成相应执行者的接触；主体获得成果时再记录主体接触。

HostEvent 与直接接触命令共用一份事件情境值模型。其字段为 `author`、`observer`、`conversation`、`participants`、`audience`、`occurred_at`、`observed_at`、`reply_to`；人物引用允许宿主外部标识与可读名称，已认识的 Entity 引用是可选关联。`role/payload/tool_call_id/response_id` 继续承载原生协议数据，`event_id` 使用真实稳定事件身份。模型请求快照与事件/接触声明在 RuntimePrepare 中分别提交。源平台账号事实由宿主提供，Nous 不根据姓名猜账号或把访问 caller 当成发言人。

没有平台人物和时间信息的通用模型 wrapper 仍能工作：完整请求与响应作为实际调用快照保存，按已知执行用途提供背景。模型输入中的旧历史、检索补充和内部 Prompt 不会据角色重新成为一批新发生的交往事件。明确导入的历史按其真实声明保存；原事件时间和未知人物不由当前接纳时间或文本相似度补造。

深度宿主提供的真实事件使用稳定外部身份去重。相同文本的两次真实发言可以是两个事件。原生工具和 reasoning 数据按协议保留；可见发言、执行产物和内部思考有不同用途。

原事件与接触事实分别去重：同一发言只有一份原事件，不同观察者或不同真实时刻可以再次接触它。一次交付重试沿用同一接触身份；SDK 使用既有调用/交付身份管理它，用户不用逐条手写事务 UUID。不能在发现原事件已存在后直接跳过本次新的实际接触。

Material/Observation 决定原件和接触事实，共同接触用例组织接纳与后续登记。它由当前接触操作重组而来，公开 observe 与 Runtime 调用同一事务参与函数：

~~~python
record_contact_in(tx, ctx, event_batch, *, materials, formation) -> AcceptedContact
~~~

函数使用 Material 接纳内容和明确接触，再由 Formation 登记待处理范围；公开 observe 打开事务，Runtime 在所属 Call 事务中调用它。MaterialService 不持有 Formation，Formation 从正式来源读取内容，避免反向依赖。Runtime 不再自行用 `role != system` 决定接触，也不重复写观察规则。

## 即时信息与长期形成

### 先使新内容可用

接纳资料与真实事件后立即取得精确引用。当前模型历史、Work 与活跃引用可以使用这些内容，Wave 可以检索原件及派生表示。长期形成尚未执行时，信息也有正常读取路径。

### 形成单位

离线资料按文档、章节、解析单元或媒体区域组织。持续交互按同一交往范围内已完成的原生消息组组织，并携带必要前文、作者、时间和 Work。工具调用与实际结果保持配对。

完整交互轮结束推进可处理水位；Work 切换/暂停/结束、显式纠正反馈及压缩将退出的完整历史范围可请求立即整理。未完成工具轮继续保留在当前历史。普通文本中的意图由语义任务理解，程序不靠词语扫描假装识别重要性或纠正。

登记的是待处理来源范围，合并作用域为 Namespace、观察者、交往 thread 及可选 Work。复用当前待处理接触合并与 DBOS 执行能力，并将其归属和范围原地修正；已处理水位、待处理范围和采用结果归 Formation，原文不复制进另一份队列历史。

默认从第一份新闭合内容登记起，使用 30 秒合并窗口安排一次低优先级整理；同一窗口中的追加内容只推进水位。此值由统一 formation 配置修改，明确边界可立即 flush。窗口用于合并持续输入，语义价值仍由形成任务判断。自动交互文本任务每批默认最多 4096 输入 tokens，并受当前模型与输出预留限制，超出时按完整原生消息组分批。显式文档与媒体处理使用其任务、区域和实际模态预算，不把这个文本批量默认值套成视频能力限制。

worker 冻结本次 new_closed_refs，另取必要的回复/工具前序与背景 refs。采用成功后只推进本次新来源的覆盖水位，空提案同样推进；执行中到来的新内容继续留在待处理范围。背景不会被反复当成新来源。合并不依赖 worker 恰好来不及启动，也不以每轮结束直接等同一次模型请求。

Formation 提供事务内 `register_in(tx, ctx, scope, new_refs, closed_through, background_refs, flush=False)`，返回待处理工作引用；现有 DBOS 作业消费该 scope 的冻结来源范围。水位表达接纳/处理顺序，事件原时间和原顺序单独保存。历史补录可以成为新待处理来源，不会因其发生时间较早而漏掉。登记、取输入和采用后的覆盖推进由同一 Formation owner 维护。

一次整理可以没有值得长期保存的认识。短回应放回其真实上下文后处理，不各自成为独立笔记任务；原始历史继续可读。需要较大输入时，程序依据实际预算分批，并保留片段间必要语境。

### 一次有情境的语义任务

程序先取得本次来源片段和少量相关旧认识。输入包括可读的作者/时间说明、原事件短键、必要前文、当前目的和旧候选短键，排除权限、UUID、事务与生命周期内部对象。

形成任务的结果表达：

~~~text
候选认识：
  text               可独立理解的陈述，保留作者、条件、否定和不确定性
  topics             主题词
  source_keys        本次实际来源中的短键
  time_expression    该认识明确涉及的原时间表达，可空
  previous_key       对应的已有认识候选，可空
  relation           新事项、重复、补充、变化或冲突
~~~

提炼和对照属于同一个有边界的语义任务。无旧候选时直接形成新认识；有候选时在同次任务中理解关系，不固定再加一轮自审。模型提供语义结果，程序完成正式身份、来源绑定、当前修订复核、采用策略和一次提交。

`notes` 是这次模型任务的结果名称，不是新的长期对象或用户必须管理的层。字段数量服从实际任务；足够的说明和例子让弱模型知道怎样保留上下文，并允许空结果。

### 采用与修订

- 新事项建立 Memory；来源和适用情境随其保存。
- 重复认识复用身份，按实际来源增加支持，避免重复记录与重复证据。
- 同一认识的补充或明确变化由 Memory owner 形成当前修订，保留旧版本和原声明。这里的变化指同一事项、认识归属和适用范围中的后继状态，语义关系由模型在实际上下文中给出。
- 多方主张或不同适用条件下的冲突可以并存并建立关系，程序不会仅凭先后覆盖另一方说法。
- 对过去经历的后来解释独立保存；原事件、当时说法和实际模型请求保持原貌。

例如本人取消同一次计划，可以更新关于该计划当前状态的认识；另一人声称计划仍照常，是不同来源的主张。此前“某人在当时宣布计划”这一历史陈述仍然成立。采用者使用语义结果及真实来源，不从作者名字相同或时间较新补推同一事项。

共同 Cognition 负责精确修订、证据、可见性和提交；具体领域负责采用规则。原 contact growth 中用于基础记忆对照和去重的部分归入这条正常形成路径；高级人格、社会与动机演进继续按其真实目的和策略工作。

形成时间来自本次实际形成/采用，记录时间来自实际提交；队列接纳时的 clock 不冒充之后发生的形成时刻。历史提供的事件、接触与认识时间按其真实来源保存。

## 各机制在同一条链中的用途

| 机制 | 需要它解决的问题 | 形成与使用 |
| --- | --- | --- |
| Material / Region | 原始资料和精确内容位置 | 输入时接纳，随时读取、检索和展开 |
| Observation | 谁真正取得什么及知情时刻 | 实际接触时记录，约束主体视角与经历来源 |
| Representation | 解析、描述、转写及媒体变换 | 复用原件处理结果，供检索和语义任务读取 |
| Memory | 以后需要使用、会变化的认识 | 片段形成或明确指令采用；查询、修订与使用反馈 |
| Episode | 还原一段经过及事件关系 | 直接组织 Observation/工作事件，Memory 可作为认识成员 |
| Journal | 有来源的主观回顾 | 有回顾目的时读取相应事件、Episode 与当时认识 |
| Work | 继续当前任务 | 即时保持目标/进展/问题，摘要回写 Work |
| Resident / Steward | 在有限窗口中取得当下相关内容 | 程序检索、选择、预算和覆盖；小语言任务辅助语义判断 |
| Social / LanguageConvention | 认识人物、关系与具体圈子的用法 | 根据真实交往与资料变化形成，按人物/群体/听众读取 |
| Ego / Motivation | 稳定自我、愿望与关切 | 创作来源或实际经历采用，按用途供给；缺资料时保持空或未知 |
| Wave | 在资料与认识中寻找相关内容 | 统一候选、索引代际、融合/重排与来源，供工具和 Runtime 使用 |

一次输入不要求填充全部对象。Work 总结只更新工作状态；明确需要长期回顾时另作 Journal。Episode 可在尚无 Memory 时组织真实事件。普通问候或偶然措辞不被强制升级为长期关系或语言惯例。

## 结构选择与修改责任

一种可行组织是以统一认知写入用例同时接纳和形成，适合输入主要用于长期记忆的应用，调用面较少。Nous 还需要在尚未形成认识时查询资料、维护当前工作及记录不同执行者的实际读取，因此选择将事实接纳与情境形成分责；对使用者仍提供一次完整操作，内部共享来源、事务与任务机制。

采用以下职责：

- Material/Observation 完成内容和接触事实的共同接纳，提供正式来源读取。
- Import 完成离线文件/批次操作，使用共同接纳及形成能力。
- Formation 组织待处理来源、情境片段、旧候选和语义变化，调用各领域采用。
- Cognition 及各领域拥有认识和修订；Wave 拥有投影与检索。
- ContextRuntime 拥有 Session/Call、当前工作引用及实际模型输入输出，调用共同接触操作。

继续使用 Authority、ContentStore、DBOS 和现有模型执行器。待形成业务范围复用现有维护链的合并能力，迁到正确所有者；不增加第二套事件权威、总线或调度器。

按实际依赖组织组合根：内容与来源、模型、Cognition、Wave、Formation、Import/Runtime。共同事务内任务接纳通过明确的内部参与接口完成，不通过全局 app、运行后回填服务或动态函数绑定隐藏依赖。

形成工作是已有业务的重组：将当前 contact growth 的待处理来源合并与旧认识检索迁到 Formation；Material/Observation 的接触操作在已有 WriteTx 中登记待处理范围，Runtime 只提交真实事件和调用关系。形成 worker 从正式来源读取内容，语言模型不管理队列。保留高级自然成长的领域用途，删除先逐事件新增 Memory、再依赖另一轮成长修补基础记忆的默认路径。

离线 Import 的文件准备、冻结单元、处理与结果按完整操作收为深模块；格式解析继续使用已有解析器。取消数十个共享整个 `self` 的跨文件函数绑定，迁出持续交往与通用语言形成逻辑。Formation 的语义任务、输入组织和采用在同一业务内共同演进。

重构覆盖实际生产者、消费者、注册、配置、必要回归和现行文档。旧逐事件形成、旧大控制提案、重复接触写入、只从 Memory 重建 Episode、以 Journal 代 Work 总结的路径一起退出。有效源码和可用能力按当前合同迁移，内部不保留版本桥和双路径。

## 用真实操作判断设计

工具式使用：导入真实文字或媒体，随后通过普通查询取得短引用，读取原件/描述/区域并纠正明确认识。只给自然语言背景也能检索。

持续交互：使用本轮真实开发对话，例如子代理模型由 Terra xhigh 改为 Terra max，或 A-Memorix 适配后移而长期目标仍保留。保存发言与已知时间，当前 Work 即时取得新要求；后台在上下文中理解变化，查询当前决定和追问历史分别取得正确内容及出处。形成不以每条消息都新增 Memory 为目标。

深度模型调用：首次请求、工具续轮和压缩后接续都使用真实原生输入，后续输出回到同一历史。原消息、摘要和认识可以各自展开来源。记录执行者的实际读取与主体接触，不用协议角色填补缺失事实。

完成这条认知主链后，继续完善自由 Seed、Ego/Social/Motivation 初始化与演进及其他领域。SDK、HTTP、CLI、MCP 随完整原生操作演进；Nous 稳定完整之后再进行独立发行、适配与公开效果评价。
