# 检索服务与认知消费者

## 目标与边界

本规范先建设完整检索底座、配置和消费者，保全原有效领域与算法；算法优化在这条链可运行之后进行。[完整查询合同](../NousQL与检索合同.md)、[固定源码与算法研究](../../研究/Nous查询与检索.md)、[能力保全依据](../../研究/目的与能力保全.md)共同给出输入、语义与迁入来源。

Nous是同进程模块化服务。公开`query.prepare/run/expand/explain`由query/retrieval owner提供；各领域owner持有正式事实、事务与领域读取，retrieval持有可重建服务资产和候选算法；contexts和成长直接消费。共同普通库`@nous-wave/platform`按独立export复用成熟组合，各产品单独实例与定义；Hept用正式npm/tarball取得。产品数据库与官方工作流组合负责本产品事务，领域状态不进入共享库。采用原Rust数值库经napi-rs addon同进程调用，文档FTS/持久dense统一采用LanceDB；本轮不重写数值算法。

## 责任及必要接口

| 责任方 | 提供给真实消费者的能力 |
|---|---|
| Identity / Subject | canonical身份、LexicalRef、名称与别名历史、主体供给、实体绑定 |
| 各认知领域 | typed对象/修订、当前与历史head、正式来源/认识立场、生命周期、按预算批量选择和读取 |
| Material / Source | 原件/区域/表示/真实观察、来源谱系、当前传播策略、带域时间；跨产品只走正式Client |
| Concept / Association | 稳定概念与membership、canonical merge/lineage、typed关系及证据根，当前/历史边读取 |
| Retrieval / Query | 资产构建/读取、lane执行、原算法profile、融合、prepare/run/expand/explain与结果使用目录 |
| Context / Growth | 当前认知投影、实际消费反馈、长期形成/维护；直接调用query与各领域操作 |
| Platform | 已配置Provider/Model/Role和网络客户端、官方SDK执行/预算/trace、标准数据库与DBOS机械 |

跨领域只读组成由产品根使用普通函数直接组合；同样的Subject、Ref、TimePoint、Policy和consumer等纯值无需反复换形。领域返回完整有意义的单元；`{content:string}`仅能是模型展示的一部分。

底座实际需要的owner接口按如下能力实现，不建立新的通用领域管理器：

- 按Subject、当前/历史时间视图及游标读取服务文档的**元数据**，包含稳定object、immutable revision、类型、实体/概念关系、各时间、文本/表示digest与来源引用；文本在获准后按有界batch取得。
- 批量绑定精确引用，批量核验当前权限、生命周期和指定历史/知情截点；当前policy可使已冻结候选退出。
- 读取正式Concept posting、AssociationEvidence、来源根与有序关系；顺序来源明示为真实source sequence或unordered membership。
- 读取owner正式变更游标及受影响引用，供提交后的索引工作继续；该记录保存事实变更，不保存重试/租约/队列状态。

不同owner可共享私有修订/SQL机械，各自规则和事务对外完整。数据库具体表按真正查询需求建立，不能要求消费者解析别的owner的JSON或表。

## 设置与资源先落地

配置使用平台的schema描述、分层稀疏覆盖、有效值求值和修订历史；无default基础schema、独立defaults与稀疏patch分开定义，patch不从带default schema.partial派生。检索owner拥有自己的typed字段与验证函数，直接注册到settings；无需为算法建立另一套配置求值器。

| 设置组 | 需表达的内容 | 生效与消费者 |
|---|---|---|
| 资源 | Provider连接/网络策略、Model标识/能力/价格、`query_embedding / query_concept_enrichment / query_rerank` Role和Prompt资源 | 下次调用取得确定修订，费用/trace记录实际资源 |
| 语义空间 | 实际provider/model、维数、metric、归一化、输入模态、representation版本、producer签名 | 空间兼容判定；变化时构建兼容资产 |
| 查询政策 | 默认域、努力程度、各lane/validation/resource预算、能力required/preferred/forbidden、诊断等级 | 每次QueryView冻结 |
| 概念丰富 | off/existing/model、catalog上限、activation数/相似度、临时hypothesis上限 | 同query共享activation和embedding |
| 算法profile | 原`baseline-rrf / nous-node-potential-v1 / vcp-dtsc-v9.2.1-adapter-v1 / vcp-rivermemo-v3.1-adapter-v1` | Host选择；Agent只表达探索意图 |
| 数值政策 | 原RRF权重/固定分母、原生graph/wave/residual/EPA、VCP assets/query/readout全部typed参数 | 查询参数实时冻结；资产参数变更触发重建 |
| 可访问性/维护 | 原幂律参数与normal/deep/explicit、使用权重、accretion范围、后台窗口与预算 | 属于相应领域规则，由query/维护消费 |
| 运行资产 | 数据路径、字节/内存预算、构建并发、缓存容量、历史资产保留与回收 | 产品管理可读；不进入主体包的操作者秘密配置 |

profile声明query embedding、residual、基础候选、图资产等真实requirements；与forbidden能力冲突时，在执行前给出具体状态。先保留原profile的有效默认参数和整组覆盖能力；新默认算法需依据研究结果确定。不能只保留profile名而绕过其参数或计算。`settings.describe/read/update/reset/history/restore`与模型/角色管理在模型不可用时仍工作。

## 服务文档与资产身份

### 服务文档

服务文档指向一个具体来源表示或认知revision，至少带：

`subjectId / domain / objectRef / revisionRef / representationRef? / textDigest / ownerCursor / entityRefs / conceptRefs / sourceRefs / time / statusMetadata`。

同一对象不同修订可有不同文档；一个revision的多模态/派生表示分别标识，候选最终回到原owner。服务行不得变成可修订认知副本。当前、history和as-of的可见文档由owner语义确定；普通查询不把全部旧版本混入当前head排名。

### Embedding space与producer

`EmbeddingSpace`固定维数、metric、归一化、模态和兼容版本；`Producer`记录实际Provider/Model、Role/Prompt修订、参数与representation生成规则。兼容性按空间和producer的上述字段核验；显示名与`id`用于资源定位。

持久embedding材料的复用key由`内容/区域digest + representation版本 + space签名 + producer签名`组成。模型或Prompt改变时，新材料与旧材料分别保存；语义允许且space兼容才可复用。query embedding在同一次query的dense、概念丰富、Pyramid、DTSC/V3及结构化叶子之间共享，记一次实际生成与费用。

共享向量材料、Concept vectors/postings和候选文档不因启用不同profile而重复生成。历史查询可对已有历史内容按许可/预算取得缺少的兼容向量；生成向量不改变历史知识事实或形成时间。

### 资产集

一个已发布`AssetSet`记录：`assetId / subjectId / family / implementationVersion / space / producer / sourceView / ownerCursors / configDigest / schemaVersion / manifest / publishedAt`。`manifest`包含实际文件/表版本及digest；历史集还含Authority recorded cut、knowledge cut、revision view和来源视图标识。

families至少覆盖lexical、dense、concept postings/vectors、native graph、VCP graph/EPA/intrinsic/candidate曲线。可共用物理引擎，发布时仍记录哪些完整组件已经就绪。正在构建、重试、取消、恢复的进展由DBOS操作保存；资产owner只保存已产生文件、发布指针与需要回收的事实。

## 采用库与迁入算法

底座保持能运行原算法的输入合同。原算法函数和具体机械API在[研究复用表](../../研究/Nous查询与检索.md)逐项列出，实施按表先复制迁入后改编。

已选的少量原预设与查询输入保存在[查询检索示例](../../示例/查询检索/README.md)，附固定commit、逐字节资源SHA-256与Apache-2.0许可证；直接用于本节迁入与真实场景。

- 先复用原NousQL三文件、Proquint/Identity含义、RRF/偏好、Native graph/wave/EPA/residual，以及`reference`和`vcp`的完整数值组合。只在负责位置替换身份、错误、存储与调用依赖。
- 文档词项与持久dense采用`@lancedb/lancedb 0.40.0`。FTS使用真实Lance ICU分词与BM25；dense初始采用未量化的`Index.ivfFlat`，metric来自space，构建参数/水位进入manifest。小集合未具备训练条件时明确显示flat scan状态，不宣称已有ANN。
- Native/VCP数值继续使用原`nalgebra 0.35.0`、CSR/邻接、`roaring 0.11.5`及`usearch 2.26.2`。USearch留给原数值内部concept/Tag residual与candidate search，和文档dense有不同输入/消费者；旧Tantivy文档服务在Lance接线后退出。Lance各family分别产出rank，外层多family加权归一化RRF使用原函数。
- 保留原数值golden、来源commit与中间测量；原生Wave、DTSC、V3保有独立实际消费者。Native cue_sensing/residual的原研究函数保留数值资源；其生产接入在算法阶段明确，当前底座不假称已有该链。仅在后续算法阶段改动公式和默认选择。

默认生产运行只取得已安装依赖和已构建资产；运行时下载、编译或安装作为明确管理工作执行。

### Lance 文档索引的实际接线

采用当前已安装声明中的`table.createIndex('text',{config:Index.fts({baseTokenizer:'icu',withPosition:true,stem:false,removeStopWords:false,asciiFolding:false})})`。多语分词不依赖另行下载词典；专名/长中文真实场景检查实际token与命中。自然文本作为字面词项请求，语法岛先由NousQL解释，不把全部文本转为Lucene表达式。[Lance FTS](https://github.com/lancedb/docs/blob/main/docs/search/full-text-search.mdx)、[Index API](https://lancedb.github.io/lancedb/js/classes/Index/)。

dense使用`createIndex('vector',{config:Index.ivfFlat({distanceType,...})})`，查询`vectorSearch(...).distanceType(...).where(...).limit(...)`。FTS使用`search(text,'fts')`及相同owner view过滤。两路默认在Top-K前过滤；不调用postfilter绕开配额语义。Subject/domain/head-or-history/source scope等列建立适用scalar索引。增量采用`mergeInsert`，按manifest追踪实际表版本、索引状态与未索引尾部；发布/optimize/cleanup遵守历史asset与在用读句柄。[Table API](https://lancedb.github.io/lancedb/js/classes/Table/)。

Lance返回的BM25/distance/rank分别保存，distance转相似度只用当前space/profile规定规则；不把Lance内置两路RRF替代原多family融合。维数、metric、索引参数、候选数、查询探测与flat/ANN状态可管理/诊断。

### Binding 与唯一边界

`packages/nous/src/retrieval/numerics.ts`是唯一产品值→数值输入的转换点。它从owner取得固定Refs、实际权限/支持边/独立根与时间视图，规范排序后建立只对该AssetSet稳定的密集整数目录。node和source-root使用不同目录；原source sequence与unordered membership分别编码，不能用数组顺序伪造真实序列。

binding采用napi生成`.d.ts`的对象/类和TypedArray，不传JSON字符串大包、回调到JS做每跳/每次残差搜索，也不建立handleId→Map的另一层注册表。下面是实施的核心形状；配置和诊断继续保留原完整typed结构：

```ts
interface NumericProjection {
  assetId:string; dimension:number; spaceSignature:string;
  documentIds:Uint32Array; vectors:Float32Array; // row-major
  conceptIds:Uint32Array; conceptOffsets:Uint32Array;
  membershipIds:Uint32Array; curveOrders:Uint8Array;
  labels:string[]; evidence:NumericEvidence[];
  documentRoots:NumericRootMembership[];
}
interface NumericEvidence {
  id:number; from:number; to:number; supportIds:Uint32Array;
  basisClass:string; associationKind:string; polarity:string;
  supportMass:number; rootId?:number;
}
interface NumericAccess {
  nodeIds:Uint32Array; candidateIds:Uint32Array;
  evidenceIds:Uint32Array; rootIds:Uint32Array;
}
interface NumericRootMembership { documentId:number; rootIds:Uint32Array }
interface OfferedCandidates {
  ids:Uint32Array;
  baseScores:Float64Array; bm25Scores:Float64Array;
  timeScores:Float64Array; anchorScores:Float64Array;
  selfEvidence:NumericRootMembership[];
}
interface CandidateSearchInput {
  limit:number; // profile为其每个实际local/transfer/原query搜索分配预算
}
class NumericAssets {
  static build(input:NumericProjection, config:NumericAssetConfig,
    signal?:AbortSignal):Promise<NumericAssets>;
  static open(path:string, manifest:NumericManifest):Promise<NumericAssets>;
  save(path:string):Promise<NumericManifest>;
  native(input:NativeWaveInput, access:NumericAccess):Promise<NativeRiver>;
  prepare(input:VcpPrepareInput, access:NumericAccess):Promise<NumericObservation>;
  close():void;
}
class NumericObservation {
  candidates(input:CandidateSearchInput):Promise<NumericCandidates>;
  dtsc(input:OfferedCandidates, config:DtscConfig):Promise<DtscReadout>;
  v3(input:OfferedCandidates, config:V3Config):Promise<V3Readout>;
  diagnostics():NumericObservationDiagnostics;
  close():void;
}
```

其余具名值按以下原类型完整生成，不重新设计一组精简`content/score`结构：

| binding值 | 原型及实际内容 |
|---|---|
| NumericAssetConfig | `WaveConfig/EpaPolicy/VcpAssetPolicy`的全部字段；不带配置registry |
| NativeWaveInput / NativeRiver | `SourceSeed[]`与max_hops/max_states；返回原`QueryRiver`全部source_field/node_potential/edge/provenance/mass字段 |
| VcpPrepareInput | `VcpQueryObservation::prepare/pipeline_input`所需原query vector、完整`VcpQueryPolicy`、seed/core/ghost和profile/config签名；graph/epa来自handle |
| NumericObservationDiagnostics | `ReferencePipelineOutput`的EPA/Pyramid/gating/Sense/fusion/双场中间量与实际搜索计数；向量为typed array |
| NumericCandidates | 原candidate union的整数id、实际family rank/distance与来源，不自动调用readout |
| DtscConfig / DtscReadout | 完整`ReferenceDtscConfig/ReferenceDtscOutput`与adapter root/provenance诊断 |
| V3Config / V3Readout | 完整`ReferenceReadoutConfig/ReferenceReadoutOutput`与adapter root/provenance诊断 |
| NumericManifest | kernel/binding/USearch版本、维数/space、文件digest/bytes、实际已建组件与原数值资产metadata；无业务进度 |

`prepare`仅计算一次共享observation；`candidates`只负责原数值内部search，Lance及其他lanes的候选由TS合并后作为OfferedCandidates传入两个readout。readout不得再扩大候选池。原`vcp/readout.rs::check_view`的generation、重复候选、有限分数、self roots归属检查保留。

document vector行数/维数、offset首0末尾=membership长度、id唯一且可映射、有限浮点、roots/support归属和原config边界都在napi入口验证。TypedArray用F32保留原向量精度、F64保原累计与诊断；整数限制在u32目录范围，超出即资源压力而不截断。大规模chunk分批构建由检索owner按同一manifest处理。

TS settings完成唯一求值后，binding接收完整config；入口检查全部必需字段，不让原serde默认值补出另一份隐含运行配置。原serde defaults作为迁入数值资源与golden保留，正式运行的实际值均来自已冻结设置。

重数值计算使用`AsyncTask<Task>`，compute在线程池运行，resolve才建立JS返回值；进入异步工作前复制一份拥有所有权的输入，避免JS同时修改buffer。构建并发和libuv占用有界；不为addon增加Tokio/持久队列。AbortSignal可取消尚未开始工作；已开始compute依原算法hop/state预算完成并丢弃迟到结果，不声称自动中断SVD。[TypedArray](https://napi.rs/docs/concepts/typed-array)、[AsyncTask](https://napi.rs/docs/concepts/async-task)。

Rust内部保留`authorized`重新组装合法support后计算的原数学行为；是否能复用更细资产是后续规模优化问题。TS每次给实际允许的node/evidence/root集合，Rust不自行授予权限。结果整数只经同一目录映射回Refs，最终由owner重验。完整自我/社会等对象不进入这个数值DTO。

### 构建、发布与迁移顺序

包采用`crate-type=['cdylib','rlib']`、napi-build::setup及napi-rs3官方ESM loader。发行构建用`napi build --release --platform --esm --output-dir <产品构建目录>`，targets按安装Spec的已支持平台列出；CI每target独立构建并运行最小实际load/ANN/readout。使用普通`.node`，本轮不引入WASM替代或独立Rust进程。[napi构建](https://napi.rs/docs/cli/build)、[target与包配置](https://napi.rs/docs/cli/napi-config)。

Node24运行只需已发行的对应平台addon及其动态库，生产不需要Cargo/C++。构建缓存/target在产品生成目录，研究实验在temp；失败给具体target/缺失依赖，不运行时自动装工具链。数值handle不能进入DBOS checkpoint；长构建仅保存manifest/path等可序列化结果，恢复时重开handle。资产格式记录binding/kernel/USearch版本与digest，不兼容时正式重建。

设置定义、无默认基础schema、defaults和profile目录是普通TS/JSON发行资源；describe/read/修改配置不依赖先打开Rust资产或调用native初始化。addon在其真实profile消费者处加载；缺失/版本不合时报告该能力不可用，精确读、已可用Lance查询和普通管理仍工作。公共contracts/browser入口不导入`.node`或Lance实现。

施工顺序：先复制纯reference及golden，去旧Error依赖；再复制Native四模块和VCP/USearch组合，改唯一整数/配置输入；建立napi并贯通Native/DTSC/V3真实消费者；Lance接好文档FTS/dense与多family融合；最后删除原Tantivy文档服务、旧SQLx投影/RPC/runtime票据。数值算法与默认profile的改变留待完整调用与规模测量之后。

## 更新、重建与发布

1. 领域短事务写入正式对象/revision及实际变更导航；属于持久工作的采用步骤与官方datasource检查点共同提交，普通短操作直接owner事务。
2. 持久工作的父DBOS工作流在提交后启动索引子工作。普通短操作提交后可以触发同一索引入口，但触发前崩溃仍须恢复：Host启动及官方DBOS scheduled reconciliation按owner正式变更cursor与已发布asset水位补齐缺口。同Subject/space/family使用官方队列分区与稳定operation identity，避免重建和增量相互覆盖。cursor保存真实事实次序，不保存重试/lease/队列状态；索引失败不撤销已成功的正式变更。
3. Builder从owner读取确定cursor/view，分页取元数据、批量取得获准表示，复用兼容embedding材料，构建新的实际资产。禁止循环全量公开list以替代候选索引。
4. 在独立staging目标构建、校验manifest/维度/空间/producer/组件齐备，完成实际readback；短事务发布AssetSet与指针。文件发布用标准原子替换及库自身事务；发布前再次核对源水位和配置语义。
5. 查询持有实际已发布AssetSet的引用，在同一次run内保持一致；发布新集不使正在读取的旧句柄变成另一代。迟到增量不得覆盖更高cursor的发布结果。
6. 旧资产在无在用读句柄且符合保留政策后回收；进程退出释放句柄，持久需要保留的历史集和研究资产有明确管理引用。清理进展交DBOS，失败显示实际未删路径。

真实引擎支持安全增量时可原位增量维护；需要一致多组件快照或重建时发布新集。两条操作都遵守同一文档身份、cursor和query view，无双写认知状态。正常更新不在每次打开连接时重建全文索引；模型切换也不重算未变化的兼容材料。

索引落后时：精确读仍走owner；普通查询只使用与请求相容的现有组件，给出所用水位和degradation；required组件缺失返回具体不可用。需要完整最新结果的调用可等待明确索引操作或指定一致性要求，不能把旧集合说成完整无命中。

### 导出、导入与恢复

Subject Bundle默认保存必要space/producer/profile/config引用，Serving与进程缓存由目标owner重建。导入期间Subject及其索引消费者暂停；领域正式记录、Source权限、时间receipt和RefMap全部采用后，再从目标owner当前cursor建立新AssetSet。源库cursor仅是源视图事实，不能用它跳过目标库尚未索引的记录。

显式附带的只读研究资产保留原manifest、identity目录、来源与digest。RefMap改变product/installation/Subject/对象身份后，这份资产继续是原视图研究材料；目标发布需重建并取得新assetId。不可只改manifest中的Refs后沿用旧文件checksum和USearch整数映射。兼容embedding可按原输入digest/space/producer复用，仍逐项检查实际来源及当前许可。

查询收据的固定结果/时间/来源可作为历史资料导入；cursor还依赖原asset和运行授权视图。原资产未恢复或目标身份/配置/view变化时，旧cursor不可续页，返回明确失效状态并由调用方发起新run。Installation Backup在完整恢复同一安装身份、数据视图和相符文件时，可由检索owner验证原manifest后重开；原生handle与内存缓存始终重新创建。

## 查询视图、过滤和缓存

内部`QueryView`冻结Subject/consumer、语义Clock和现实时间、两种历史截点、返回域、配置/角色修订、资源空间、来源范围、当前context和预算。它是一次执行对象；同进程直接传递。公开prepare是只读预览，run建立自身视图；有模型/外部资源步骤时使用正式平台执行与恢复。

`referenceTime`使用时间合同的`CapturedTime`，普通查询/预览通过`clock.read`取得同次投影而不持久推进high-water；实际形成/消费另由其owner执行`clock.capture/captureIn`。`asRecordedAt`为现实域TimePoint，`knowledgeAt`为声明语义域TimePoint；所有at在入口规范为UTC六位微秒。持久查询收据保存run使用的冻结元数据、各namespace设置revision/definitionRevision、asset manifest和实际结果固定Refs，供恢复/续页使用，不保存原生handle或执行进度。expand/续页读取该run视图，不复用独立prepare预览。

配置参数的求值与资产的实际生效分开：query参数按settings的next_call快照采用；影响资产的参数保存后成为desired，新调用选择兼容AssetSet或明确degradation/unavailable。完整构建发布后，asset消费者报告该configDigest已采用。旧query继续持有原配置与已发布代际，当前权限仍重验。

权限、源类别、域及历史可见性在候选配额前应用：词项引擎query filter、ANN prefilter/bitmap、Concept posting过滤、图的合法节点/支持边。保留对authorised support重新计算权重的数学含义；把整个VCP子集每次重建EPA/双ANN的实现放到规模研究和资产复用改进中。最终owner再次读取当前限制，Serving不是授权判定者。

本次QueryView记录实际采用的来源/支持边读取范围及其owner视图。重排或模型步骤返回后，当前校验覆盖这些实际依赖和最终命中；若其中来源撤回，结束旧授权视图，用合法范围重算未付费候选/数值步骤或返回具体不可用。只删去最终命中的私密对象，仍可能保留旧支持边产生的排名，应同时使该计算结果失效。实际已派发调用及费用保留；下一次付费调用仍需正常授权和预算。

| 缓存 | key与失效 |
|---|---|
| query embedding | 输入representation digest、space、producer/参数修订；有容量限制；不重复provider调用 |
| persisted embedding材料 | immutable输入digest与space/producer；来源清除后按依赖处理 |
| 打开的资产句柄 | 实际AssetSet身份与引擎版本；只读句柄随查询结束释放 |
| Concept posting/历史元数据 | Subject、owner cursor/历史view、配置；变更或purge后新view失效 |
| 结果目录/QueryFeedback | queryId、consumer/权限范围、实际精确返回成员；续读时重新核验，不复用旧正文授权 |

当前授权不使用无版本TTL的正向缓存；外部root的当前policy经正式来源Client获取。可缓存的授权metadata必须能和owner版本/撤权变化对应，并在对外返回前重新确认。日志不带秘密凭据或越权正文。

## 认知消费者必须同时接通

| 消费者 | 所需能力与实际owner |
|---|---|
| 普通Agent / CLI / MCP | 自然NousQL、全域return、prepare/explain、LexicalRef/result:N续读、来源展开、历史、错误恢复 |
| 每次模型调用的contexts | 当前Self身份优先且完整，相关Social/LanguageConvention/KnowledgeProfile/Motivation与Memory；按真实consumer/purpose/audience选择；词项/向量与原算法可继续检索 |
| WorkContext / 当前认知 | 多个任务、真实目标/问题/进展、精确anchors和当前材料；不依赖长期形成或向量完成才可使用最新实际输入 |
| Reflection / Growth | 已实际接触来源、精确旧revision、跨域候选与明确依赖；形成后更新Serving，再成为下一次真实查询输入 |
| Concept维护 / Accretion | Tag/Association当前与历史、独立根、有意义UseEvent、QueryFeedback、accretion目录；维护结果由owner采用 |
| Hept与原生Agent | 通过正式Client使用相同query/contexts，不解析Nous表；每次实际模型调用、工具后续和成果查看继续使用真实来源身份 |
| 管理/研究 | 当前设置、算法profile、组件就绪、实际generation、费用、预算、存储占用、更新/重建/清除操作与trace |

统一查询命中外壳只组织`Ref、domain、正文摘要、来源、时间、立场、匹配理由`。完整Self/Social/条件/经历对象由本领域返回；其schema、选择、正文组织和预算归该owner。语义单元不能由统一字符串slice切断成另一个含义。

## 诊断与失败

每个query trace应可读取：原/规范化/bound文本、选择和默认域、真实身份绑定、截点/Clock、context来源、有效设置修订、role/Prompt/space/producer、实际资产集、每lane候选及过滤数、budget、费用、final validation、rerank/资源动作、最终状态。

该查询解释由受QueryReceipt/源权限保护的owner读取，正文与query文本可引用受限Artifact；Pino/OTel默认仅记录安全关联元数据。公开explain先核验该query的consumer/authorityRef及当前源范围，不因拥有traceId就返回原输入或候选正文。

算法诊断保留真正被计算的数据：Native root/support与hop/state/flow；VCP EPA/Pyramid/gating/Sense、双场收敛、morphology/Ω、candidate pool、DTSC信任/fallback或V3几何/anchor/innovation。没测量的discarded mass用缺失值，不能填0。业务说明优先给具体原因和实际可用能力，高级数值按需展开。

取消、重试、provider结果未知、数据库/索引失败均交正式平台执行能力处理。领域owner重验revision/policy，已成功正式写入与已付费模型结果保留原身份；执行恢复不重复外部工作或重造一个查询来源。

## 删除数据与独立运行

- Source/认知owner先正式收紧传播或清除内容，同事务保存受影响引用；当前读取和后续模型输入立即按此限制执行。
- Retrieval退出相应文档、posting、向量、graph support、候选曲线、缓存及结果目录；受牵连资产标明需要重建，查询不得使用其残留私密影响。
- 在途build、冻结QueryView、结果续页和资产读句柄也在清除范围。停止受影响的新工作，取消可取消的DBOS工作并关闭句柄；已开始且无法中断的native计算完成后丢弃结果。Builder发布前重新确认Subject存在及所用来源仍可用，旧cursor/manifest不能让已清除内容重新发布。仍被实际句柄占用的文件在清除结果中保持pending，释放后完成物理回收。
- 原件、派生表示、embedding和共享字节只在没有合法保留依赖时物理回收；清除事实与尚未删除的路径分开显示。既有备份按管理保留/清除政策处置。
- 独立Nous不用Hept即可管理、接纳、形成、查询、重建；完整主体高级域按供给启用。联合运行的root权限/时间来自可信连接，连接失效给明确状态，不改写成本地主体事实。

## 施工与检查

先完成设置/资源、权威batch/history/source接口与Serving资产管理，再恢复原语言、基础query及消费者，然后把原算法原样接入profile。完成这些底座后才开始算法重写或默认参数实验。

检查复用一条连续认知场景和少量集中规则：中文长句/专名、同名人物歧义、私密Source在重排期间撤权、修订与后来理解、明确Concept及结果续读、模型/space切换、重建与删除。数值golden只保护真实迁入的原公式，不为库本身和薄转发另建支架。
