# 共同值与调用上下文

## 位置与依赖

公共纯值位于 `@nous-wave/contracts/common`，由 Nous 独立发行，并随官方 Client 提供。浏览器入口仅依赖 Zod 和纯值，不能经根 barrel 引入 pg、文件或 Node 专用实现。通用执行机械由 `@nous-wave/platform/*` 的独立入口提供。

共同值表示身份、时间、引用、调用授权和诊断关联；Memory、World、Message、Task 等结构由各产品自己的 contracts 导出。跨产品经生成 Client 传输，服务内部用同一 owner 的类型。

## 稳定身份与对象引用

```ts
type SubjectId = string;       // UUIDv7；两产品绑定同一逻辑 Subject
type InstallationId = string; // 本地实例稳定身份，迁移/恢复有明确操作
type ObjectId = string;        // 业务实体默认 UUIDv7；正式资源采用 owner 声明的稳定命名ID
interface Ref {
  product: 'nous' | 'hept';
  installationId: InstallationId;
  subjectId?: SubjectId;
  kind: string;               // owning contract 声明的真实对象种类
  id: ObjectId;
  revision?: number;
  selector?: Selector;
}
type Selector =
  | { kind:'text'; start:number; end:number; within?:Selector }
  | { kind:'page'; page:number; within?:Selector }
  | { kind:'image'; x:number; y:number; width:number; height:number; within?:Selector }
  | { kind:'media'; startUs:string; endUs?:string; within?:Selector }
  | { kind:'part'; partId:string; within?:Selector }
  | { kind:'node'; pointer:string; within?:Selector };
```

文本坐标用 Unicode code point，区间半开；页从 1 开始；图像为归一化矩形，边界限制在 `[0,1]`；音视频为十进制微秒；node 使用 RFC 6901 JSON Pointer。`within` 表示所选范围所在的外层区域。owner 负责检查区域是否存在、固定修订及规范化端点，不能仅验证字段类型。

`Ref.revision` 缺失表示请求当前版本。读取后返回实际固定修订；形成来源、执行输入和采用操作保存固定引用。对于不可变 Encounter、Receipt 等，所属合同声明该类型不使用 revision。任何 `kind` 都必须有实际 owner 的读取/生命周期合同。可注册模型、Provider、Prompt等正式资源使用其owner声明的命名ID与唯一作用域，返回真实产品Ref；vendor modelId、原生entryId等外部标识仍放来源/资源字段。

原生账号、平台消息 ID、会话 entry ID、URL 或文件标识不是产品 ObjectId：

```ts
type OriginIdentity =
  | { type:'platform'; adapterId:string; accountId:string;
      conversationId:string; messageId:string; nodePath?:string[] }
  | { type:'resource'; connectorId:string; documentId:string; version?:string }
  | { type:'native'; runtimeId:string; sessionId:string; entryId?:string; callId?:string };
```

这些信息保存在 Message、Material 或原生任务的来源描述中。跨产品引用实际 Message/Event/Material 等产品对象；原生来源通过持有者定位。来源根的稳定文档身份、所用版本和实际接触各有字段。不要伪造一个产品安装身份来装入外部字符串。

Nous LexicalRef 与结果集数字引用由 NousQL owner 绑定到 Ref。它们改善模型阅读和工具调用；对象权限仍按实际 owner 检查。

## 时间值

```ts
interface TimePoint { domainId:string; at:string } // canonical UTC ISO，六位小数；输入按精度规则归一化
interface TimeRange { start?:TimePoint; end?:TimePoint }
type TemporalExtent =
  | { kind:'unknown' }
  | { kind:'instant'; point:TimePoint }
  | { kind:'interval'; range:TimeRange };
```

`real` 是保留现实域，recorded 时间始终来自它。其他 domainId 指向正式 TimeDomain，不使用 worldId 代替。数值精度、跨域关系、捕获及五轴由[时间与调度](时间与调度.md)完整定义。

## 调用身份、消费者和资料范围

```ts
interface Consumer {
  kind:'subject'|'worker'|'author'|'maintenance';
  host:string;
  id:string;
}
interface Actor {
  id:string;
  kind:'human'|'service'|'subject'|'worker'|'author';
  authorityRef:string; // 指向可重新取得当前授权的账号/委派，不是模型自述
}
interface TraceContext {
  traceId:string;
  operationId:string;
  traceparent?:string;
  invocationId?:string;
  taskId?:string;
  effectId?:string;
}
interface CallContext {
  actor:Actor;
  consumer:Consumer;
  subjectId?:SubjectId;
  purpose:string;
  audience:string[]; // owner 发放的稳定会话/群体/人物/公开 scope 身份
  trace:TraceContext;
}
interface Policy {
  readers:string[];
  purposes:string[];
  audiences:string[];
}
```

readers 与 audiences 的值来自实际身份/scope registry；显示名称、群昵称和模型猜测不参与授权。保留通配值 `*`，空集合表示没有对应许可。通用库提供集合操作；每个业务 owner 决定相应读取、用途和披露的规则。

CallContext 在可信入口从 Better Auth 会话/API key、服务委派和 native host binding 建立，公开业务 body 不接受可自选的 Actor/grants。管理员可在明确的授权操作中注册/修改服务委派；正常调用不能随意把 worker 改为 subject。

一个实际账号可以同时拥有系统管理和交往身份，操作入口明确选择哪种权限。系统管理员的阅读不会给 Subject 写入经历。Subject 的社会关系、行为优先指令和软件权限分别由其 owner 管理。

执行私有范围由 Consumer 标识。worker/author 原件与草稿只在同一范围及明确数据管理授权下读取；被选定发布的结果可以由主体阅读，仍继承实际来源的传播约束。背景读取、成果就绪和实际消费分别保存。

持久工作保存 authorityRef 与冻结的任务范围。真正外部派发前重新取得当前委派、来源和目标授权；已经持久保存的成功结果直接补交后续事实。恢复不能靠一份早期 Actor/grants 快照扩大当前权限。

详细委派、撤权和秘密接口见[身份权限与密钥](身份权限与密钥.md)。

## 金额与资源用量

```ts
interface Money { amount:string; currency:string } // 十进制字符串、ISO 4217
interface UsageQuantity { unit:string; quantity:string; source:'provider'|'measured'|'estimated' }
```

金额和可能含小数的媒体用量在传输与持久化时保留十进制精度，计算使用decimal.js，数据库用numeric。未知金额使用null并保留usage及来源，不能写成0。不同币种分别归集，转换需要明确的汇率来源和操作；通用预算不把字段固定为USD。各模型的细分usage与缓存计数按[模型供应](模型供应与调用.md)保留原SDK语义。

## 统一传输错误与长工作引用

```ts
interface Problem {
  code:string;       // owner 稳定命名，如 settings.revision_conflict
  category:'validation'|'forbidden'|'not_found'|'conflict'|'unavailable'
          |'resource_pressure'|'budget'|'effect_unknown'|'failed';
  status:number;
  messageKey:string;
  args?:Record<string,string|number>;
  message:string;    // 可读安全回退文本
  operationId?:string;
  traceId?:string;
  currentRevision?:number;
  retry?:{ mode:'after_change'|'after_delay'|'reconcile'|'none'; at?:string };
  details?:Record<string,unknown>; // owner 选择的可披露字段
}
interface OperationRef {
  operationId:string;
  statusUrl:string;
  resourceRef?:Ref;
}
```

错误 code 与 category 表达实际语义，CLI、HTTP、SDK 和 Web 只做传输与显示。DBOS 重放后的普通 Error 应从已验证的序列化 Problem 字段恢复，不依赖 JavaScript instanceof 识别业务错误。详情不带秘密、未经授权原文或完整请求 body。

同步读取与短事务直接返回结果；真正长工作返回 `202 + OperationRef`，进度来自 DBOS 和领域记录。查询分页使用 `{items,nextCursor?}`，不可把截断数组冒充完整历史。游标绑定 Subject、授权用途、查询条件与排序，使用成熟 keyset 库。

## 提交身份与幂等

公开写操作通过正式SDK选项传稳定submissionId，并在HTTP使用Idempotency-Key。服务把它与产品、Actor权威、目标scope和操作名绑定形成ctx.trace.operationId；业务body无需再复制一份submissionId。in-process/原生调用用同一规则派生子操作身份，实际invocationId/callId/effectId单独保留。相同提交身份异内容为冲突，重放先取得原owner回执，随后按当前权限披露；DBOS checkpoint不替代长期业务幂等。

## 最小校验与消费者

共享 Zod 只验证上述形状、UUID、ISO、有限数和集合。实际归属、修订存在性、来源区域、权限传播和时间可知性由相关 owner 一次检查。

HTTP/SDK、Prompt preview、模型执行、查询、媒体、世界调度、后台工作、导出与诊断共同使用这些值。修改共同值时迁移全部当前消费者设计和生成合同；内部不设置旧形状旁路。
