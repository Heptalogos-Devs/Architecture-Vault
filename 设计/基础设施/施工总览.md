# 23类基础能力的模块与施工总览

23类是需求范围，组合为少量普通库入口及两个产品组合根。公共机制只维护一份实现，每个产品创建自己的实例、迁移、资源和运行状态。领域模块在底座可用后接入自己的语义；不增加第三个持有两边业务状态的平台。

## 模块与责任

| 类别 | 实现归属 | 直接采用与保留的边界 |
|---|---|---|
| 1 安装与目录 | platform/bootstrap | 复制原Nous locations，env-paths/confbox；逻辑根、安装身份、locator唯一来源 |
| 2 服务生命周期 | platform/bootstrap + 产品Host | 原生systemd/SCM+Shawl/launchd；Bootstrap/Host/Subject分别启停 |
| 3 统一配置 | platform/settings | Zod、deepmerge、JSON Patch、PG；模块自己的schema/defaults/生效规则 |
| 4 身份与引用 | contracts/common + 产品Identity | 安装/Subject/Actor/Consumer/固定Ref与跨产品绑定；不复制业务状态 |
| 5 认证授权密钥 | platform/credentials + 产品授权操作 | Better Auth、原Hept OS keyring和Secret源码；引导凭据先于DB可用，当前授权在真实派发点执行 |
| 6 扩展能力 | 产品能力目录 + Cordis/OpenClaw | 原生插件/工具/Skills/MCP保其owner；仅产品独有动态能力接Cordis |

| 17 日志Trace费用 | platform/telemetry + ModelInvocation | Pino/OTel/DBOS；费用唯一记在实际执行owner，跨产品只归集预算 |
| 18 错误系统状态 | contracts Problem + 各owner状态 | 稳定错误码/当前就绪/局部故障和压力；所有入口同一Problem |

模块路径相对Nous仓库的`packages/platform/src/`和`packages/contracts/`。Hept正式依赖其发行版本/tarball，各产品领域结构仍在自己的仓库；共享库不导入Memory/World/Task等业务实现。

## 依赖顺序

1. **纯合同、目录、引导凭据、存储与独立发行。** 先让空安装可初始化、离线诊断、启动/关闭与重启。普通SQL无需DBOS工作流；新安装没有主体自动工作或付费调用。
2. **配置、认证/当前授权与资源。** 模块Schema和四层覆盖进入真实PG，配置修订/来源/生效可查看，权限与秘密只有真实owner能解析。
3. **网络、模型、Prompt和实际输入。** 成熟SDK承担协议与循环；每次调用冻结资源/配置/Prompt及真实消息，结果先保存，时间/后续采用可独立恢复。
4. **时间、持久工作、原生运行和媒体。** 重投影真实期限；完整原生执行/历史保留；收件保全与主体消费分开；每次物理效果有自己的回执。
5. **诊断、全管理入口、本地化与数据发行。** 在已经可调用的owner操作上补完整呈现；安装/主体包/更新各自恢复，unknown不自动重发。
6. **领域消费者。** 基础机制贯通后，按能力保全合同接回完整认知/检索、世界/生活/任务/承诺/交往。现有消费者在底座接口更换时同步迁移，不通过保留旧接口延长施工。

具体步骤沿[施工顺序](../../施工顺序.md)，类型、SQL、配置和源码采用沿[详规目录](README.md)。以上安排没有把底座全部做成常驻服务，也不要求按表创建23个package。

## 验证与删除

保留极少量能够失败在真实边界上的贯通场景：两个空安装的独立启动/重启与正式SDK；修改配置/Prompt后下一次实际模型输入采用新值；带时间和原生效果的主体导出/恢复。必要的事务/CAS、精度、算法和权限规则使用真实依赖或少量纯输入边界。

临时探针、调试服务、开发期fixture只放temp，用后清理。被替代结构的测试、Mock、转换和脚本随结构删除；不为测试保留旧接口。不要用getter/转发断言、源码字符串匹配或一个假依赖响应充当底座可用。
