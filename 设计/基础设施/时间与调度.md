# 时间与调度

本设计与[共同值与调用上下文](共同值与调用上下文.md)使用同一 TimePoint、Ref 和 CallContext。本设计落实[项目宪纲](../../项目宪纲.md)的认知五轴、连续世界、长期任务与故障继续要求。源码依据和实际实验见[Hept 时间生活与消息研究](../../研究/Hept时间生活与消息.md)。公开操作、纯值与模块位置沿[整体架构与模块合同](../整体架构与模块合同.md)。

## 1. 责任与采用来源

Hept 拥有世界时间映射、世界离线政策、日历、已实现生活和主体自然节点。Nous 拥有通用认知时间、来源时间证据、认知形成/适用/修订、知识切面与现实数据库历史。Nous 可独立使用 real、应用自定义或自管虚拟域，不要求存在 Hept、World 或角色人格。

共同 TimePoint/TemporalExtent 等值由正式 contracts 导出；Temporal、微秒算术、同域比较和 deadline 投影放在共享普通库 `@nous-wave/platform/time`。源码位于 Nous 的 `packages/platform`，通过独立构建的 npm/SDK 产物供 Hept 使用，不使用相邻仓库 link。这个库不保存 World、ClockSegment 或认知业务状态。两个产品共享纯时间值与纯运算。各产品的数据与运行状态在自己的数据库；外部 ClockSource 通过正式 Client 接入。Nous 绑定 Hept 时读取实际 Hept 映射，不再维护另一份可自行变化的世界钟。

第三方直接承担 Temporal/IANA/DST、RFC 5545、数据库事务与持久延迟执行。分段映射、实际捕获和生活采用属于已有领域语义。施工从已复制源码开始，在实际 owner 改编：

| 采用源码 | 保留的实际算法 | 迁入后调整 |
|---|---|---|
| Nous master `crates/core/src/time.rs` | unknown/instant/半开 extent、同域比较、逐 occurrence 联合时间证据 | 共同 Zod/TS 纯值与 SQL 谓词；保留 unknown 语义 |
| Nous `subject_clock.rs` | 单调在线推进、高水位、capture、同请求回执、CAS、离线恢复 | TS Clock owner 与 Kysely datasource；显式保存段与政策；不携带旧 Authority 平台 |
| Nous Client `clock.ts` | due/paused/unmapped 投影与同域 compare | 改用微秒整数与新 TimePoint；删除 protobuf/Date 精度转换 |
| Hept `world-calendar.ts` | 原当地 recurrence identity、RRULE/RDATE/EXDATE、例外、生效版本、DST 转换 | 保持 rrule + Temporal；更新正式值与存储接口，保留原算法 |
| Hept `world-lifecycle.ts` / `world-host-runtime.ts` | 实际停钟 receipt、expectedRevision、unknown、operator superseded | 放回 Hept 世界生命周期；进度使用 DBOS，删除原执行/lease/fence 支架 |
| Hept WorldLife/Living/Life 的实际消费者 | 已实现区间、覆盖、政策修订、活动窗口/恢复 | 全部消费新捕获/区间/调度合同，同步删除旧钟转换路径 |

原样副本在 `temp/spec-research/source-candidates/time/`，出处、commit 与 SHA-256 见其上级 `manifest.json`。新实现先迁入这些实际函数，再改导入、合同及事务接线。旧 Rust 的算法转为 TS 时保持其有价值的断点和规则，不从本文另写一套近似算法。

## 2. 共同时间值与精度

```ts
type DomainId = string;
type Revision = number; // 已创建修订为正安全整数，与共同 Ref.revision 一致；PG 使用 bigint

type TimePoint = { domainId: DomainId; at: string };
// at 的唯一 wire 形式：YYYY-MM-DDTHH:mm:ss.SSSSSSZ
// 四位公历年 0001..9999，UTC；六位小数代表微秒坐标。

interface TimeRange { start?:TimePoint; end?:TimePoint }
type TemporalExtent =
  | { kind:'unknown' }
  | { kind:'instant'; point:TimePoint }
  | { kind:'interval'; range:TimeRange };
// interval = [start,end)，省略端点表示无界，已知双端必须同域且 start < end。

// Query owner 的带域谓词，空边界仍须声明目标域。
type TimePredicate =
  | { kind:'point'; point:TimePoint }
  | { kind:'range'; domainId:DomainId; range:TimeRange };

type ClockRef = Ref & {kind:'Clock'; selector?:never};
type ClockSegmentRef = Omit<Ref,'kind'|'revision'|'selector'> & {kind:'ClockSegment'};
type TimeCaptureRef = Omit<Ref,'kind'|'revision'|'selector'> & {kind:'TimeCapture'};

type CapturedTime = { // 同次读取的快照值；正式持久捕获返回下面的 receipt
  point: TimePoint;
  realAt: string; // 同次读取的现实 UTC
  clockRef?: ClockRef;
  clockRevision?: Revision;
  segmentRef?: ClockSegmentRef;
};
type TimeCaptureReceipt = CapturedTime & {captureRef:TimeCaptureRef} & (
  | {clockRef:ClockRef & {revision:Revision};
     clockRevision:Revision; segmentRef:ClockSegmentRef}
  | {point:TimePoint & {domainId:'real'};
     clockRef?:never; clockRevision?:never; segmentRef?:never}
);
```

Clock、ClockSegment、TimeCapture 都是实际时间 owner 的正式产品对象。读钟返回的 clockRef 固定 revision；段与捕获事实不可变，不使用 Ref.revision。它们完整携带 product/installationId/kind/id，需要时携带 subjectId。内部 SQL 的 clockId/segmentId/captureId 是本库 opaque ID；跨产品不能把它们直接放进名为 *Ref 的字符串字段。公开时间选择可带目标 `subjectId?:SubjectId`，时间字段为 `{domainId?:DomainId,preferClock?:ClockRef}`：省略时使用职责已绑定参考域，显式给出两者时必须一致。preferClock 沿共同 Ref，先核对当前授权和正式时间来源连接，模型不能自选其他 authority。持久来源绑定用省略 revision 的 Clock 身份 Ref；read/capture 显式带 revision 时要求它仍是当前 head，否则返回 revision_conflict。读取固定旧配置使用 clock.references.read，冻结的 QueryView 继续复用其已保存 point/snapshot。

例如 Hept 返回的同一捕获包含 `clockRef:{product:'hept',installationId,kind:'Clock',id:clockId,revision:7}`、`segmentRef:{product:'hept',installationId,kind:'ClockSegment',id:segmentId}` 和 `captureRef:{product:'hept',installationId,kind:'TimeCapture',id:captureId}`；具体 ID 由实际 owner 生成并可读。TimePoint 仍只保存 domainId/at。

`real` 为保留的现实域。没有实际 Clock 对象时，real 的纯读取仅返回 point/realAt；正式捕获仍保存可定位 owner 的 TimeCaptureRef，不伪造 Clock 或 ClockSegment。real 捕获使用当次真实 wall，不用虚拟 high-water 改写现实记录。domainId、clockId、worldId、subjectId 相互独立。不同域坐标即使数字相等，比较仍返回 `unknown`；有正式映射证据时才能转换。TemporalExtent unknown、无界区间与缺失值分别解释，不用零点、now 或无限大替代。

外部输入可含显式 Z/时区偏移和不同小数位。入口先用 TimePointInputSchema 验证合法 ISO 日期、显式 offset 及坐标范围，再用公共 Temporal 函数 overwrite 为 UTC 六位微秒，最后通过 canonical schema。允许 0..9 位小数；超过六位时仅接纳整微秒值，非零超微秒精度返回 validation，不隐式舍入。非法日期、缺 offset、输出超出四位年份范围及溢出均拒绝。

```ts
const ValidatedTimePointInputSchema = TimePointInputShape
  .superRefine(validateInstantAndWholeMicroseconds);
const TimePointInputSchema = ValidatedTimePointInputSchema.pipe(
  TimePointInputShape.overwrite(normalizeTimePointUtcMicroseconds)
    .pipe(TimePointCanonicalSchema),
);
// normalize 中使用 Temporal.Instant.from(at).toString({fractionalSecondDigits:6})；
// validate 已确认 epochNanoseconds % 1000n === 0n 及合法年份/offset。
// pipe 只有在前一阶段无 issue 时执行归一，非法输入不会进入 Temporal overwrite。
```

Fastify 的公共 body/query schema 接受这一输入合同，不能先用仅 canonical 的正则拒绝合法 offset 或短小数；输出合同仅接受 canonical。$time/$asof 的字面量、SDK 输入和 pg 精确字符串使用同一 Temporal 校验/归一路径。规范化后才计算业务摘要、相等、cursor 与身份；全程不经过 Date。正文、平台 raw、已付费输入与原生 transcript 保留原表示。显示层可格式化地方时间。

内部比较和计算使用 Temporal.Instant 的 epochNanoseconds 经 floorDiv(...,1000n)，转换到存储坐标时统一向下取整。PostgreSQL 使用 `timestamptz(6)`；驱动读取为精确字符串或微秒整数，禁止经默认 pg Date parser 往返。SQL 对外可用固定 UTC `to_char(...US...)` 投影。Node Date 只用于最终显示或第三方要求毫秒的调度边界；这种转换显式向未来取整，防止提前唤醒。

六位格式是坐标精度。现实 wall clock 的实际分辨率由平台决定，不能因补零而宣称观测达到微秒精确。处理耗时使用单调 tick；重启后不复用前进程的单调 tick。

## 3. TimeDomain、Clock 与 ClockSegment

### 3.1 正式对象

TimeDomain 保存 `domainId, label, coordinateSystem='iso8601', precision='microsecond', authorityRef, status`。authorityRef 指向实际拥有此域映射的产品安装。真实应用事件、训练场景、文档叙事和虚拟世界都可引用域；域记录本身不自动创建世界或主动工作。

Clock 的公开记录保存 `ref:ClockRef, domainId, revision, currentSegmentRef:ClockSegmentRef, onlineRate, offlinePolicy, status`；内部以 clockId 关联 SQL。一个域有一个当前权威映射；外部绑定只登记来源，不成为第二个可变权威。Subject 的当前参考域是正式绑定，默认 real；同一 Subject 的事件和资料可保留其他域。

ClockSegment 保存：

```ts
type ClockSegment = {
  ref: ClockSegmentRef;
  clockRef: ClockRef & {revision:Revision};
  domainId: DomainId;
  revision: Revision;
  domainAnchor: string;
  realAnchor: string;
  rate: string; // 非负有限十进制，如 '0'、'1'、'0.25'、'60'
  startedByOperationId: string;
  reason: 'configure'|'change_rate'|'pause'|'resume'|'advance'|'host_start'|'host_stop';
};
```

公开 rate 用规范十进制字符串，去多余零，不用指数表示。内部将它精确拆为整数分子与 10 的幂分母，用 bigint 乘除后向下取整；复用旧线性映射含义，不累计浮点余差。wire rate 最多 18 位整数与 12 位小数；安装可设置更低的倍率上限。保存前拒绝超界、负值和非有限值。管理员输入 number 可由客户端规范化为该字符串，服务不保留第二种 wire 形状。

段的锚点、倍率及创建原因一次写入后不可变。结束旧段产生 `ClockSegmentClosure {segmentRef,closedByClockRevision,domainEnd,endedRealAt,endedByOperationId}`，保存在既有 clock_changes.receipt；history 按修订投影闭合边界，不回写原段，也不新增闭合队列或状态表。

Ref.revision 与已创建的 ClockRevision 均检查正安全整数；0 仅作为 expectedRevision 的“尚无 head”条件，不进入正式 Ref。数据库 bigint 超出该范围即明确报溢出，不静默转换或丢精度。已结束段不可改写。每次实际改钟追加一个段并增加 ClockRevision；段边界允许显式向前 advance，禁止同域回退。读钟、数据库 checkpoint 和正文查询不增加 revision。

新的显式域可选择初始坐标。更换 World 不自动更换域；切换参考域也不重写旧事件、认识或原请求身份。要进入更早故事坐标，创建新域并保留原域历史。

### 3.2 在线时钟与单调来源

在线沿旧算法：`domainAnchor + floor(monotonicElapsedMicros × rate)`，当前映射至少达到持久 high-water。变速/暂停先捕获旧段当前点，再建立新段；新段关联本次操作的实际 wall 与 mono 捕获，提交完成后仍从那一次 mono 起点继续，不遗漏提交等待时间。

当前每个产品安装有一个在线 Clock authority 进程，DBOS 的同进程 workflow workers 共享它。使用已有产品进程生命周期及 PostgreSQL 原生 session advisory lock 防止两个 authority 同时接管同一安装；不另造 lease、epoch 或资格平台。session/数据库连接失效时停止写钟和新捕获，重新取得权威后按恢复流程建立新段。跨进程工作者使用正式 ClockSource，不能各自在内存启动同名域。

wall 与 mono 分开注入：wall 提供真实记录坐标；mono 提供本进程持续时间。wall 回调不使在线虚拟钟倒退。real 来源的原始时间与实际数据库 recorded 保持真实值，事件顺序另由权威提交序号表达；不借高水位修改外部平台原始时间。

### 3.3 捕获与纯读取

公开读取输入和结果为：

```ts
interface TimeSelection {
  subjectId?:SubjectId; // 目标归属，仍由受信入口鉴权
  domainId?:DomainId;
  preferClock?:ClockRef;
}
type ClockSnapshot =
  | {domainId:'real';rate:'1';now:CapturedTime & {
       point:TimePoint & {domainId:'real'};
       clockRef?:never;clockRevision?:never;segmentRef?:never;
     };clockRef?:never;revision?:never;segment?:never}
  | {domainId:DomainId;rate:string;
     clockRef:ClockRef & {revision:Revision};revision:Revision;
     segment:ClockSegment;now:CapturedTime & {
       clockRef:ClockRef & {revision:Revision};
       clockRevision:Revision;segmentRef:ClockSegmentRef;
     }};
```

映射分支的 domainId、Clock/段身份、revision 及 now 内证据必须一致；real 分支不含虚构 Clock。没有显式选择时，按获准职责的当前绑定取域，未绑定默认 real；显式未知/不可用源返回问题，不回退到另一域。`clock.read` 只读当前投影，不写 checkpoint。管理观察、日历查询、历史查询与查询相对时间解释不得触发世界实现、模型调用或资料接触。

同库业务在所属短事务中调用 `captureIn(tx, selection, operationId)`，映射分支先取得实际 Clock 锁及修订，捕获一次 point/realAt/segment/revision，并更新 high-water；real 无 Clock 时直接保存同次 point/realAt 的最小捕获事实；与业务结果一起提交或回滚。锁顺序固定为 Clock → Subject/World → 具体对象。事务内后续逻辑复用该值，不再次取 now。

已保留的模型结果保存其原 formed capture，恢复和重新采用不改形成时间。后来权威采用的 recorded 是新的现实提交点，两者分别保存。单纯准备、上传、目录展示不会创建主体 observed。

### 3.4 跨库捕获

Nous 使用外部 Hept 映射形成新认知时，需要先取得可恢复的捕获回执。单纯 HTTP read 可能返回高于源产品持久 high-water 的在线 point；如果只有 Nous 提交，源进程断电后 freeze 可能恢复到该 point 之前。

外部 ClockSource 因此提供显式持久捕获操作：以稳定 operationId 在源 owner 短事务更新该映射 high-water 并保存 TimeCaptureReceipt；real 无映射时直接保存最小捕获事实；所属长工作使用官方 datasource 时，与该步骤 checkpoint 一同提交；响应丢失按原 operationId 取原结果。Nous 在自己的业务事务中保存这份完整回执及实际记录时间。跨库没有原子提交承诺：若 Nous 回滚，源高水位仍合法，它只表明时间已经达到，不创建主体接触或认知。正式操作为 `clock.capture`，返回 `TimeCaptureReceipt`；`clock.read` 保持纯读。captureRef 指向最小捕获事实，不复制当前 Clock 配置。

capture 的幂等身份区分实际阶段。一次模型父操作的 step N 使用稳定子身份 `parent/stepN/observed` 与 `parent/stepN/formed`；同一阶段恢复使用原子身份，下一阶段使用自己的身份。父模型 operationId 关联整次工作，captureId 由时间 owner 生成 UUIDv7，二者不相等。不能直接让 observed/formed 共用 `(domainId,parentOperationId)`，否则会把后形成点误复用为先前观察点。

跨库恢复先按原 operation 查询源回执。Hept capture 支持 existingOnly=true：当前授权后返回原回执；不存在时返回 time.capture_not_found，既不取新点也不写捕获。ClockSource.recover 使用同一 POST captures 和原 Idempotency-Key，正文只多带 existingOnly；mode 不参与业务摘要。捕获身份以受信 Consumer、Subject、显式 selection 计算，凭据轮换不改变消费事件；原 Actor 与 authorityRef 仍保留审计。

同库 `captureIn` 在所属业务事务同时保存最小 capture receipt。若受信 Hept 模型宿主已在所属业务事务保存相同捕获，可直接传正式 receipt，由 Nous 核对绑定与来源后采用。不能接受模型正文中自报的 currentTime 替代宿主捕获。

## 4. SQL 与事务

以下是概念 SQL；具体 schema 名、ID 与 JSON 类型随总体存储合同统一。列是领域时间事实，不是另一套工作流状态。

```sql
CREATE TABLE time_domains (
  domain_id text PRIMARY KEY,
  label text NOT NULL,
  authority_ref jsonb NOT NULL,
  status text NOT NULL CHECK (status IN ('active','retired')),
  created_real_at timestamptz(6) NOT NULL
);

CREATE TABLE clocks (
  clock_id uuid PRIMARY KEY,
  domain_id text NOT NULL UNIQUE REFERENCES time_domains(domain_id),
  revision bigint NOT NULL CHECK (revision >= 1),
  current_segment_id uuid NOT NULL,
  online_rate numeric NOT NULL CHECK (online_rate >= 0),
  offline_policy jsonb NOT NULL,
  status text NOT NULL CHECK (status IN ('running','paused','retired'))
);

CREATE TABLE clock_segments (
  segment_id uuid PRIMARY KEY,
  clock_id uuid NOT NULL REFERENCES clocks(clock_id),
  revision bigint NOT NULL CHECK (revision >= 1),
  domain_anchor timestamptz(6) NOT NULL,
  real_anchor timestamptz(6) NOT NULL,
  rate numeric NOT NULL CHECK (rate >= 0),
  operation_id text NOT NULL,
  reason text NOT NULL,
  UNIQUE(clock_id, revision)
);
ALTER TABLE clocks ADD CONSTRAINT clocks_current_segment_fk
  FOREIGN KEY(current_segment_id) REFERENCES clock_segments(segment_id)
  DEFERRABLE INITIALLY DEFERRED;

CREATE TABLE clock_checkpoints (
  clock_id uuid PRIMARY KEY REFERENCES clocks(clock_id),
  segment_id uuid NOT NULL REFERENCES clock_segments(segment_id),
  clock_revision bigint NOT NULL,
  domain_high_water timestamptz(6) NOT NULL,
  captured_real_at timestamptz(6) NOT NULL
);

CREATE TABLE clock_captures (
  capture_id uuid PRIMARY KEY,
  domain_id text NOT NULL REFERENCES time_domains(domain_id),
  clock_id uuid REFERENCES clocks(clock_id),
  operation_id text NOT NULL,
  domain_at timestamptz(6) NOT NULL,
  captured_real_at timestamptz(6) NOT NULL,
  clock_revision bigint,
  segment_id uuid REFERENCES clock_segments(segment_id),
  CHECK ((domain_id='real' AND clock_id IS NULL AND clock_revision IS NULL AND segment_id IS NULL)
      OR (clock_id IS NOT NULL AND clock_revision IS NOT NULL AND clock_revision >= 1 AND segment_id IS NOT NULL)),
  UNIQUE(domain_id, operation_id)
);

CREATE TABLE clock_changes (
  clock_id uuid NOT NULL REFERENCES clocks(clock_id),
  operation_id text NOT NULL,
  request_digest text NOT NULL,
  actor jsonb NOT NULL,
  request jsonb NOT NULL,
  receipt jsonb NOT NULL,
  recorded_real_at timestamptz(6) NOT NULL,
  PRIMARY KEY(clock_id, operation_id)
);
```

`clock_captures` 仅保存上述最小事实；带映射的捕获校验 domainId、Clock 与段一致，real 无实际 Clock 时保留该行可读的 captureId/domainId。公开 captureRef 由实际 owner 的产品/安装/对象身份构造，不每次调用复制整套 Clock 设置。`clock_changes` 保存操作者改变时间的正式历史和精确回执，包含该正修订的完整 Clock 记录及原段 closure，使旧 ClockRef 能读到该修订配置；DBOS 保存执行进度。两者职责不同。采用 Kysely datasource 的 transaction，使改钟记录、段、checkpoint、业务修订与该事务 step checkpoint 同时提交，不创建自有 transaction replay 框架。

checkpoint 不得用新 realAt 配旧 domainHighWater 拼成一次观测。保存的是同次完整 capture；竞争时在同一 Clock 行锁内选择较新合法完整 capture。不同域不比较 high-water。时钟段按 revision 排序，wall 校时回调时仍保留实际 endedRealAt，不用现实时间排序代替提交顺序。

Hept 本地 Clock authority 将 Host stop/start 的原 operation、resumeOperationId、完整前后段、closure、status 与 gap 直接保存在 clock_changes.receipt.lifecycle。World 只持 domainId/ClockRef；本地同库生命周期在 Clock 事务内完成，原外部 ClockSource 的分步确认语义由该原子回执承担。

## 5. 公开操作、权限与幂等

正式修改与绑定输入沿既有公开字段；canonical 输出和 ISO 输入校验按第 2 节：

```ts
type ClockOfflinePolicy =
  | {mode:'freeze'}
  | {mode:'elapsed';offlineRate:string};
type ClockConfigureInput =
  | {subjectId?:SubjectId;domainId:DomainId;expectedRevision:0;
     initialAt:string;rate:string;offlinePolicy:ClockOfflinePolicy}
  | {subjectId?:SubjectId;domainId:DomainId;clockRef?:ClockRef;
     expectedRevision:Revision;rate?:string;offlinePolicy?:ClockOfflinePolicy};
interface TimeBindingUpdateInput {
  scope:Extract<ConfigScope,{kind:'installation'|'subject'}>; // 当前正式调用已接通的层
  expectedRevision:number;
  domainId:DomainId;
  preferClock?:ClockRef;
  connectionRef?:Ref;
}
interface TimeSourceRevisionChangedInput {
  domainId:DomainId;
  clockRef:ClockRef & {revision:Revision};
  subjectId?:SubjectId;
}
```

configure 第一分支只在该域尚无 head 时成立，返回从 1 开始的真实 ClockRef；initialAt 使用该 domainId 的输入归一规则。已有 head 的第二分支 expectedRevision 必须为正，至少修改 rate/政策之一，给出 clockRef 时必须与本域实际对象一致。保留域 real 使用真实墙钟，不配置虚拟倍率。Clock.onlineRate 保存本次配置的在线倍率；offlinePolicy 只保存离线模式/倍率，不复制第二份在线设置。已有 head 只修改 offlinePolicy 时保持当前运行/暂停状态和映射倍率；明确给出 rate 才改当前映射。

time.bindings.update 是时间 owner 的完整操作，使用[配置合同](配置与生效.md)的 ConfigScope 与 CAS，把本 scope 的来源值写入本产品 `time.reference` namespace，沿单一 settings head/history；不再维护可独立修改的 binding 副本。connectionRef 指向已授权的实际产品连接，纯 real/本地来源可省略。当前有效取值按 installation→subject 合并与源约束校验；角色调用没有独立 role 时间输入，设置目录仅开放这两个实际消费层。

通知仅携带源权威的固定 ClockRef 和 domainId。入口从受信连接及当前已登记来源核对 sender，通知只是重读/重投影提示；不接受它作为新的映射事实或更改绑定。旧修订/重复通知可幂等忽略。

读钟与历史分别授权 `clock.read/history`，持久捕获授权 `clock.capture`，改钟和绑定使用安装/域管理权限；Hept 世界操作者的授权通过正式管理入口落实。主体休息或模型不可用时，时间管理继续可用。跨安装凭据仅具有需要的 scope，URL/SecretRef 属于安装连接设置，不放进便携主体资料。

每个改钟操作在 Clock 锁内按 `(clockId,operationId)` 先查旧回执：同摘要及同授权来源返回原结果；异输入返回 conflict。只有新操作才检查 expectedRevision。修订不符、同域倒退、未知域、无映射、精度/数值溢出分别返回稳定问题码。网络结果未知保留同 operationId 查询/继续，不能用新的 ID 再次 advance。

## 6. 离线与 Host 生命周期

Clock 保存 onlineRate，offlinePolicy 保存 mode 与 elapsed 分支的 offlineRate：

- `freeze`：正常 stop 结束当前段并暂停；start 只恢复本 Host 确认保存的暂停修订。
- `elapsed`：正常 stop 建立声明的 offlineRate 段，start 建立 onlineRate 段。默认 offlineRate=1；沿在线倍率推进必须显式配置。
- 显式 operator pause 独立于 Host 停机。没有 Host 所有的 pause receipt，不自动 resume。

stop 流程复用原源码：读取 Clock → 保存 before 与确定的 operationId → CAS 改离线段 → 保存精确 paused/offline 回执。start 先用原 operationId 找回未确认操作，再检查当前修订；若管理员已改变钟，记录 superseded 并保留操作者结果。网络超时留下 unknown，不用本机推测值写入已确认字段。

异常退出没有精确关机点。freeze 从已提交 high-water 开始并保留 gap；elapsed 从 checkpoint 的同次 realAt 按声明 offlineRate 计算非负现实经过时间，再恢复 onlineRate。恢复过程建立有原因的新段，保留实际开始运行的现实时间。单调 tick 不跨进程比较。

离线时间推进只决定哪些世界区间已过去。确定性规则和已采用活动可由 world owner 分段实现，空白与待细化片段保留 coverage；不能补造离线 QQ 发送、网页访问或其他工具成功。catch-up 的世界创作工作由正常预算与 DBOS 工作流接纳。

### 6.1 导出、清除与恢复闭包

时间域、被引用段、capture receipt 与改钟历史属于安装/主体数据引用闭包。导出必须纳入认知 formed/observed、资料表示、世界事件、消息和任务所引用的 capture/segment；Subject 分支分配的新身份不倒改原来源域。ClockSource URL 与凭据独立配置。导入先恢复域/段/回执，再绑定其当前 authority；high-water 至少覆盖全部已导入 capture point，未完成操作按原 ID 继续。不能只恢复 Clock 当前配置而遗失 capture、造成域时间退回已保存认知之前。按所属数据清除时处理反向引用与保留义务，不为每个 capture 创建新的执行调度对象。

## 7. DBOS 唤醒与时钟变更传播

### 7.1 节点属于领域，等待交给 DBOS

Hept agency 保存每个 Subject 的最近自然节点：`nodeId,revision,worldDue,reasons,state`。候选来自活动结束、日历变化、自由窗口、既定观察、承诺、任务结果及主体明确 reconsiderAt。Nous 的认知 idle/settle 保存自己的语义 due，专业任务另保存现实 deadline。它们不共用一份业务队列表。

选中的节点投影保存 `clockRevision,segmentRef,realDue,workflowId` 作为该节点本次安排。工作流先用 datasource 事务保存节点及修订，再在后续 DBOS durable 调用启动延迟 workflow。事务后崩溃时重放同一节点结果，再用稳定 workflowId 启动同一个等待；不增加 outbox、lease 或自有调度 daemon。

按已核实 DBOS 5.3 API，注册函数在 launch 前，queue 在 launch 后。delaySecondsCeil 将剩余微秒向未来取整到毫秒，再除 1000，交给库的秒参数：

```ts
await DBOS.launch();
await DBOS.registerQueue('hept.time-wake', {workerConcurrency: 8});
await DBOS.startWorkflow(wake, {
  workflowID: `wake:${node.id}:${node.revision}:${clock.revision}`,
  queueName: 'hept.time-wake',
  enqueueOptions: {delaySeconds: delaySecondsCeil},
  workflowAttributes: {subjectId, nodeId: node.id, operation: 'time.wake'},
})(node.id, node.revision, clock.revision);
```

不在 Subject 前台 workflow 长睡。前台按 SubjectId 分区并发 1；延迟等待独立。未到期暂停域不创建真实到期 workflow；unmapped 保存明确原因并等待源绑定/时钟修订。若业务 due 已过，即使 rate=0 也返回 due，交领域判断是否仍需执行。

到期 workflow 读取当前节点、Clock 和正式时间：节点已取消或修订变化就结束；语义 due 尚未来到则重新投影；到期才推进对应 world/agency/maintenance 操作。旧唤醒不会因现实时间已过而越过暂停、来源权限、预算或当前行为开关。

### 7.2 改钟后的传播

改钟工作流的本地 Clock 事务完成后，枚举受影响的当前领域节点，分别启动幂等 reprojection 子工作流。原 delayed workflow 无需逐个强制删除，它们到期读取修订后结束；当前节点只指向新安排。

Hept 与 Nous 绑定时，Hept 改钟工作流还通过正式 Client 提交 `time.sourceRevisionChanged` 通知，携带 domainId、固定 clockRef 和操作身份，受信连接定位已登记来源绑定。Nous 只把它当重新读取实际 ClockSource 的触发，不把通知内容当新的时间权威。传递进度和重试由原 DBOS 工作流持有，不建立第二份跨产品发送队列。永久移除绑定时取消其语义待办，不启动新模型工作。

改钟与网络 backoff 独立。重新计算世界 due 不清除实际 `retryNotBefore`，不重置调用/费用预留，不创建新的付款身份。任务现实 timeout、工具网络 timeout 和平台实际发送时刻使用现实/单调基础设施时间。

### 8.1 认知 SQL 与结果冻结

Nous 的原查询编译与领域 SQL 在迁入时同步替换时间值，沿既有 `query.prepare/run/expand/explain` 使用；不新增简化的查询命名空间。公开 query.prepare 是独立只读预览。每次新 query.run 内部通过 clock.read 冻结 `referenceTime:CapturedTime` 和现实 `authorityCutoff`，expand/续页使用该 run 的 QueryView，不复用独立 prepare 结果。相对时间用纯投影即可；查询收据保存该读值与固定结果，不要求源 Clock 更新高水位或创建 TimeCapture。真正的形成、observed 或其他需要持久证明的业务点再由所属 owner 调用 clock.capture/captureIn，保存正式 receipt。实际读取与派发继续重验当前来源权限。

各 owner 的 SQL 保留有类型域列：来源 occurrence 的 occurred domain/extent、observed domain/point、现实 observed/recorded；认知版本和派生区域保存自身 formed/valid domain/point/extent。真实记录列全部 `timestamptz(6)`。没有某轴的对象不补造那个轴：Self/Social/Motivation 的来源事件仍在来源 occurrence 中。

occurred 与 observed 的合取必须落在同一 occurrence 关联行，SQL 语义为：

```sql
WHERE EXISTS (
  SELECT 1 FROM source_temporal_evidence s
  WHERE s.target_ref = owner.ref
    AND s.source_scope = :authorizedSourceScope
    AND occurred_matches(s, :occurredPredicate)
    AND observed_matches(s, :observedPredicate)
    AND s.recorded_real_at <= :authorityCutoff
)
```

这里 `*_matches` 是已有 owner SQL 谓词生成的说明名，不要求新建 PostgreSQL 函数。分别对两个聚合时间数组执行 EXISTS 会产生不存在的共同见证，应直接替换。授权和语义过滤先于候选预算与正文读取，索引只加速已授权候选。跨域谓词无合法映射时按 unknown 处理，不按 timestamp 数字相交。

createSession 来自产品 Storage，返回尚未 connect 的独立 pg.Client，复用本产品连接参数、TLS、UTC 六位 codec 与安全错误处理。原生 session advisory lock 独占当前安装的 authority；连接丢失后新捕获与改钟关闭。单调 tick 不跨进程延用；新段从实际变更时的 mono 起点继续，包含提交等待耗时。并发存活检查合并为同一次原生查询。readCurrent 是可信同产品 World 组合的纯读入口，不映射 HTTP，也不构造管理 Actor。

`recordings(capability)` 只在可信组合根接收 `TimeRecordings`，再把 `capability.captureTerminal(ctx,{operationId,originRef,consumer,observed,realAt?})` 交给真实模型或效果 owner。该能力没有 app.time 方法或 HTTP 路由。Time 先核实本地原 observed 回执的完整值、原 Consumer 与 Subject，校验本安装 ModelInvocation 来源；随后沿原时域和 Clock 捕获，不读取新默认，也不要求已撤销 caller 再获得 clock.capture。originRef 留在 capture 审计与数据闭包。普通 capture 与回执恢复仍检查当前授权。单业务连接真实场景已验证撤销后公共恢复拒绝、私有完成记录成功、原 terminal 回执重放、错误 Consumer 拒绝，以及 mapped 缺原回执拒绝历史回填。

realAt 是已经持久保存的实际结果到达点。real 域可据此恢复原形成时间；虚拟域只有原 operation 已保存的回执可复用，缺失则返回 time.capture_recovery_unavailable。重取当前点不能修复过去映射证据。公开 references.read 对每项实际资源与当前 scope 授权；精确 Clock 目标委派直接检查真实 ClockRef，real 读取另按无映射资源授权。

World 采用保存独立 domainId/ClockRef，初始包使用 `clock:{initialAt,rate,offlinePolicy,timezone}`，倍率为十进制字符串。旧 worldAnchor/realAnchor/paused 副本、mapClock、worldClockSegments 和旧 clock patch 消费者退出。actual advanceIn 接收真实 ctx 与阶段身份；react_prepare、decision_adopt、observe 分别保存捕获。事件/活动保存真实形成回执，活动暂停剩余时长用整微秒。situation/calendar 纯预览不造捕获。

Clock 修改经 Hept 正式 DBOS 父工作流保存原回执，再以 `clock-reproject:<ClockID>:<revision>` 启动稳定子工作；回放不重新采样。Host 在 launch 和 queue 注册之后启动 authority，并扫描当前自然节点补投影。到期采用在同库事务重新核对 Clock、节点修订和语义 due。业务 Pool、Clock session 与 LISTEN session 各由成熟连接机制承担，不以增大连接池解决事务自等。

时间 data owner 导出域、Clock、全部被保留段、完整 checkpoint、capture 与原操作回执；恢复验证段/捕获/高水位并保留原身份。已有共享 Clock 不被主体包回退到旧 head；跨安装恢复须明确原 authority 身份或来源连接，不能只改 Ref 的 installationId。主体分支的新实时域与原历史域分别处理。包的外层操作回执和 DBOS 进度仍归产品 data owner。
