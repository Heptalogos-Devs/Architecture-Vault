# 管理呈现与扩展

## 采用与产品边界

两产品各自提供正式 API、CLI 与 Web，直接调用相同 owner 方法。联合管理连接各产品正式 Client，展示真实 owner、安装、范围、保存修订与实际生效状态；修改发送给持有者。Nous 和 Hept 独立启动、登录、配置、备份和恢复。

联合 Console 默认由浏览器正式 SDK 分别建立两产品的用户 session；连接面板展示每个安装的登录态、授权范围与失效原因。各服务配置自己的 CORS、cookie prefix 与 trustedOrigins。浏览器不取得宽域服务 API key，联合管理不另建万能代理或第三认证服务。跨产品读取仍由各 owner 对当前用户授权，标准 OIDC 可按明确部署需求接入。

管理前端直接复制 AstrBot 4.29.1 固定提交 `fc6b326fc9012873c4adc0183256c90d34a3d912` 的 Vue 3＋Vuetify 功能组及依赖闭包。复用配置 Profiles、Provider、Persona/能力、插件、Tools/MCP、历史、日志和备份交互；对应服务流程从 `astrbot/dashboard/api/` 与 `services/` 复制改编为本产品 owner 操作。Hept 自己承载产品。Star 生命周期、AstrBotCoreLifecycle、默认对话 pipeline 和全局数据库不进入产品 host。

通用扩展生命周期直接使用原 Hept 已采用的 Cordis `4.0.0-rc.8`（MIT）；MCP/工具/Skills 的运行机械使用实际模型 SDK 或 OpenClaw 已有模块。通用平台只维护产品接纳与能力语义。具体固定来源、文件、许可和小型实测见[第三方研究](../../研究/第三方模型Prompt与管理.md)。

## 管理 API 与显示合同

所有管理输入在服务可信入口建立[CallContext](共同值与调用上下文.md)，沿当前 authorityRef 检查安装/主体范围。管理员查看、改设置或测试工具不产生 Subject 实际经历。主体看过资料、采用任务成果和交往消息由对应业务操作保存。

```ts
interface ManagementTarget {
  product:'nous'|'hept'; installationId:string; baseURL:string;
}
interface ApplyState {
  savedRevision:ManagementRevision;
  adoptedRevision?:ManagementRevision;
  effect:'hot'|'next_call'|'restart';
  state:'saved'|'applying'|'active'|'failed'|'restart_required';
  problem?:Problem;
}
type ManagementRevision =
  | {kind:'settings';revisions:RevisionRef[]}
  | {kind:'resource';revision:number}
  | {kind:'native';revision:string};
interface ManagedItem<T> {
  id:string; owner:string; scope:ConfigScope;
  definition:T; apply:ApplyState;
  allowedActions:readonly string[]; // 当前账号的服务端计算结果
}
```

ApplyState 是真实 owner 的运行视图。`savedRevision` 不推定为 `adoptedRevision`；offline/failed 的管理资源仍可编辑。列表使用共同 CursorPage，长操作返回 OperationRef；HTTP/CLI/Web 完整保留 Problem code/category/messageKey/currentRevision/retry，不凭自然语言匹配错误。

UI 文案统一由 vue-i18n key 与服务 Problem.messageKey 驱动，message 是安全回退。具体业务时间显示 domainId、时区和五轴含义，保留微秒精度原值；截断、未知、部分覆盖与待核实直接显示其字段。图形编辑只是设置/时间/领域方法的调用界面，不另存独立的可变业务状态。

| 管理组 | 同一正式方法与路由根 | 页面内容 |
|---|---|---|
| 设置 | `settings.describe/read/update/reset/history/restore`，`/v1/settings` | 全部命名空间、范围、默认/显式来源、CAS、保存/生效、恢复继承 |
| 凭据/授权 | credentials/auth owner，`/v1/secrets`、`/v1/delegations`及`/v1/auth/*` | SecretRef、绑定、可用性、授权范围、轮换/撤销；秘密值按正式写入流程处理 |
| 模型 | `models.providers/resources/describeRoles`、测试/调用读取；`/v1/model-providers`、`/v1/models`、`/v1/roles`、`/v1/model-invocations` | 来源/模型/角色、实际参数与请求、用量、费用、unknown核实 |
| Prompt | `prompts.describe/read/save/activate/reset/preview`，`/v1/prompts` | 资源/语言/版本/依赖、参数、预览、当前与实际采用版本 |
| 扩展与能力 | `extensions.*`、tools/MCP/Skills owner | 来源、版本、开关、当前权限、加载与停用状态、失败/恢复 |
| 历史/Task | Hept 会话/消息与 work owner；Nous 对象/Encounter/query owner | 分页、筛选、修订、来源与消费、原生会话引用和选定成果 |
| 操作/诊断 | operations/telemetry owner，`/v1/operations`、`/v1/diagnostics` | 当前进度、已发生事实、失败阶段、实际 Artifact 与恢复条件 |
| 数据 | data + 各产品 lifecycle owner | manifest/检查/备份/导出/导入/恢复/分叉/清除范围和缺口 |

AstrBot ConfigProfile 可保存一组参数选择和会话路由；在本产品中表现为 settings 的已命名 preset 与 Role/Consumer binding。应用 preset 是一次明确修改所选范围的操作，当前有效值仍从原有 revision/head 求值；不创建另一套 profile 文件作为运行权威。Persona 页完整保留编辑、分组、排序、Prompt 与能力选择，长期身份/关系修改调用实际 Nous owner，不把管理 Persona 当成唯一认知身份库。

## 扩展资源与 Cordis 运行

共享 `@nous-wave/platform/extensions` 只组合 Cordis、模块发现/清单、配置和运行事实。产品注册可用能力接口，并决定哪些主体/角色/工具可以使用；原生 OpenClaw 扩展/Skills 的生命周期由其原 owner 管理，控制台聚合读取其正式状态。

```ts
const ExtensionManifest = z.object({
  id:z.string().min(1), version:z.string().min(1),
  entry:z.string().min(1), integrity:z.string().min(1),
  source:z.object({url:z.url(),revision:z.string(),license:z.string()}),
  requires:z.array(z.string()), provides:z.array(z.string()),
  configurationNamespace:z.string().optional(),
});
interface ExtensionView {
  manifest:z.infer<typeof ExtensionManifest>;
  enabled:boolean; desiredRevision:number;
  state:'disabled'|'loading'|'active'|'draining'|'failed';
  appliedRevision?:number; loadedAt?:TimePoint;
  activeOperationIds:readonly string[]; problem?:Problem;
}
```

扩展发行物固定来源版本、integrity、许可与依赖，依赖解析使用正常 package manager 与 lockfile。安装/更新操作先取得完整制品、校验 manifest/依赖/当前配置，再通过 Cordis 加载。普通插件是与 host 同权限的受信代码；运行外部不受信工具使用原生 sandbox/process 权限，不能把 Cordis fiber 视作隔离机制。

```ts
const root = new Context();
const fiber = await root.plugin((ctx, config) => {
  const service = createAdoptedModule(config, productServices);
  ctx.effect(() => () => service.close());
}, effectiveConfig);
await fiber.dispose();
```

以上 `Context.plugin` 的返回 Fiber 可 await；`ctx.effect` 注册清理，`Fiber.dispose()` 为异步 API，本轮实际探针已验证。正式使用 Cordis Plugin.Config/StandardSchema 支持和 Fiber.state/await/update/restart/dispose；不另写模块加载器、服务依赖容器或通用清理栈。扩展必须在自己的 ctx 注册真实可释放资源，避免顶层进程常驻副作用。

本产品只补真实业务接纳顺序：

1. 启用时验证当前 authority、依赖和配置快照，调用 Cordis；只有真实加载成功报告 active。失败保存具体 Problem，其他模块仍提供管理入口。
2. 热配置经 settings 保存后由该插件真实消费者调用 Fiber.update 或完整 reload；对不能热改的资源显示 restart_required。异步旧初始化不得覆盖新 revision。
3. 停用先关闭该能力的新业务 admission，记录受影响真实 operation；可取消工作请求取消，已保存输出继续接纳；待外部 effects 明确或进入 unknown 核实后再释放 fiber。
4. 删除/更新前完成相同停用；失败状态可 retry/reload。已派发外部结果属于领域 operation，不随 fiber disposal 丢失；卸载不能把 unknown 标成未发生。
5. 启动从持久 enabled/desired revision 重建 Cordis 对象。Fiber 是进程资源，DBOS/领域记录保有长期工作与恢复；不序列化 Fiber，也不把安装进度保存在内存 Map。

原 Hept `runtime-substrate/src/cordis-adapter.ts` 的 Activation 状态包装、重复 task/disposer 队列与 Cordis 能力重叠，删除这些通用机械。保留外部操作 admission、当前权限与 effect 收尾的产品语义，以 owner 方法连接 operations。不要将普通 extension lifecycle 扩成第二套 durable workflow。

安装资源保存不可变 manifest/Artifact；启用和指定版本通过 settings 修订，进程 Fiber 状态来自真实实例。最小专有安装记录如下，下载/校验/安装进度仍是同一个 DBOS operation：

```sql
create table extension_artifacts (
  id uuid primary key, extension_id text not null,
  version text not null, integrity text not null,
  manifest jsonb not null, artifact_ref jsonb not null,
  installed_by jsonb not null, installed_at timestamptz(6) not null,
  unique(extension_id,version,integrity)
);
```

`platform.extensions` 保存按 extensionId 的 artifactId/enabled/config namespace 绑定；API 更新复用 settings CAS。卸载先解除/替换绑定并收尾，再删除未引用 Artifact。文件删除失败保留实际 pending 范围。`artifact_ref` 指 data owner 对象，不把任意磁盘路径作为可移植公开 Ref。

## Tools、MCP 与 Skills

工具分目录发现/管理、实际执行与业务授权。工具描述使用 SDK/原生已有 schema 和 parts，真实 toolCallId/result/run 引用保存一次；工具参数不能赋予权限。角色允许列表和当前委派在实际执行前求交，撤销阻止新派发，已有远端结果依原身份补交。

OpenClaw Task 直接复用 `src/agents/core-coding-tools.ts` 及 fs-safe、进程、sandbox、路径与 workspace 能力闭包；Skills 采用 `src/skills/loading/workspace-skill-loader.ts` 与 `runtime/refresh.ts`，保留发现、可见范围、快照、修订和容量退路。工作目录不承担隔离。工具进程不挂产品 secrets 和整仓，只拿被授权输入/输出及宿主发放的最小环境。

直接 SDK 角色可使用正式 AI SDK tool 定义。远端 MCP 直接依赖 `@ai-sdk/mcp@2.0.80`：正式 createMCPClient、tools/listTools/callTool、resources 和 close，HTTP/SSE 支持自定义 fetch、sessionId 和协议恢复。固定包源码已解到研究目录核对。stdio 导出当前为 `Experimental_StdioMCPTransport`；仅在需要的受信本机能力使用，默认继承 HOME/PATH 等环境，宿主须给出明确环境和真实运行隔离。MCP 协议和工具转换沿用客户端。

```ts
import {createMCPClient} from '@ai-sdk/mcp';
const client = await createMCPClient({
  transport:{type:'http',url:server.url,fetch:networkClient.fetch,
    headers:authorizedHeaders,redirect:'error'},
  maxRetries:0,
  initializationOptions:{timeout:15000},
  onUncaughtError:error => reportSafeMcpFailure(error),
});
const tools = await client.tools();
// 以正式工具 owner 的执行 gate 包装 execute，传入 SDK 原生 tools。
await client.close();
```

headers在credentials.withSecret回调内构造，该回调包住客户端使用、真实工具执行/模型循环和close。tools及其execute闭包也持有client，不能将它们返回到callback外后提前关闭作用期；模型流消费/取消须收尾后再退出。不把带秘密客户端放入长期全局缓存。服务器资源配置明确transport、URL/command、args、SecretRef/network profile、超时、启用和工具许可。server instructions、工具说明和结果是外部输入，不获得系统授权。OpenClaw已有MCP连接由其owner管理，不重复接第二个相同服务器会话。

管理页复制 AstrBot McpServersSection 的增加、编辑、测试、删除、开关、工具列表/权限与失败显示；新增配置先验证并建立候选客户端，成功再切换当前实例，失败保留旧可用实例和 desired/applied 差异。测试是显式操作，有副作用的 tool test 使用相同 effect/预算授权，不能在读取管理页时自动执行。

## 历史、日志和备份

会话历史读取Hept Message/Conversation。OpenClaw当前sessions.get是近期有界视图；完整原生Task历史/迁移通过[数据规范](数据生命周期与发行.md#原生资料的真实owner)需要建设的SessionManager/backup窄scope接口，保留entry/run/call、retained版本、队列/unknown与workspace闭包。UI不能把recent数组显示成完整导出，也不复制另一套原生历史表。批量删除/导出使用可恢复操作，普通sessions.delete会归档，其归档路径仍在清除范围。执行私有草稿与主体可见成果遵守Consumer/发布边界，管理员删除不改写Subject实际经历。

日志与 trace 复用 Pino/OpenTelemetry/DBOS 及实际 operations 视图。SSE 采用成熟传输，游标对应同一日志/事件 owner 的稳定身份；断线按已确认位置恢复，缺口显式显示。普通日志只含安全字段，不直接输出 SDK Error、完整 tool 参数或原生 request。

Provider 的 APICallError 可能将正文放在 requestBodyValues/responseBody/message/cause；Pino 字段 redact 无法清理自由文本。模型真实 doX 错误出口先抽取 status/requestId/retry 分类，必要 raw 先去秘密并存受限 data Artifact，再以安全 SDK Error 进入 durableCalls；DBOS 的错误序列化和日志仍按其实际范围检查。受限 Artifact 与 checkpoint 的访问、保留和删除是数据管理范围，管理页按授权读取；详见诊断 Spec。业务 Problem 始终来自安全字段。

备份复制 AstrBot manifest、检查、上传/下载、进度与结果 UI/API 流程，后台使用 DBOS 与 data owner。其 `backup_tasks/progress` 内存字典删除。manifest 记录产品/安装/版本、数据库快照、水位、Blob、Prompt/配置修订、原生数据范围及校验摘要。密钥值不进可移植备份；目标安装重新绑定。未知原生/外部备份范围显示 pending/blocked，恢复完成来自实际检查结果。

原生整安装采用现成backupCreateCommand/createBackupArchive和backupRestoreCommand，恢复先进入新staging并显式切换。单Subject的native.data.prepare/export/importPreview/restore/purge是数据规范要求的新接缝；先在真实owner改编后才可将对应管理能力报告available。无消息ID的OneBot文件ack按[物理回执owner](媒体与材料基础.md)保存accepted operation，UI显示实际文件动作/ack；只有真实messageId才提供原消息引用、回复/撤回等动作。

完整OpenClaw archive实际包含config与oauth/credentials，现有API没有excludeSecrets。管理页仅在显式includeSecrets:true并采用成熟加密时执行这种完整安装备份，按artifact标明containsSecrets。默认引用模式要求完整native而未选择含秘密备份时，显示backup.native_secrets_required；不能用“privacy测试通过”推定归档已脱密。Subject Bundle仍按其独立授权选择导出。

## 配置、入口和生命周期

| 定义 | 默认/范围 | 生效 |
|---|---|---|
| UI locale/theme | 管理用户偏好，zh-CN/system | 当前用户下次渲染 |
| 连接产品/安装 | 安装授权配置，无自动扫描 | 显式绑定后；凭据仍由认证/秘密 owner 保存 |
| 列表分页 | 默认50，最大200 | 请求级；不代替领域查询预算 |
| extensions enabled | 显式安装后默认 disabled | 启用成功才 active |
| 插件配置 | 按模块定义和 scope | hot/next_call/restart由真实消费者声明 |
| MCP connect timeout | 安装默认15s；工具执行默认60s，允许角色收紧 | 新连接/调用；长工具有各自声明 |
| 插件停用等待 | 默认30s | 等待到限后保留未结 operation并报告，不能强造成功 |
| 备份/诊断保留 | 由 data/telemetry正式定义 | 管理页展示当前有效策略与实际范围 |

生命周期顺序是 Host 初始化 data/settings/credentials/network，再启动真实所需模块，最后接纳外部请求。模型/可选扩展不可用时保留管理。Host 停止关闭新接纳，按 owner 收尾/持久进度，再 dispose Cordis fibers 和网络资源。每产品 factory 只创建自己的数据库和资源；共享库没有第三个服务或全局产品注册中心。

HTTP `/v1/extensions` 的 list/read/install/update/enable/disable/reload/remove、`/v1/tools`、`/v1/mcp-servers` 对应同名正式 owner；CLI 提供同一操作与 OperationRef 查询。外部安装包、模型/工具测试和备份都由用户显式操作触发，页面初始化只读取目录和状态。
