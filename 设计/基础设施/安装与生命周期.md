# 安装、目录与三种生命周期

## 实现基底

采用 Node.js 24 LTS、TypeScript 7 ESM、pnpm。普通产品和 SDK 运行编译后的 JavaScript；开发运行器只用于开发命令。两个产品分别构建、安装和启动。

共享纯目录解析与运行适配放在 `@nous-wave/platform/bootstrap`，直接搬入原 Nous [resolveLocations](https://github.com/Heptalogos-Devs/Nous-Wave/blob/412b062082afb75ccfae4c3f69fc606d3e3cc862/apps/nous-core/src/locations.ts) 的逻辑根与locator计算，再接 env-paths、confbox、成熟原子文件库及各OS服务工具。领域初始化由产品自己的 composition 完成，bootstrap不创建另一套业务运行器。

## 逻辑根与物理路径

```ts
interface Paths {
  program:string;   // 不可变发行版本与当前版本指针
  runtime:string;   // 已明确取得的Node/PG/FFmpeg/OpenClaw等原生包
  instance:string;  // 实例身份、bootstrap locator和服务描述
  config:string;    // bootstrap文件；运行配置以数据库为准
  data:string;      // 所属产品的持久数据库/正式导出工作区
  blob:string;
  cache:string;
  secret:string;
  log:string;
  run:string;
  temp:string;
  backup:string;
  workspaces:string;
  exports:string;
}
```

env-paths 只提供OS默认位置，bootstrap负责创建与授权，随后向模块注入绝对只读 Paths。默认产品名为 nous-wave / heptalogos，实例子目录包含稳定 installationId。支持显式instanceHome及locator逐根覆盖；相对路径相对于locator所在目录解析。

| 类别 | Ubuntu默认 | Windows默认 | macOS默认 |
|---|---|---|---|
| config | XDG_CONFIG_HOME/product/instance | APPDATA/product/Config/instance | Library/Preferences/product/instance |
| data/blob/runtime/workspaces | XDG_DATA_HOME/product/instance | LOCALAPPDATA/product/Data/instance | Library/Application Support/product/instance |
| log | XDG_STATE_HOME/product/instance/log | LOCALAPPDATA/product/Log/instance | Library/Logs/product/instance |
| cache | XDG_CACHE_HOME/product/instance | LOCALAPPDATA/product/Cache/instance | Library/Caches/product/instance |
| temp/run | env-paths temp下实例目录 | 用户TEMP下实例目录 | env-paths temp下实例目录 |
| secret | 受限实例目录/OS keyring | 明确服务账号凭据与受限文件 | 服务账号Keychain/受限文件 |
| backup/exports | 安装者显式选择的持久目录 | 同左 | 同左 |

目录解析直接取 env-paths，不硬编码用户名或某台开发机路径。可重建cache和temp不保存唯一正式成果；program更新不覆盖data。

当前开发环境的新增下载、工具缓存、实验安装和临时构建统一放工作区 `temp/`。Windows为用户指定的 `C:\dev\Heptalogos-Devs\temp\`；当前Linux工作区使用其 `temp/`。已有 `data/` 资料就地读取。正式发行包内部的 `dist/` 是已编译文件，实验输出路径不写入公开SDK依赖。

## Bootstrap 文件

```ts
interface Bootstrap {
  formatVersion:1;
  product:'nous'|'hept';
  installationId:string;
  paths:Partial<Paths>;
  database:
    | {mode:'external';urlRef:string;maxConnections:number}
    | {mode:'managed';runtimeRef:string;port:number;database:string;
       user:string;passwordRef:string;maxConnections:number};
  listen:{host:string;port:number;publicBaseURL?:string;trustedOrigins:string[]};
  service:{mode:'foreground'|'user'|'system';autoStartHost:boolean};
  logging:{level:'debug'|'info'|'warn'|'error'};
}
```

TOML由confbox读取。选择顺序为CLI `--config`、NOUS_CONFIG/HEPT_CONFIG、env-paths默认配置。明列环境覆盖仅有配置路径、数据库引用/秘密输入、监听、数据根和日志级别；结果显示来源。普通运行字段不按任意双下划线映射整棵配置树。

默认仅回环监听；Nous端口4333，Hept8788。publicBaseURL与trustedOrigins由管理员明确设置，供认证/反向代理使用。软件安装和Host启动默认不启用Subject、不安装可选模型包、不发付费模型调用。

installationId首次初始化通过原子独占创建持久保存。并发初始化读取已创建身份；绑定已有实例与创建新实例分别执行。绝对机器路径留在本地bootstrap，不进入Subject Bundle。

## 生命周期与接口

```ts
bootstrap.inspect(locator):Promise<BootstrapView>
bootstrap.init(input):Promise<InstallationRef>
bootstrap.doctor(input):Promise<OfflineDiagnostics>
bootstrap.configure(input):Promise<BootstrapView>
service.install/start/stop/status/uninstall(input):Promise<ServiceResult>

host.start(options):Promise<Host>
host.status(ctx):Promise<HostStatus>
host.drain(ctx,{reason,deadline}):Promise<DrainResult>
host.stop(ctx,{mode:'graceful'|'force'}):Promise<StopResult>

subjects.start(ctx,{subjectId,expectedRevision}):Promise<SubjectStatus>
subjects.pause/resume/stop(ctx,input):Promise<SubjectStatus>
```

Bootstrap操作使用当前OS账号与明确机器/恢复权限，能在Host、模型或业务数据库不可用时执行有限目录、服务、配置与诊断操作。普通业务修改仍通过其owner，离线CLI不直接改Memory/World表。

Host负责数据库、认证、API、已启用的连接和持久工作。Subject负责自己的前台、自主性、活动及获准后台工作。GUI关闭不停止Host；Subject睡眠/暂停也不停止收件、原件保全和管理。

## 初始化与启动顺序

1. 解析locator和Paths，检查版本、目录权限、运行依赖与当前选择的数据库模式；不联网取得未安装资源。
2. 首次init创建安装身份与bootstrap，创建受限SecretRoot，按所选模式准备数据库；CLI显式创建初始管理员。
3. 用迁移身份运行产品自己的Kysely migrations与Better Auth正式migration，初始化官方DBOS datasource所需schema/授权。运行账号使用最小数据库权限。
4. Host注册领域操作、实际需要的DBOS workflows/queues和能力定义；加载Settings目录、当前资源引用与认证。
5. 启动API和本地诊断；分别报告模型、索引、渠道及可选原生运行环境的就绪程度。某个Provider离线不会关闭普通管理。
6. 仅按已保存的Subject运行授权和明确autoStart设置恢复对应工作。全新安装没有这些已授权工作。
7. 网络、Prompt、索引和媒体消费者按快照使用配置。需要原生工具/渠道时才连接已安装OpenClaw。

某项数据库迁移失败时停止业务启动并给出具体迁移/版本；offline doctor、bootstrap与服务管理仍可使用。不要在认证数据库失败时开放一个无鉴权写入模式。

## PostgreSQL 形态

支持外部PostgreSQL18、标准Docker Compose以及显式选装本地managed PG。两产品各有业务数据库与迁移，可共用外部物理实例。产品服务停止不停止外部数据库。

本地managed采用 `embedded-postgres` 的成熟 `initialise/start/stop/createDatabase/getPgClient`。已核实包 `18.4.0-beta.17` / commit `8c8c16d1b81bec8ae3315d59a050654086a85e23`，它的wrapper版本带beta标记，运行平台包分别发布；实际发布验证随平台施工完成。它在模块加载时会选择平台binary，因此只在明确选择且已安装的managed模式动态加载。

```ts
const pg = new EmbeddedPostgres({
  databaseDir:paths.data+'/postgres', port, user, password,
  authMethod:'scram-sha-256', persistent:true, createPostgresUser:false,
  onLog:safeLog, onError:safeError,
});
await pg.initialise(); // 仅未初始化时
await pg.start();
await pg.createDatabase(database); // 仅首次所选产品库
```

不采用该包默认 password，也不在正常主机上启用createPostgresUser。运行于明确的非root服务账号。取包及平台binary属于显式 `runtime acquire postgres` 或安装选项，普通serve只加载已安装包。外部/Compose模式不强制安装这些binary。

两个独立managed安装使用各自cluster和端口；联合安装可配置同一独立PostgreSQL服务里的两个库。不要让停止Nous Host隐式关闭Hept仍在使用的cluster。

## OS服务的直接采用

- Ubuntu：生成标准systemd unit，使用绝对Node与entrypoint、WorkingDirectory、受限服务账号、SecretRoot权限和标准restart/stop timeout。使用systemctl管理和查询，不写自有daemon监督器。
- Windows11：打包Shawl，调用 `shawl add --name <instance> -- <absolute-node> <entry.js> ...`，明确cwd与服务账号。通过Windows SCM管理启停。Shawl把stop转成ctrl-C，产品处理SIGINT并在期限内关闭；不靠管理员当前PATH查找node。[上游实际用法](https://github.com/mtkennerly/shawl#usage)。
- macOS：生成原生launchd plist，ProgramArguments使用数组和绝对路径，按user/system模式选择相应域及账号，通过launchctl加载/停止。Keychain和服务账户匹配。

服务配置默认不开机启动Subject。Host自动启动与Subject自主工作分别显示。系统服务的权限提升由OS完成，网页人格模型没有机器服务控制权限。

## 停止、异常与重启

正常停止先关闭新Subject工作接纳和新付费派发，再让外部效果owner保存已知结果；取消或暂停可取消的后台工作，按World离线政策保存相应时钟/高水位；停止渠道接入或保留其明确停服状态；关闭API、DBOS、网络池、OTel，再关闭仅由本安装独占管理的PG。

Node收到SIGINT/SIGTERM走同一停止函数。默认graceful期限30秒，可配置；超过期限由OS supervisor执行实际终止。强停后恢复通过DBOS、当前领域事实、native结果和unknown语义继续，不能仅因进程新启动就重发旧效果。

世界的正常停钟回执与异常关机缺口由[时间owner](时间与调度.md)处理；Host不在自身配置中保存另一份World状态。原生执行历史仍在OpenClaw，恢复采用相同run/session/call身份。

## 就绪与运行状态

HostStatus分开报告process、database、auth、native、models、index、channels和Subjects。每项有available/degraded/unavailable及Problem/操作引用；整体产品可受限运行，不用一个布尔健康值隐藏具体状态。

liveness只表明当前进程可响应；readiness由实际消费者需要的能力决定。`status --watch`使用正式状态流。数据库不可用时，CLI仍能给出OS服务和bootstrap诊断，不伪造领域状态。

## 发行与SDK

发行清单记录版本、平台/架构、入口、Node要求、schema版本和可选runtime。使用正常包管理器、lockfile和上游发行件；源码改编的OpenClaw/OneBot插件提供固定基线与差异，安装后不搜索修改node_modules。

Nous contracts/client/platform分别产出可独立安装的普通ESM包与d.ts。Hept的正式依赖为这些发行版本或已构建tarball；删除相邻开发仓库link。CI/本地只使用TypeScript7编译器，不为AST工具加回TS6。

开发构建可使用共享temp中的输出与安装试验；发布包内export指向相对编译JS和types，不能依赖某台机器的temp、data或TypeScript开发入口。两产品的生产依赖闭包分别安装检查。
