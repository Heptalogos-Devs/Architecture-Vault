# 模型供应与调用

## 1. 责任与采用

通用实现位于 Nous 仓 `packages/platform/src/models/`，由普通库 `@nous-wave/platform/models` 导出。Nous 与 Hept 各自创建实例，绑定各自数据库、配置、凭据、网络、操作记录与角色目录。库不读取 Memory、World、Reactor 表，也不保存跨产品共享状态。

采用 AI SDK `7.0.146`，固定源码提交 `0a5c786ef65bcd835328fb543685f6d8ef233dae`。直接使用 Provider Registry、正式 Provider 包、各模型族 API、结构化输出、工具循环、流和 middleware。专业 Task 继续使用 OpenClaw 原生执行能力；它的每次实际模型调用接相同的计量与上下文边界。主观审议、世界作者、自然表达、认知形成和成长直接调用 SDK。

复用来源与许可证、真实源码入口见 [研究报告](../../研究/第三方模型Prompt与管理.md)。Prompt 资源与认知贡献见 [Prompt 与上下文](Prompt与上下文.md)，管理操作见 [管理呈现与扩展](管理呈现与扩展.md)。共同身份、调用上下文与错误采用[共同值](共同值与调用上下文.md)。[网络工厂](网络与外部资源.md)提供兼容 WHATWG Fetch、Request、FormData 与流的 fetch，具体使用 Node24 原生 Fetch＋Undici8 官方 Dispatcher1Wrapper；Provider 工厂使用既有 `fetch` 选项注入。

## 2. 资源、职责与本次采用值

### 2.1 稳定值

以下 schema 位于 `@nous-wave/contracts/models`，只依赖纯值与 Zod。产品 RoleId 是自己注册的字符串，平台没有写死业务角色枚举。配置采用 settings 的 revision vector，PromptSnapshotRef 从 prompts 引入；两者独立于 Memory/World 的业务 state revision。

```ts
const ModelKind = z.enum(['language','embedding','reranking','transcription','speech']);
const ResourceRef = z.object({ id: z.string(), revision: z.number().int().positive() });
const ProviderOptions = z.record(z.string(), z.record(z.string(), z.json()));
const Reasoning = z.enum(['provider-default','none','minimal','low','medium','high','xhigh','max']);
const Selection = z.enum(['ordered','balance','random']);

const ProviderDefinition = z.object({
  id: z.string().min(1), adapter: z.string().min(1),
  baseURL: z.url().optional(), credentialRef: z.string().optional(),
  networkProfileId: z.string(), options: z.record(z.string(),z.json()),
  enabled: z.boolean(),
});
const ModelResource = z.object({
  id: z.string().min(1), label: z.string().min(1), providerId: z.string(),
  modelId: z.string(), kind: ModelKind, enabled: z.boolean(),
  capabilities: z.array(z.string()),
  contextLimit: z.number().int().positive().optional(),
  outputLimit: z.number().int().positive().optional(),
  providerOptions: ProviderOptions, pricingRef: z.string().optional(),
});
const LanguageSettings = z.object({
  maxOutputTokens: z.number().int().positive(),
  temperature: z.number().optional(), reasoning: Reasoning.optional(),
  providerOptions: ProviderOptions,
});
```

这些是无默认完整约束 schema，defaults 独立提供：Provider 新定义 enabled=true/options={}，ModelResource 新定义 enabled=false/capabilities=[]/providerOptions={}，language defaults maxOutputTokens=2048/providerOptions={}。无效或未完整配置的资源不能承担职责。稀疏输入按 settings JSON Patch 修改本层值，合并全部来源后校验。

Resource 的 kind、模型 ID、窗口和模态描述对应管理员选择的真实资源。Provider adapter 决定如何构造 SDK Provider 及其参数命名空间，价格引用真实价目。连接状态、近期错误、实际使用模型与配置定义分别展示，不将连接测试结果改写为配置。

Provider的options是所注册adapter校验的非秘密配置；凭据、敏感headers与签名材料仍用SecretRef，在withSecret内交SDK。配置保存和trace不把原始秘密塞入任意options字典。推理ProviderOptions保留SDK原有命名空间和参数语义。

需要认知预算的 language 资源执行前必须取得真实 contextLimit/outputLimit，来自明确资源配置或已固定的官方模型元数据。未知时提示配置缺项，不按模型名称猜窗口。候选选择先过滤 kind、能力、当前可用性与授权，再执行 ordered/balance/random；随机选择结果进入快照，恢复使用原选择。对已派发的 unknown 调用不切换候选。

RolePolicy共有kind、enabled、resources、selection、timeoutMs、budgetPolicyRef、Prompt绑定；参数部分按ModelKind区分。language才有maxOutputTokens/temperature/reasoning；embedding可设置SDK批处理并行上限和ProviderOptions；重排有topN；转录/语音使用各自输入与ProviderOptions。

```ts
const LanguageRolePolicy = z.object({
  kind:z.literal('language'),enabled:z.boolean(),
  resources:z.array(ResourceRef),selection:Selection,
  timeoutMs:z.number().int().positive(),budgetPolicyRef:z.string().optional(),
  prompt:PromptBindingSchema,inference:LanguageSettings,
});
```

完整 schema 另要求启用的 RolePolicy 至少有一个资源。干净安装可以保存禁用且候选为空的职责，等待管理员配置后启用。`prompt` 对有固定程序 Prompt 的职责提供，纯 SDK 操作可以只提供实际消息；产品 RoleDescriptor 决定该职责需要的指令与参数合同。

以上ProviderDefinition/ModelResource描述SDK自己管理的资源。原生资源在正式目录使用不同definition分支，避免把native连接再存成一份可改SDK配置：

```ts
interface NativeModelBinding {
  id:string;runtimeId:string;nativeResourceId:string;
  configRevision:string;
  actualProvider:string;actualModelId:string;kind:ModelKind;
  capabilities:readonly string[];contextLimit?:number;outputLimit?:number;
}
type ModelDefinition =
  | {managedBy:'sdk';definition:z.infer<typeof ModelResource>}
  | {managedBy:'native';id:string;binding:NativeModelBinding;
      enabled:boolean;pricingRef?:string};
```

native binding持久登记真实runtime/resource定位；配置revision/能力是从实际原生owner读取的视图和本次调用快照，不建立另一份可写配置head。本产品只管理启用、费用及角色/任务引用。Role使用统一ResourceRef选择真实分支，SDK工厂只接收sdk分支。

角色目录由产品领域提供：

```ts
interface RoleDescriptor {
  id: string;
  label: string; description: string;
  kind: ModelKind;
  requiredCapabilities: readonly string[];
  defaultPolicy: unknown;       // 由该 kind 的正式 schema 校验
  promptId?: string;
  outputSchemaId?: string;      // 领域合同的身份，不是第二份可写 schema
}
interface InvocationSnapshot {
  config: {revisions:RevisionRef[];definitionRevisions:Record<string,string>;digest:string};
  roleId: string;
  requestedResource: ResourceRef;
  actualResource: ResourceRef;
  actualProvider: string; actualModelId: string;
  prompt?: PromptSnapshotRef;
  inference: unknown;           // SDK 对应模型族的已校验设置
  credential?:{ref:SecretRef;revision:number;generation:number};
  network:{profileId:string;revisions:RevisionRef[]}; // 引用与修订，绝无秘密正文
  budgetAllocation?:BudgetAllocationSnapshot;
}
```

### 2.2 配置范围、默认和生效

| 项目 | 范围 | 默认 | 生效时机 |
| --- | --- | --- | --- |
| Provider 来源、凭据与网络绑定 | 安装 | 未配置即不可用；不自动猜选服务 | 新调用使用新配置；现有连接按网络/凭据 owner 的撤权与收尾规则处理 |
| 具体模型目录、模态与限额 | 安装 | disabled/未配置能力不承担该职责 | 新调用 |
| Role 候选资源及推理设置 | 安装默认→主体→职责 | 产品 RoleDescriptor 提供默认；普通语言角色输出默认 2048，另受真实资源 outputLimit 限制；temperature 留给 Provider 默认 | 下一次调用快照；一个调用中保持已采用值 |
| reasoning | 职责/调用 | provider-default | 本次实际步骤 |
| ProviderOptions | Provider/资源/职责/调用 | 空对象 | 按命名空间合并；显式参数交给 SDK Provider 处理 |
| SDK 自动重试 | 实际调用 | 0 | 物理结果为 unknown 时先核实；已知 not_sent 才能按已配置策略选择下一资源 |
| 管理读取 | 安装/授权主体 | 始终可用 | 不要求模型在线 |

PatchSchema 独立定义且无 default：只校验显式字段，合并覆盖后才对完整设置补默认。清除覆盖恢复上层来源；删除、数组替换与对象合并使用 settings 的正式语义。RolePolicy 的读取同时返回实际来源、配置修订和是否已生效。

## 3. 工厂与调用接口

```ts
createModels({
  product,installationId,processBootId,db,settings,credentials,network,prompts,data,
  roleCatalog,providerAdapters,clock,authorize,budgetScopes,
  beforeDispatch?,contextHooks?,nativeBindings?,diagnostic?,
}): Models

interface Models {
  providers: ProviderManagement;
  resources: ModelResourceManagement;
  invocations: {list(ctx,filter);read(ctx,{invocationId})}; // 全局管理读，可选Subject
  reconcile(ctx,input):Promise<ModelCallView>;
  costs:{read(ctx,filter):Promise<ModelInvocationPage>};
  describeRoles(ctx, scope): Promise<RoleView[]>;
  prepare(ctx, roleId, callOptions?): Promise<InvocationSnapshot>;
  text: {
    bind(ctx,callOptions):Promise<LanguageModelV4>;
    generate(ctx, request: TextRequest): Promise<TextResult>;
    stream(ctx, request: TextRequest): Promise<TextStream>;
  };
  embeddings: { embed(ctx, request); embedMany(ctx, request) };
  reranking: { rerank(ctx, request) };
  transcription: { transcribe(ctx, request) };
  speech: { generate(ctx, request) };
  native: { prepare(ctx, event); dispatch(ctx, id); complete(ctx, event) };
}
```

这些方法选择 SDK 对应操作。稳定 operationId 来自可信 `ctx.trace.operationId`，roleId、真实输入/来源与领域用途由调用 owner 提供；actor、consumer、authorityRef 与资源范围在可信入口建立，真正派发前重新检查当前授权。

TextRequest 使用 SDK 的 ModelMessage、tools、toolChoice、Output 与推理设置。领域传入自己的输出 Zod schema，输出仍经本领域采用流程验证。API、SDK 与原生消息的转换只发生在真实外部边界。输入包含图像、文件、音频、工具请求/结果或不透明 Provider 状态时保留对应 parts。

Provider 工厂基本形式：

```ts
const {resource:networkScope} = await models.networkSelection(ctx,modelRef);
const transport = await network.client(ctx, {resource:networkScope,deadline});
return credentials.withSecret(ctx, {
  ref:provider.credentialRef,purpose:'model.provider',
  resourceRef:providerRef,useRef:modelRef,
}, async secret => {
  const sdkProvider = adapter.create({
    provider, apiKey:new TextDecoder().decode(secret), fetch:transport.fetch,
  });
  const registry = createProviderRegistry({ configured: sdkProvider });
  const model = registry.languageModel(`configured:${resource.modelId}`);
  return runWithSdk(model); // 返回本次结果，不返回捕获 secret 的 SDK 实例
});
```

秘密用途解析与当前 guard 来自[身份与密钥](身份权限与密钥.md)的当前资源/消费者授权。无凭据的 Provider 走同一执行闭包。秘密不经方法结果、DBOS input/output 或长期缓存返回；SDK 需要 string 时只在 callback 内构造和使用。连接池由 network 复用，非秘密的 adapter/资源求值缓存按配置、凭据修订、网络修订与版本索引。参考 MaiBot ClientRegistry generation：替换后新请求取新代，旧初始化不回填新缓存。捕获 apiKey 的 SDK 实例仅在本次 callback 有效，结束后释放。

实际 Credential 调用为 `credentials.withSecret(ctx,{ref,purpose:'model.provider',resourceRef:providerRef,useRef:modelRef}, callback)`。`models.credentialTarget` 是此 purpose 的静态关系解析器，返回已核验的 `{operation:'models.invoke',target:modelRef}`。SDK 准备输入和额度期间可能经过异步等待；注入 SDK 的真实 fetch 在发请求前再次核验同一秘密代际，保留完整响应/流的外层 callback 使用期。

Provider Registry 的本地 key 固定为 `configured`，实际 Provider 身份仍由正式定义与 SDK model.provider 保存。这样命名 Provider ID 与 vendor modelId 都保留原字符串，后者中的冒号不参与错误的 Provider 分割。

### 3.1 当前施工接口

`modelSettingsModules(roleCatalog,providerAdapters).modules` 注册 `platform.providers`、`platform.models`、`platform.roles`、`platform.modelPrices`、`platform.modelBudgets`、`platform.modelLimits`。Provider、Model、价目与命名预算是安装级 dictionary；Role 与 modelLimits 按安装→主体→职责求值。modelLimits 是有静态字段元信息的单份 ModelBudget；实际准入同时核验每个祖先 scope 的有效约束。命名预算由 Role.budgetPolicyRef 引用，作为附加约束，不另建余额。金额为空不清除祖先上限。Model 的 ResourceRef.revision 采用该 Model dictionary 的真实 Settings 修订；价目写入 `{id,rates}`，快照中的 PriceBook.revision 同样来自实际 namespace 修订，不维护第二个计数器。精确历史读取使用已注册 consumer 的 `snapshotRevision`，当前多 scope 读取使用 `settings.snapshotConsumers(existingHandles)` 的一条批量 SQL。

`createModels` 直接接收 `product/installationId/processBootId/db/settings/credentials/network/prompts/roleCatalog/providerAdapters/clock/authorize/data/budgetScopes`，另有 `beforeDispatch/contextHooks/nativeBindings/diagnostic` 钩子。产品保留各自 ModelInvocation 表与迁移，注册共享 `modelMigration/ModelsDatabase`；旧 Invoice 表与生产者、消费者整体删除。

TextRequest 是 `{roleId,inputRefs,resource?,budgetAllocation?,promptParams?,estimate?,selection?,preparation?,contextHooks?,options}`。preparation 保存原 referenceTime/contextRef/inputDigest，contextHooks 仅为受信宿主闭包，不进入 wire 或模型输入。options 保留真实 SDK 的消息、工具、Output、回调及参数，model 由正式资源选择，maxRetries 固定为0。`text.bind` 返回不持有秘密、保留真实 SDK metadata 的 V4 边界，供宿主在原生 SDK prepareStep.model 中选择；任意未登记模型不能绕开实际计量边界。其余模型族使用同一调用字段和本族原 SDK options。Host 初始化通过官方 `globalThis.AI_SDK_LOG_WARNINGS=false` 关闭 SDK 自由文本 warning 输出；原 warnings 仍保留在受限实际结果中，不按调用切换全局日志。

`data.validateSources` 在派发前重验当前来源；`saveInput` 保存实际 V4 参数和 observed 回执，返回正式输入 Ref；`saveOutput/loadOutput` 保全并恢复实际 V4 结果，包含 Date 与二进制 Blob；`adopt` 采用原 observed/formed 与已保存输入、输出 Ref。SDK Provider 输出属于受限原件，面向认知或生活的可读投影由实际产品 owner 形成。 Nous 分别保存带 V8 Blob 的 raw holder 与无 Blob 的 text/plain 成果，outputRefs 保留两者；typed 回放读取原件，Encounter.resultRef 采用文本成果。raw 模型记录不进入普通 publish，文本成果发布后仍沿原件与输入链检查当前来源策略。 Subject 范围的 Nous 输入、输出走 Materials 私有实际接收能力，输出继承已保存输入的来源、策略和 Consumer；已完成的事实写入不再次要求原调用者 models.invoke，后续读取仍重验当前来源。安装级模型测试保存 ModelArtifact 与原 V4 bytes，不创建占位 Subject 或 Experience。库不复制这些领域的 SQL、来源语义或经历状态。 typed bytes 使用 Node 原生 v8 serialize/deserialize 与现有内容存储保全 Date、二进制和 Provider 类型；普通日志与 operation inspect 不返回这些原件。

调用视图包含原 purpose/audience、traceId、authorityRef、NativeOrigin 与原 Consumer；invocations.list 可按 logicalOperationId 精确读取本语义 phase 的全部物理调用。管理者重采用保留这些原事实，ctx 继续表示实际当前发起者。

`models.data.export/import/deleteSubject` 由唯一调用表 owner 执行，纯 ModelDataBundleSchema 位于 contracts/models。可传当前同库 Kysely 事务；JSONB 的对象与数组均显式按 JSONB 写入。恢复保留原调用身份、snapshot、observed/formed、费用、预算键与 typed output Ref，prepared/dispatched 导入为 unknown；已有已确认结果互相矛盾时拒绝。同主体恢复不发 Provider。实际原件与来源资料由产品数据闭包一起搬运。

默认适配器采用官方 `@ai-sdk/openai`、`@ai-sdk/openai-compatible` 与 `@ai-sdk/cohere`。OpenAI 与兼容端点将通用 reasoning 映射到正式命名空间的 reasoningEffort；其他适配器缺少对应映射时明确报告未配置，原 ProviderOptions 继续保留。Cohere 重排的实际 billed_units 从原响应元数据保留，缺失费用单位保持未知。

`models.networkSelection(ctx,modelRef)` 是模型资源 owner 的目标授权函数，返回 `{resource:ResourceNetworkScope,scope:ConfigScope}`：固定 Model Ref、Provider 选中的 profileId、当前允许 origins/paths/methods、地址与凭据范围。它不从模型正文选择目标，也不读取未定义的 provider.networkScope 字段。配置快照为全部参与 namespace 的 revision vector＋definitionRevisions map，不能用一个定义版本代表所有模块。

流式方法的 callback 持续到 SDK流实际结束、错误或取消收尾。对外提供标准 ReadableStream/parts 与最终安全结果；用 Web Streams 的背压/取消连接消费，禁止把持有 secret 的原 SDK结果/Provider/iterator返回到 callback 外后提前结束withSecret。MCP tools及其 execute闭包同样在受控客户端作用期内使用。HTTP断开触发同一AbortSignal并等待真实收尾，不依赖垃圾回收来结束秘密使用。

## 4. 实际调用顺序

### 4.1 语言、结构化与工具步骤

1. 领域提交当前输入与职责。读取有效设置，验证资源/能力和权限，取得 ConfigSnapshot、PromptSnapshot、凭据/网络引用；创建稳定逻辑操作。配置资源 API 复用 settings 修订/head，资源目录、RolePolicy 没有第二份可修改镜像。
2. 交给 SDK `generateText/streamText`。宿主先完成本步实际模型选择、active tools与任何语义消息变换，再在prepareStep使用当前 `step.messages`、最终选择与工具预算取得认知贡献；将冻结 role instructions 与本次认知 slot 合成，保留当步完整消息。
3. SDK 完成工具选择、消息转换后，onStepStart 记录最终 instructions/messages/promptMessages/stepTools。近 Provider 的 wrapGenerate/wrapStream 冻结实际 V4 params、输入估计和物理调用身份。
4. 实际doX派发前按稳定捕获操作取得observed TimeCaptureReceipt，保存到本次输入快照；跨库capture在本地SQL事务外完成。随后同一数据源短事务检查当前授权/额度并预留、记录prepared及派发事实，紧邻实际Provider方法执行。not_sent只留下捕获与调用事实，不产生Encounter。真实网络等待期间不持有业务行锁。
5. 捕获 request.body、response metadata、warnings、原始/规范化 usage、实际输出与 finish reason。二进制保存为正式 Blob；记录引用和摘要，避免在普通日志重复塞入 base64。
6. Provider terminal处先保全真实输出、usage与现实到达点，记录已知completed；同时按稳定操作取得输出formed TimeCaptureReceipt，在输出owner正式语义结果持久时保存。成功/可确认消费后Encounter采用第4步原observed，recorded是实际现实提交点。capture/语义采用失败保留原输出、费用及待接纳进度，不将已知completed降为unknown。领域合同解析失败仍保留实际输入消费、输出与费用。
7. SDK 工具结果进入下一步消息；下一步重新准备认知。循环、并行工具、流与结构化输出仍由 SDK 承担。

`prepareStep` 返回的 messages 保留本步真实历史与工具结果。每个尚未派发的 physical step 重读当前 Role、Prompt 与候选配置；已经保存的 physical step 使用原冻结 snapshot/preparation。base instructions 从该步 PromptSnapshot 与宿主指令组成，上一轮临时认知不进入下一轮 base。Hook 的 snapshot.inference 已合入本步实际 SDK 参数，输出预算读取此值。

onStepStart/实际V4边界核对已准备的模型、工具、事实输入与来源。Provider协议表示转换可继续由SDK承担；新的语义裁剪、压缩或middleware变换必须先回到该宿主的准备位置，重做认知与预算，不能在prepare之后悄悄换输入。当前来源授权在官方 durableCalls 外层和 dispatch 重验；SDK checkpoint 重放同样不能绕过撤权。实际 V4 params 除 AbortSignal 后计算 inputDigest；复用 operation 但改变消息、工具或参数时返回 input_changed。

接纳原输出失败时，恢复沿原input/output capture和固定成果继续；不得重新取now改写已保存formed/observed。ClockSource暂不可用时保全实际输出及现实到达点，按原稳定capture操作继续时间接纳，停在明确待接纳进度；Provider结果仍是completed，不再次派发。准备/只读查询只用时间参考，不创建observed。未显式 selection 时，实际捕获固定使用 preparation.referenceTime 的 domainId 与无 revision Clock Ref；正常 terminal 与恢复保持同形 selection。首次 terminal 不传 realAt；恢复时才带已保存的现实到达点，虚拟域须恢复原 capture receipt。 `ModelClock.captureTerminal(ctx,{operationId,originRef,consumer,observed,realAt?})` 是 Time owner 只交给实际结果接收者的私有能力；校验原本地 observed、Consumer/Subject 与来源后记录终止事实，沿原时域捕获。它不作为 app.time 或 HTTP 操作公开。普通 capture 保持当前授权，外部源没有实际 record 能力时保留 completed/输出/费用并等待接纳。

### 4.2 其他模型族

- embed/embedMany 保留 SDK 的批次、并行与模型限制；每个实际 doEmbed 请求具有独立调用身份与用量，逻辑操作聚合它们。重放采用已保存批次结果。
- rerank 保存输入文档引用与原始索引映射，返回原有文档身份和实际 score，不将排序生成内容当作新证据。
- transcribe 保留原始音频引用、实际转录、分段、时间与语言；generateSpeech 保留实际音频与媒体格式。它们的 Provider 原结果可有 request 与 usage，不能只从高层文本/音频结果计费。
- LanguageModelMiddleware 只覆盖语言模型。各模型族在真实 doX 接口加同一操作记录与计量边界；SDK 协议、multipart、流解析和 ProviderOptions 原样保留。

DBOS管进度和步骤重放；普通Kysely owner事务保存短修改，workflow中的正式采用步骤才使用官方datasource把业务/checkpoint共同提交。稳定调用身份至少区分logical operation、SDK step、物理attempt/批次；SDK之外不再维护队列、租约或重试循环。

实际采用官方 `@dbos-inc/vercel-ai@0.5.4`。它的durableCalls默认允许DBOS重试，正式物理调用显式使用 `durableCalls({retriesAllowed:false,include:{requestBody:false,responseBody:false}})`，SDK maxRetries也为0；Provider inner gate读取长期ModelInvocation以阻止进程恢复重派已dispatched调用。确认not_sent后的再次尝试由原owner明确采用新attempt。

组合顺序明确为 `wrapLanguageModel({model:safeBoundaryModel,middleware:durableCalls(options)})`；safeBoundaryModel由真实Provider model加本产品实际边界组成。这样doX/error安全化和stream消费都在官方durable step内部。该inner边界的预算/dispatch/Provider结果记录使用普通Kysely短事务和长期幂等回执，不能在DBOS step内再开datasource.runTransaction。网络不在SQL事务中；外层workflow后续领域采用可使用官方datasource。

官方同一workflow不允许并发durable model calls；embedMany并行批次等场景要先冻结稳定批次/调用身份，每个实际批次启动官方子workflow，在各自工作中使用durableEmbeddingCalls；语言并行任务同理。SDK原有批次上限、输入/结果顺序及并行能力保留，不直接在同一workflow并发重入durable middleware。并发开始前固定计划，不能依完成顺序分配恢复身份。官方internal.restoreAISDKErrorIdentity已处理重放后AI SDK标记，直接复用。

### 4.3 OpenClaw 专业 Task

OpenClaw 原生任务拥有其历史、工具循环、Skills、子代理、沙箱与原始输出。采用固定源码能力闭包，在实际每次模型边界调用 native.prepare/dispatch/complete，并请求同一个认知准备服务。常规循环、辅助摘要、手动/预压缩及 Provider-owned compaction 都应进入相同实际调用合同。

认知接线按产品实际能力选择。独立Hept使用自己的种子/近期事实和角色输入，Native调用仍由其本地模型owner计量；没有Nous绑定时不强制请求Nous。绑定Nous且该角色要求长期认知时，使用正式Client的contextHooks；连接失败报告受影响能力，不静默退回一份复制Self。没有角色认知要求的纯SDK操作也可不注册hooks，仍完整保存实际输入/用量与错误。

Hept 保有业务 Task、目标、预算归属、原生 run/session 引用及成果机会；不复制原生执行历史。Nous 认知接入只做实际上下文与消费，专业任务费用由实际执行所属的一个模型 owner 计入，避免两产品重复记账。native usage 在这一外部边界转换一次：原生 uncached input 与 cacheRead/cacheWrite 分项合成总输入，不能直接按 SDK V4 的输入含义解释。

```ts
interface NativeInvocationPrepare {
  invocationId:string; roleId:string; modelResourceId:string;
  actualProvider:string;actualModelId:string;
  native:Extract<OriginIdentity,{type:'native'}>;
  inputTokensEstimate:{value:number;method:string};
  maxOutputTokens:number;inputRefs:Ref[];
  budgetAllocation?:BudgetAllocationUse;
}
interface NativeInvocationCompletion {
  invocationId:string;
  status:'completed'|'not_sent'|'unknown';
  usage?:NormalizedUsage;rawUsage?:JsonValue;
  providerRequestId?:string;outputRef?:Ref;
  formed?:TimeCaptureReceipt; // completed的正式输出采用必须有原formed
}
models.native.prepare(ctx,event) -> ModelCallView // 内含固定snapshot与费用预留
models.native.dispatch(ctx,{invocationId,observed?}) -> DispatchReceipt
models.native.complete(ctx,event) -> ModelCallView
```

正式客户端公开 `POST /v1/subjects/{subjectId}/model-invocations/prepare`、`POST /v1/subjects/{subjectId}/model-invocations/{id}/dispatch`、`POST /v1/subjects/{subjectId}/model-invocations/{id}/completion`；管理读取走 `GET /v1/model-invocations/{id}`，管理恢复走 `POST /v1/model-invocations/reconcile`，Subject 为可选限定，安装级模型测试也能定位恢复。这些原生写入口只接实际 Native Host；SDK 调用沿库内真实边界执行。dispatch/completion 从已保存的 `ModelCallView.native` 取得原调用身份，不在 body 再提交第二份 native。prepare同身份同规范输入返回原结果，不同输入为conflict；dispatch只允许prepared→dispatched，重复返回effect_unknown并要求原生查询；completion幂等采用同一结果。before-dispatch完成后直接进入对应真实Provider方法，不夹额外异步准备。 native.prepare 与 dispatch 同时执行 Host 的 beforeDispatch gate，drain 后拒绝新付费；complete 继续接收已发生事实。原生完成可以先保存无 outputRef 的 completed、费用和 formed，保持待接纳；晚到的实际 Ref 由 native owner 核对原已持久结果后 attachOutputs。无 Ref 的用量确认可在原生 Ref 已保存后重放，保留已有引用；只有提交 Ref 时才与原生终态精确核对。已有完成行不重复计费。当前原 Worker 撤权使认知 capture 不可用时，原生原件和 ContextView 作为实际 pending 定位继续保存，不将模型调用改成 failed/not_sent。

dispatch在真正交还native派发前保存observed捕获；宿主已有同一受权ClockSource的正式receipt时可传入并验证，否则模型owner按当前绑定取得。completion采用原native terminal处的formed；无capture时先保全已知Provider完成事实与输出，时间接纳沿原operation继续。公开completed输入的formed/output约束由联合schema与owner规则检查；not_sent/unknown不补造输出形成。captureId、clock/segment/revision均按真实来源核验，不能从模型生成字段采信。

资源映射由受信 native binding 保存并核对实际 provider/model；Task/root budget owner、consumer 与计费产品从当前委派/实际Task取得，不接受原生模型正文传入。没有资源映射或正式 owner 不可用时停止该次派发。只读预览和 contexts.prepare 不额外计一笔父 Task 费用；其中实际发生的辅助模型调用仍按自己的实际物理调用计入相同预算归属。

SDK资源连接由本产品models管理；OpenClaw原生Provider、模型、工具与Skills配置由其正式owner管理。NativeModelBinding只保存runtime/resource identity、当前配置revision/能力快照及本产品预算/价目引用，连接正文为只读native投影，不再建立第二份可写baseURL/secret/model目录。管理修改发送给真实配置owner。

## 5. 操作、用量与存储

ModelInvocation是长期模型事实，自己保存真实prepared/dispatched/completed/not_sent/unknown及输入、结果与费用。DBOS拥有运行进度、checkpoint和恢复；operations聚合官方状态与该回执，不建立通用platform_operations状态表。调用归属的逻辑operation/trace和可选workflow身份是关联值，不成为正式回执的删除依赖。

```sql
create table model_invocations (
  id uuid primary key,
  logical_operation_id text not null,
  workflow_id text,
  physical_ordinal integer not null,
  step_no integer, batch_no integer, attempt_no integer not null,
  status text not null check(status in ('prepared','dispatched','completed','not_sent','unknown')),
  role_id text not null, model_kind text not null,
  config_snapshot jsonb not null,
  resource_id text not null, resource_revision integer not null,
  prompt_snapshot jsonb,
  actual_provider text not null, actual_model_id text not null,
  native_identity jsonb,
  inference jsonb not null, input_sources jsonb not null,
  budget_snapshot jsonb not null,
  semantic_input_ref jsonb, provider_request_ref jsonb, output_ref jsonb,
  observed_capture jsonb, formed_capture jsonb,
  token_estimate jsonb, usage jsonb, raw_usage jsonb,
  warnings jsonb not null default '[]', provider_metadata jsonb,
  provider_request_id text, actual_cost jsonb,
  recorded_at timestamptz(6) not null,

```

多个并行批次在调用范围内分配确定序号，重放使用相同计划与快照。计费预留与ModelInvocation接纳在同一owner事务完成；观察/形成捕获的锁与事务次序遵守时间owner。workflow清理后长期调用、幂等和费用事实仍可查询，见[存储事务](存储事务与缓存.md)。

公共时间采用共同 `TimePoint {domainId,at}`，at 为 UTC ISO、最多微秒精度。recorded/provider request 时间属于真实时域；业务的发生、有效、观察时间仍由领域传入，模型层不计算世界映射。原生 session/run/entry/call 使用 OriginIdentity；产品 Ref 指向实际保存的调用/Material/Artifact，不能为原生字符串伪造产品安装与对象身份。

### 5.1 用量含义

- V4 原始 LanguageModel usage 使用 `inputTokens.total/noCache/cacheRead/cacheWrite` 与 `outputTokens.total/text/reasoning`。高层 LanguageModelUsage 使用数值 inputTokens/outputTokens 和 details；两种形状按其接口读取。
- generateText.usage 是最后一步，totalUsage 是全部步骤合计。物理 ledger 按每步记，合计只作为派生值。
- embed 提供 usage.tokens；rerank、speech、transcription 的高层结果没有统一语言 token usage，按 Provider 原始数据与实际价目计算。
- 估计注明方法和单位：对应 tokenizer、保守字节上界、图像/音频/视频估计分别记录。字节估计不冒充实测 token。未知 usage/价格保持未知；声明金额上限的策略需要足够预留或明确的每次金额界限。

额度由安装、Subject、Role、根Task/显式工作预算共同约束。限制保存在 settings/领域 Task；模型 owner 只保存实际用量、价目修订与本次预留。根Task覆盖主/子调用及明确续行，子 run 保留自己的 OriginIdentity；不得为绕过额度新建预算归属。

```ts
interface ModelBudget {
  maxCalls?:number;maxTokens?:number;
  totalAmount?:Money|null;dailyAmount?:Money|null;perCallAmount?:Money|null;
  window?:{kind:'rolling';durationMs:number};
}
interface NormalizedUsage {
  inputTokens?:number;outputTokens?:number;
  cacheReadTokens?:number;cacheWriteTokens?:number;
  reasoningTokens?:number;
  units?:UsageQuantity[]; // 共同unit/quantity/source，按真实计费单位保留
}
```

调用数/Token 的上限为正整数，Money 使用共同 `{amount:decimalString,currency:ISO4217}`，金额用 decimal.js 计算并在 PostgreSQL numeric 保存。maxTokens 是总输入＋输出；cache 分项用于价格且不再重复增加 total 输入。窗口按现实时间计算，dailyAmount 按已配置账期时区的现实日（默认UTC）；World 变速不扩大额度。默认没有明示金额上限，仍受授权范围与已配置并发/调用/任务上界；未知价格不当0。不同币种分别记账，不自动相加或换汇。

null 表示该层未设置金额界限；上层授权/预算上限仍成立。删除本层覆盖恢复上层值，不能以null清除父范围限制。价格资源只由明确的配置/真实Provider事实取得；管理读取不自动查价或发付费测试。

同产品根Task预算由work owner通过注入的budgetScopes私有函数参与同一事务，模型库不读Task表。跨产品使用根Task owner的子额度回执：Hept先按稳定childOperationId预留，Nous只消费已受信验证的allocation，实际Provider费用仍只由执行产品的ModelInvocation记录。没有跨库共享锁、通用预算服务或第二份可写余额。

```ts
interface BudgetAllocationUse { allocationRef:Ref;childOperationId:string }
interface BudgetAllocationSnapshot {
  allocationRef:Ref;childOperationId:string;receiptDigest:string;
  taskRef:Ref;budgetOwnerRef:Ref;
  issuer:{product:'hept';installationId:string;authorityRef:string};
  target:{product:'nous'|'hept';installationId:string;
    subjectId:SubjectId;consumer:Consumer};
  limits:{totalAmount:Money;perCallAmount?:Money;maxCalls?:number;maxTokens?:number};
  expiresAt:TimePoint; // real域
}
```

allocation专用limits必含非负、明确币种的totalAmount，不接受空对象、null金额或无币种授权。call/token/perCallAmount只能附加收紧；根Task的daily/window等限制由Hept预留该子额度时先执行。

TextRequest、各非文本调用及NativeInvocationPrepare可携带BudgetAllocationUse定位请求；它不是自授额度。产品budgetScopes适配通过正式Hept Client取得当前work owner回执，检查来源、Subject/Consumer、父Task、目标安装、childOperationId、期限和当前授权，返回上述已受信snapshot给通用模型机械。快照随ModelInvocation保存，实际admission在本地锁住该allocation的已用＋预留并与本地限制求交。

共享库只依赖纯snapshot形状和产品注入的verify/current/settle回调；正式Hept Client仅由Nous组合根适配，不让platform/models导入Hept业务包或表。settle回调提交固定用量/费用与原调用Ref，其结果由原业务workflow接纳；跨库响应丢失按同一子操作继续，不创建通用预算轮询器。

Hept正式操作为tasks.budgets.allocate/read/settle：`POST S/tasks/{taskId}/budget-allocations`、`GET S/tasks/{taskId}/budget-allocations/{id}`、`POST S/tasks/{taskId}/budget-allocations/{id}/settlements`。S为`/v1/subjects/{subjectId}`。Nous组合根只调用这套owner接口，不另立allocation公共服务。

顺序为Hept预留子额度→Nous验证并接纳稳定子操作→各实际模型调用按allocation锁检查/预留→保存真实输出/用量→按原allocation向Hept结算。响应丢失读取/继续同一个childOperationId；unknown保留两边原预留，Hept在pending/unknown期间不重分这笔额度。Hept根预算显示本地用量＋未结子额度＋已结实际汇总，汇总引用Nous正式结算事实，不再记第二笔Provider费用。币种不匹配或无法核实回执时停止付费派发；无Hept根Task的独立Nous调用继续使用自身预算。

导出/恢复/分叉保留旧allocation的issuer、target、Consumer、期限和原结算作历史；RefMap不得把这份授权改成新安装/新主体/新Consumer的执行许可。恢复未决结果沿原身份核实，新执行由真实Task owner重新授权并取得新的allocation。

为每个当前预算 scope 建立可锁记录，在时间捕获所需Clock锁之后按安装→Subject→Role→根Task固定顺序锁定；同一短事务重新读取限制、求已用＋未结预留、检查并创建本次预留与prepared调用。预留可用独立表 `model_budget_reservations(invocation_id,scope_id,reserved_calls,reserved_tokens,reserved_amount,currency,pricing_revision)`，FK指model_invocations；限制和status不在此重复保存。聚合从实际调用/预留得出，不维持第二套可变余额权威。

已知完成按真实 usage/价目结算，not_sent 释放；unknown 保留最大预留并显示待核实金额。设金额限制时，缺对应币种价格且无显式 perCallAmount 界限则拒绝派发；perCallAmount 是管理员允许的费用预留上界，其来源进入快照。实际费用超过预留仍如实记录，阻止后续超额调用，不能篡改账目使其看似符合限制。

### 5.2 失败与恢复

| 已知事实 | 正式结果及下一动作 |
| --- | --- |
| 配置/能力/权限/预算在派发前拒绝 | 未派发；释放本次预留，返回具体不可用项，不生成实际接触 |
| 执行边界明确确认 Provider 未接收 | not_sent；保留拒绝证据，按配置选择备用资源或等待配置修正 |
| 派发后网络中断且无完整响应 | unknown；保留预留、原调用身份与核实入口，停止对同一效果的自动重发 |
| Provider 完成，随后 schema 解析或业务采用失败 | 模型调用 completed；保存实际输出、费用与采用失败，继续处理原结果 |
| Provider 输出已保存，后续认知/账目接纳失败 | DBOS 恢复先采用保存结果和同一调用身份，不再次派发 |
| 流被取消 | 依据实际 Provider 事实区分已完成、确认未提交和 unknown；用户取消意图与外部结果分别保存 |

未知调用的管理核实保留证据、操作者和修订；人工判断明确标其来源，不伪装成 Provider 原始回执。实际模型事实、费用和领域采用结果可分别查询。

### 5.3 Provider 错误的保存边界

SDK APICallError 的 `requestBodyValues/responseBody/message/cause/data` 都可能含正文或秘密。实际 doX 错误出口位于 durableCalls **内层**：先从 SDK Error 提取 statusCode、isRetryable、允许的 request ID/响应头和安全 URL，再保存安全异常给 SDK/DBOS。普通 Pino 日志与公开 Problem 只接收安全字段。

```ts
if (APICallError.isInstance(error)) {
  const diagnosticRef = await diagnostics.captureRestricted(error, ctx); // 按策略可不留 raw
  throw new APICallError({
    message:safeProviderMessage(error.statusCode),
    url:safeOriginAndPath(error.url),
    requestBodyValues:undefined,
    statusCode:error.statusCode, isRetryable:error.isRetryable,
    responseHeaders:allowedResponseHeaders(error.responseHeaders),
    data:diagnosticRef ? {diagnosticRef} : undefined,
  });
}
```

不保留原 responseBody/raw cause/错误自由文本；其他错误同样按类型转安全异常。保留官方 APICallError 身份与 retry 分类供 SDK 使用，避免改成普通 Error 破坏其判定；恢复后的公开错误按已验证 Problem 字段解释，不依赖 instanceof。SDK 的默认自动重试仍为0，业务重试遵守实际效果规则。

流式doStream可能成功返回后再由error part或reader.read()拒绝报失败。同一Provider边界用标准ReadableStream/getReader薄guard：pull时捕获read拒绝并转安全异常，error part同样替换；cancel/Abort收尾错误也先安全化，再交SDK/durable消费。只加TransformStream.transform不能拦截源read rejection。保留原背压、取消与结束语义，不缓冲整条流，不只catch建流Promise。tool execute异常同样在实际工具owner出口形成安全结果，原始工具正文进入受限材料。

受限 raw 先去除秘密再进 data Artifact，普通日志只引用其 ID。捕获失败时仍返回安全的原失败分类，并附诊断未保存状态。DBOS5.3 会枚举序列化原 Error 字段并递归 cause/AggregateError，不能等进入 checkpoint 后再做日志 redact。checkpoint 的私密访问、保留与删除和 Artifact 一同纳入诊断/数据管理；已保存的原件仅在授权下读取。

## 6. 管理入口

公开安装管理：Provider 来源/资源 CRUD、启停、测试连接、模型能力与价格、角色目录、有效设置、调用列表与调用详情。主体设置与角色参数沿 settings 写入来源；模型资源 API 复用同一资源修订机械，不另存一份可修改镜像。

正式路由为Provider CRUD `/v1/model-providers`、模型资源`/v1/models`、职责`/v1/roles`、调用`/v1/model-invocations`，详情/历史按稳定ID读取。实际生成是领域方法，管理测试是显式models.test并经过同一预算。API/CLI/Web显示实际采用模型、Prompt/配置版本、原输入、结果、warning、用量、费用和恢复条件；secret只显示引用与可用状态。

`GET /v1/costs`调用costs.read按实际调用owner汇总，返回按币种分组的费用/预留/未知与来源Ref。查询不重新计费或重写ModelInvocation，跨产品费用用原allocation结算关联去重。

模型离线或未配置时，资源编辑、Prompt 预览、历史读取、日志与其他独立功能继续可用。
