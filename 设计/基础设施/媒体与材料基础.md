# 媒体与材料基础

本规范保全原有完整消息、媒体、来源与实际消费能力，使用[共同值与调用上下文](共同值与调用上下文.md)和[时间与调度](时间与调度.md)。源码与隔离实验见[Hept 时间生活与消息研究](../../研究/Hept时间生活与消息.md)。各 owner、SDK 与执行边界沿[整体架构与模块合同](../整体架构与模块合同.md)。

## 1. owner 与实际复用

| owner | 持有的正式内容 | 不混入的状态 |
|---|---|---|
| OpenClaw OneBot 插件 | 平台连接、账号、原生接收/发送/历史/媒体 API、真实物理调用及原生回执 | Subject 是否阅读、认知形成、Hept 生活决定 |
| Hept communication | Message、修订、会话、平台事件、回复/转发引用、通知和历史覆盖 | 模型对图像的理解、后台 worker 私有推理 |
| 产品 Blob owner | Blob 元数据、持有者引用、内容字节保留/清除 | 单独授予字节读权限、主体经历 |
| Hept Media owner | 消息区域与原媒体的关系、协议取得状态、保全版本、当前来源许可 | 已经读过或已经理解的事实 |
| Nous Material/Source | 正式材料、区域/表示、来源谱系、Consumer 私有范围、传播许可、五轴 | 通信平台连接与重发队列 |
| 表示派生 owner | 文档解析、转录、OCR/视觉、帧/音轨等实际成果及版本、费用与来源 | 替换原件、覆盖原形成时间 |
| 实际执行/Encounter owner | 本次真正消费的固定表示与区域、执行 consumer、观察点和完成事实 | 收件、保全、预览、ready 自动视为 Subject Experience |

Blob 的字节机制直接使用成熟 `cacache` stream/content APIs；解析使用已有 Readability、文档解析库、sharp、FFmpeg/ffprobe 等成熟能力。模型派生通过正式 `@nous-wave/platform/models` 执行和预算入口。各产品拥有自己的 Blob/Material/Media 实例与目录，通过官方 SDK 传递对象；共享普通库不成为第三个资料服务。

## 2. 引用、来源身份与区域

产品对象使用正式 `Ref`，读后固定 revision。平台 ID、URL、native session/entry 均使用 `OriginIdentity`，不伪造产品 Ref：

```ts
interface MessageOrigin {
  type:'platform'; adapterId:string; accountId:string;
  conversationId:string; messageId:string; nodePath?:string[];
}
interface SourcePortion {
  ref:Ref;                    // 已绑定实际 revision/selector
  coverage:Coverage;
}
type Coverage = {
  status:'complete'|'partial'|'unknown';
  basis:'original'|'expanded'|'sampled'|'derived'|'platform_window';
  selected:Selector[];
  omitted?:{selector?:Selector;reason:string}[];
  continuation?:string;
};
```

Selector 沿共同定义：text 用 Unicode code point 半开区间；page 从 1 开始；image 是归一化矩形；media 用 `startUs/endUs` 十进制微秒；node 用 RFC 6901 `pointer`；part 用稳定 partId。`within` 表示父区域。owner 负责校验父子区域、端点与实际修订存在性。

例如对某个转发节点内视频取前 5 秒：

```ts
{ product:'hept', installationId, subjectId, kind:'Forward', id:forwardId,
  revision:3, selector:{kind:'media',startUs:'0',endUs:'5000000',
    within:{kind:'part',partId:'video-0',
      within:{kind:'node',pointer:'/nodes/2/children/0'}}}}
```

该 ref 的 owning read 操作是 `messages.references.read`。pointer 指向这一修订的实际节点，不是临时展开数组的序号。变化、追加或移动后的表示具有新 revision；执行输入和形成来源始终保留原固定引用。

## 3. 完整消息与修订

```ts
type MessagePart = {partId:string;nativePointer?:string} & (
  | {kind:'text';text:string}
  | {kind:'mention';accountId:string;displayName?:string;all?:boolean}
  | {kind:'reply';origin:OriginIdentity;messageRef?:Ref;
      state:'pending'|'resolved'|'unavailable'}
  | {kind:'image'|'sticker'|'audio'|'video'|'file';mediaRef:Ref;
      nativeType:string;name?:string;declaredMediaType?:string}
  | {kind:'face';nativeId:string;metadata:Record<string,unknown>}
  | {kind:'forward';referenceRef:Ref}
  | {kind:'card'|'link'|'location';data:Record<string,unknown>;rawRef?:Ref}
  | {kind:'unknown';nativeType:string;rawRef:Ref}
);
interface MessageRevision {
  ref:Ref; origin:OriginIdentity; direction:'inbound'|'outbound';
  authorRef?:Ref; authorSnapshot:Record<string,unknown>;
  platformSentAt?:TimePoint; receivedAt:TimePoint;
  parts:MessagePart[]; rawRef:Ref; policy:Policy;
  lifecycle:'present'|'edited'|'retracted'; previousRevisionRef?:Ref;
}
```

未知段仍占据原顺序并保留原件；文字里的 CQ 样式保持普通文字。昵称、卡片名和作者自报都保留来源，不据此合并真实人物。原件不因解析成功而删除。

Message/Forward/Media/Representation 的 *Ref 均为共同产品 Ref；平台 ID 与协议 file code 只放 OriginIdentity/原始来源，秘密引用仍使用 credentials 专用 SecretRef。MessageRef 的固定修订保存原始 parts、来源和原当时政策；现行撤回及传播限制另由当前 head 检查。媒体取得和转发展开是独立正式对象的修订，不为它们的进度重写原消息正文。读取返回原消息修订及本次实际绑定的 Media/Forward 修订。

原生消息稳定身份为 `(adapterId,accountId,conversationId,messageId)`。实时流与补拉走同一 accept；相同身份同事实返回原 Message，同身份的编辑/撤回走 message-change；异内容无对应事件依据时返回 conflict。平台事件可先于原消息到达，后续 accept 继承已记录的 lifecycle。

## 4. 转发与引用

复制旧 Hept `parser.ts/lossless.ts/source.ts/forward.ts/history.ts/history-sync.ts` 后修改其导入和 API client，保留完整节点的：`pointer,parentPointer,claimedAuthor,platformSentAt,parts,origin,rawRef`。外部 API 原响应及内嵌 JSON 各保存原件，摘要独立派生。

展开仍使用原有有界算法：inline nodes、内嵌 JSON 与真实 `get_forward_msg` 返回均进入同一个 node parser；QQContextBot 的 URL+HTML 内嵌解码作为原函数改编加入。保留原作者、原发送点、回复和媒体段，不把子节点 flatten 成无 parent 的标签文本。

`messages.references.expand` 输入固定 referenceRef 与 continuation；结果返回新 fixed Ref、Coverage 和未展开原因。每步控制 depth/nodes/bytes/API requests，保存待继续的来源位置和已取得节点。continuation 是 owner 的不透明数据，不能授予更大的范围。碰到 cycle、缺失、已过期或平台不支持时保留原件和明确 coverage，不生成替代正文。

回复引用解析通过原生 `get_msg` 接纳其真实返回，再绑定 canonical MessageRef；未取得原文时不宣称已经读到被回复消息。历史补拉保留真实平台覆盖、cursor、原响应及缺口；时间过去、数组为空或命中已有 cursor 都不能独自建立“完整历史”。

## 5. Blob、Media 与表示

### 5.1 字节保全

`blobs.putStream` 输入 Readable/SDK upload stream，返回 `{ref,digest,bytes,detectedMediaType}`。服务端边流边校验真实字节数、hash 和限额，通过 mature store 保存；Content-Length 只作预检。格式检测与声明类型分别保留。失败临时字节由 store 清理，不返回 available。

BlobRef 本身不授予读取权。`blobs.readStream` 必须同时指定实际 holderRef，验证该 holder 在当前 Consumer/purpose/audience 中可读，并确实持有这个 Blob/区域。某个其他会话持有相同字节不扩大本会话权限，物理去重也不合并不同来源或实际接触。

### 5.2 Media 取得

```ts
interface MediaRevision {
  ref:Ref; sourceRef:Ref; origin:OriginIdentity;
  state:'pending'|'acquiring'|'available'|'unavailable'|'expired'|'too_large';
  blobRef?:Ref; digest?:string; bytes?:string;
  declaredMediaType?:string; detectedMediaType?:string;
  failure?:{code:string;retry:'after_change'|'after_delay'|'none'};
  policy:Policy; recordedAt:TimePoint; // 保留现实域
}
```

sourceRef 指向真实 Message/Forward 区域。协议下载 URL、临时文件和 NapCat file code 保存在受保护来源，不能成为产品 BlobId。使用原 `media.ts/resources.ts` 的协议确认、群文件元数据、专用 export roots 和实际流保存路径；文件路径来自已验证平台来源或受限 staging，不采纳模型任意本机路径。

收件后尽早保全易过期的媒体，与主体是否阅读分开。网络失败重试同一取得操作和原来源；expired/unsupported 没有伪成功。更新采用 expectedRevision，迟到的旧取得结果不覆盖较新的源修订或撤回。

### 5.3 原件、派生与实际模型输入

```ts
interface Representation {
  ref:Ref; inputRefs:Ref[]; blobRef?:Ref; text?:string;
  kind:'parsed_document'|'transcript'|'ocr'|'visual_description'
      |'video_frames'|'audio_track'|'summary'|'region';
  producer:{resourceRef?:Ref;modelId?:string;promptRef?:Ref;
            parametersDigest:string;implementationVersion:string};
  formed:TimeCaptureReceipt;
  coverage:Coverage;
  policy:Policy;
}
```

解析、OCR、ASR、视觉描述、音轨、帧序列和摘要各有实际 producer 与形成回执；原件继续保存。复用 key 包含输入固定区域 digest、producer/model/prompt/参数及表示格式版本。新模型结果不覆盖旧表示。

GIF 保留原始动画、帧序与时间；视觉模型只看到采样帧时，coverage 为 sampled，不能据此宣称看过完整动作。视频区域用 startUs/endUs，帧、音轨、字幕和原视频分别寻址；同一页的 OCR 与页面图像也分别记录。文档先用成熟解析库；真正视觉/ASR 通过正式模型/资源入口，费用、token、trace 和能力检查齐全。

直接多模态输入与文本派生可按实际 Model capability 选择。媒体指针、`[图片]` 标签、下载成功都不证明模型取得其内容。模型执行 owner 保存最后实际传给 provider 的 selected input portions；token/正文预算不足时返回完整单元的 omitted/continuation，不静默截断后标完整。

Hept 独立运行也可通过已配置原生 worker/模型资源取得媒体表示，其 Media owner 保存正式结果。接入 Nous 时，使用 Client 上传原字节及选定表示，Material.source.inputs 连接精确 Hept 来源；不把派生表示再次声明为没有依赖的新根。

## 6. 实际消费、私有结果与来源权限

Nous Material 由可信 ctx.consumer 确定私有范围。worker/author 的中间原件和草稿留在对应 Consumer；Subject 不因同一 SubjectId 而自动读到它们。原生任务完成只产生 ready 通知；可信 worker 宿主通过 `materials.publish` 选定已保存区域，主体显式阅读 publishedRef，仍继承原来源传播限制。selected 发布不带回原大 Blob 的全量读取权。

prepare/read 返回内容目录和本次可以取得的区域；query.prepare 为独立纯预览，query.run/expand 使用原 run 的纯 clock.read 时间视图。材料目录、query 结果与准备操作不取得 TimeCaptureReceipt。真正 provider 派发和成功/可用部分结果由现有执行 owner 保存，Encounter 再记录实际消费的 fixed portions、consumer、正式 TimeCaptureReceipt 和 invocation。观察与形成分别由真实 owner 在需要持久记录的业务点取 clock.capture/captureIn，以 `parent/stepN/observed`、`parent/stepN/formed` 等稳定阶段身份幂等；receipt 中 clockRef/segmentRef/captureRef 均为共同 Ref，原资料的发生点和平台原时间继续保存。原有准备阶段提前写 Experience 的流程删除。模型返回格式验证失败仍可能有真实输入消费和费用，按执行事实记录，不能把它重写成未发出。

政策按实际源递归求交：holder/表示自身限制、每个 input 的当前传播限制、当前授权与 Consumer 范围都适用。`sources.policies` 对外只查当前政策和 availability，不复制另一份可自行修改的权限。Hept 的消息/媒体源由 Hept owner 提供当前政策；Nous 通过绑定 authority 的正式 Client 批量查询，不能只依赖 capture 时快照。

权限与内容状态分开：撤回后未阅读主体不取得原正文；已经有的实际接触记录可继续证明曾接触，其后能否再取原文、对外传播由当前政策决定。删除源内容后 descendants 的正文、检索和再次派发按来源关闭；系统管理的受控审计读取不成为主体经历。

## 7. 原生通信与物理回执

### 7.1 收件交接

OneBot `gateway.ts` 在 `JSON.parse`/聚合前取得 raw；迁入 `parseOneBotJson` 保留数字词元，将 OriginIdentity 单独归一。经宿主实际账号和会话范围检查后，使用原生 SDK ingress queue/drain 持久保留 raw/receivedAt。drain 调官方 Hept Client 的 messages.accept，获得已持久接纳的回执后才完成原生 queue item。失败沿同一个 ingress identity 继续，实时和补拉最终到同一 accept。

聚合属于接纳后的注意优化，不删除每条消息事实。Hept 的 DBOS workflow 负责保全派生、通知和 Reactor；插件不再使用自己的 timer 启动第二条主观回复链。普通消息、notice 和原生管理命令分别路由，聊天内容不取得 System 管理权。

### 7.2 出站交接

Hept 保存已采用 Expression、受众和来源，形成固定 native send intent。通过 SDK `sendDurableMessageBatch/withDurableMessageSendContext` 交给同一 OneBot adapter，保留其发送、staging 和原生恢复机制；不另写 OneBot HTTP 发送客户端。

插件在 `callApi` 每一次真正变更请求前后取得：

```ts
interface PhysicalReceipt {
  receiptRef:Ref;
  expressionRef:Ref;
  expressionPartRefs:Ref[];
  physicalCallId:string;
  action:string;
  target:{adapterId:string;accountId:string;conversationId:string};
  origin?:OriginIdentity; // 仅有真实平台消息或原生来源身份时填写
  attemptedRealAt:TimePoint;
  attemptedSemanticTime?:TimeCaptureReceipt;
  status:'accepted'|'not_sent'|'unknown';
  platformMessageId?:string;
  nativeAckRef?:Ref;
  failure?:{code:string;definite:boolean};
}
```

一个表达段可能分成多个真实调用，一个平台调用也可能含多个表达段。每次原生结果在开始下一次 fallible 步骤前，通过 SDK `onDeliveryResult`/原生回执 owner 保存，再由 Hept 按稳定 receipt identity 采用为交往/效果事实。Hept 不另维护一个可自行重发的 sender。后续消息索引、认知反思或产品回传失败，只补原回执的交接。

异步 staging/权限查询完成后，沿 SDK `onPlatformSendDispatch` 重新检查当前委派、来源、目标、取消与预算；紧邻 I/O 调 `assertDirectAdapterHandoff` 检查同一宿主授权仍有效。结果确定前不能用新的发送身份替代旧操作。accepted 表示平台确认接纳，对方是否已读由独立平台阅读事实表达；not_sent 必须有明确未发生依据；网络 timeout/丢响应保留 unknown，沿原 ID 只读 reconcile 或显式人工处理。

OneBot 的 upload_group_file/upload_private_file 可成功而没有 message_id。必须保留原 action、真实 ack 和可用的 file/resource identity，platformMessageId 可以缺失；target 保存实际渠道目标，origin 仅在确有符合共同合同的消息/原生来源时填写，不以目标和 action 伪造 Message Origin。删除插件当前 Date.now 伪 ID。已核实 SDK 的实际闭包：`src/infra/outbound/deliver-results.ts::observeDeliveryResult` 当前只接纳可解析 message ID 的结果；无 ID 会成为 adapter_returned_no_identity。按实际 owner 改编如下：

- 在原结果类型增补确认接受的 operation acknowledgement，包含 `action,physicalCallId,acknowledgement`；平台 ID 改可选。物理 attempt identity 参与去重，平台 messageId 仍只保存真实值。
- `receipt.ts` 保留无 messageId 的 accepted operation part；`platformMessageIds` 数组只含真实消息 ID。不要只加一个 meta 字段而让 result observer 继续丢弃它。
- `deliver-queue-execute.ts` 的 onDeliveryResult 当前只把结果放入内存 deliveredResults；`deliver-queue-state.ts::persistQueuedPostSendState` 只调用 markDeliveryPlatformOutcomeUnknown，没有保存 action/ack/result。原 marker 只表达派发后的未知边界。
- 在既有 `delivery-queue-storage` 的 canonical entry、worker 更新及 retained receipt 路径扩充逐 physicalCallId 证据：实际 action、accepted operation acknowledgement、对应表达片和真实平台/资源 ID。仍使用同一个原生交付记录与存储，callback 先持久保存 accepted call，再回传 Hept 和继续下个可失败步骤；不新增 native 表外重试引擎。
- 同 batch 一个 call accepted 时只关闭该 piece。batch completion/ack 必须覆盖其余实际 call 的状态；不能以首个 ack 提前完成整批。恢复按这些已保存 call 证据跳过确认片段，剩余 unknown 先核实原操作。
- `delivery-completion.ts` 允许 undefined 平台 ID 的完成事实；读取平台 ID 的 helper 改可选。recovery 中仅依赖平台 ID 判断完成的分支也识别已保存 acceptance，确认 ack 不重发，无 ack 仍为 unknown。

原生记录写入失败或进程在 dispatch 后、accepted 证据提交前退出时，保留 unknown 并核实原操作，不能根据曾进入内存结果数组判为已持久。

这套修改同步现有调用方及计数/归一用例。未经 owner 修正前，accepted upload 只解释为已确认的文件操作，不能宣称为普通消息已发送，也不能因外层无 ID 异常重传已确认的操作。

物理执行进度由原生 sender 持有；Hept 记录真实平台后果与表达关系。unknown 的解决回到原生原操作，回传后再更新产品事实，不能只改 Hept 状态而让原生 recovery 仍认为可重发。

## 8. SQL 与公开操作

概念表按各 owner 分开，均在所属产品库中；对象修订引用共同 Ref，原生身份保存在 origin 字段。

```sql
message_origins(adapter_id,account_id,conversation_id,native_message_id,
                message_id, UNIQUE(adapter_id,account_id,conversation_id,native_message_id));
messages(message_id uuid PRIMARY KEY,subject_id uuid,current_revision bigint,lifecycle text);
message_revisions(message_id uuid,revision bigint,origin jsonb,parts jsonb,raw_ref jsonb,
                  author_snapshot jsonb,platform_sent_at timestamptz(6),received_at timestamptz(6),
                  policy jsonb,PRIMARY KEY(message_id,revision));
message_events(event_id uuid PRIMARY KEY,origin_event_key text UNIQUE,
               target_origin jsonb,kind text,payload_ref jsonb,recorded_at timestamptz(6));
message_references(reference_id uuid PRIMARY KEY,message_ref jsonb,current_revision bigint);
reference_revisions(reference_id uuid,revision bigint,nodes jsonb,coverage jsonb,
                    continuation jsonb,PRIMARY KEY(reference_id,revision));
media_assets(media_id uuid PRIMARY KEY,subject_id uuid,source_ref jsonb,current_revision bigint);
media_revisions(media_id uuid,revision bigint,state text,blob_ref jsonb,origin jsonb,
                failure jsonb,policy jsonb,PRIMARY KEY(media_id,revision));
blob_objects(blob_id uuid PRIMARY KEY,digest text UNIQUE,bytes bigint,detected_media_type text,
             state text,recorded_at timestamptz(6));
blob_holders(blob_id uuid,holder_ref jsonb,PRIMARY KEY(blob_id,holder_ref));
representations(representation_id uuid PRIMARY KEY,subject_id uuid,current_revision bigint);
representation_revisions(representation_id uuid,revision bigint,input_refs jsonb,
                         producer jsonb,body jsonb,formed_capture_ref jsonb,coverage jsonb,
                         policy jsonb,PRIMARY KEY(representation_id,revision));
```

Blob 字节在 mature store，SQL 保存实际对象/持有关系。representation 表属于采用该派生结果的产品 owner，不在共享库维护一份跨产品总表。Message/Media/Material 的规范化索引和 owner change cursor按真实查询需要建立；不把重试、claim 或 lease 塞进这些表。

| 操作 | 返回与规则 |
|---|---|
| `messages.accept/change/read/history` | 固定事实/修订、完整 parts、OriginIdentity、选定 Media/Forward refs、Coverage/nextCursor；同源幂等 |
| `messages.references.read/expand` | 当前或指定固定展开表示、有界 continuation，不改变原消息 |
| `media.preserve/read/retry` | 相同原来源取得、实际状态与 blob 元数据；可用性失败明确 |
| `blobs.putStream/readStream` | 真正字节流和完整性；read 指定实际 holder 与权限 |
| `materials.capture/read/publish` | 原件/区域/私有 Consumer 与精确来源；publish 选定真实结果 |
| `representations.derive/read` | 已保存的实际派生成果、producer、形成 capture 与覆盖 |
| `sources.read/policies` | 批量绑定当前可用性/许可或精确有界正文区域；返回 fixed refs |
| `encounters.accept` | 根据实际执行回执保存消费；不是普通聊天模型可自报的经历写入口 |
| `expressions.send/inspect/reconcile` | 同一原生 intent 的真实物理结果；unknown 不换新写请求 |

短事务保存事实与修订，长下载、转发展开、派生和交接由 DBOS workflow 分步执行；网络不在数据库事务里。源码迁入时删除旧回放表/队列机械，使用 datasource checkpoint；来源修订和 coverage 是保留的领域事实。

## 9. 限额、故障与清除

默认限额作为 settings 稀疏覆盖与 schema 元数据发布：raw 单批 8 MiB；media 每对象 64 MiB、每日保全 1 GiB、取得并发 4；forward 每步 depth 8/nodes 256/bytes 2 MiB/requests 16，累计 nodes 4096；read 默认最多 64 消息与 1 MiB 正文；sources.policies 每批最多 200 引用。具体模型/媒体资源还施加自己的真实输入、输出、费用与执行限制。超出不截断原件，保存可续位置或明确 unavailable。

下载断点与完整性由所选 HTTP/Blob 成熟机制承担；不能确认 partial 文件完整时保留 temporary，重取也不重复形成 Subject 接触。派生已保存但采用/回传失败时复用原成果、producer 与 formed；模型结果未知停在原 operation，不自动再付费。

出站媒体若需要 URL，使用受限下载 ticket 或已授权原生本地 staging。ticket 只允许指定 holder/selector/表达目标，短效（默认 120 秒）、日志脱敏；取字节时再次核验当前政策与 source availability。URL 或文件路径不进入主体可执行命令。

撤权先关闭新读取、检索和派发，再按实际持有关系清除。物理 Blob 仅在最后合法持有/保留义务结束后删除；删除某条来源不能因内容 hash 复用而删除其他来源合法字节。原生 ingress/send checkpoints、临时媒体、派生/向量、主体导出、独立备份和外部平台各有实际清除范围。通过各自正式 owner/API 清除，未确认范围返回 pending；平台已发生效果保留其事实，不能通过删本地记录假装未发生。
