# 数据生命周期、备份恢复与软件发行

## 三种不同对象

| 对象 | 用途 | 包含和恢复的权威 |
|---|---|---|
| Subject Bundle | 搬迁、分享、研究分支或同一主体恢复 | 所选Subject的正式领域闭包、合法来源/原件、相关覆盖/资源及已发生效果 |
| Installation Backup | 整个安装故障恢复、机器迁移 | 产品数据库、官方DBOS状态、Blob、配置/Prompt、native state及受保护安装资料 |
| Software Release | 安装或更新程序 | 编译JS/声明、前端、普通SDK、迁移、默认资源、原生包及许可证；不含主体运行数据 |

Subject包不是整库dump；安装备份不是软件发行；软件更新不覆盖主体内容。Nous与Hept各自有完整数据操作，联合协调只调用其正式owner，不能跨读另一产品表或native私有SQLite。

## 采用的机制与实现位置

产品 `data/` owner组织自己的导出、导入、分支、清除、备份和更新入口，通用流/归档/校验及进程适配置于 `@nous-wave/platform/data`。PostgreSQL18 `pg_dump/pg_restore`提供一致数据库快照；成熟tar/zip流库负责打包和安全提取；Restic可选承担安装备份的加密、去重、保留与远端存储。普通Blob沿正式内容地址库读取，不重写备份引擎。

OpenClaw整state备份/恢复直接复用其backup owner，单Subject能力在其实际session/backup owner补窄scope入口，详见下文。每个领域owner提供真实数据与生命周期操作，管理层不枚举其私表拼导出。

```ts
interface OwnerExport {
  owner:string;
  schemaVersion:number;
  cut:OwnerCut;
  records:ArtifactRef[];
  blobs:BlobExportEntry[];
  dependencies:Ref[];
}
interface DataOwner {
  prepareExport(ctx,selection):Promise<OwnerExport>;
  inspectSelection(ctx,selectionRef):Promise<OwnerCut>;
  validateImport(ctx,manifest):Promise<ImportValidation>;
  import(ctx,prepared,refMap,transaction):Promise<OwnerImportResult>;
  planPurge(ctx,selection):Promise<PurgeSelection>;
  purge(ctx,prepared):Promise<PurgeReceipt>;
}
```

这些是静态组合所需的实际参与操作，普通函数即可；不创建新的插件运行、步骤/租约/重试平台。JSONL、文件流、读写事务由成熟依赖完成，进度由DBOS持有。

DataArtifact/ImportArtifact是本产品Data owner的正式归档资料，使用共同Ref；它们的字节仍由Blob owner持有。公开metadata保留`ref,blobRef,mediaType,digest,bytes,createdAt,expiresAt?,policy,consumer?,sourceRefs`。`data.artifacts.read/readStream`读取metadata/标准字节流，均核验当前数据授权和源限制；知道digest或下载路径不授予权限。`data.selections.read`经静态DataOwner表调用实际owner的inspectSelection，只返回cut/闭包摘要，成员按其owner批量接口取，不暴露SQL。

正式表位于产品迁移，通用归档库不保存第二份业务状态：

```sql
CREATE TABLE data_artifacts (
  artifact_id uuid PRIMARY KEY, kind text NOT NULL,
  subject_id uuid, blob_ref jsonb NOT NULL,
  media_type text NOT NULL, digest text NOT NULL, bytes bigint NOT NULL CHECK(bytes>=0),
  policy jsonb NOT NULL, consumer jsonb, source_refs jsonb NOT NULL,
  created_at timestamptz(6) NOT NULL, expires_at timestamptz(6)
);
CREATE TABLE data_manifests (
  artifact_id uuid PRIMARY KEY REFERENCES data_artifacts(artifact_id),
  format text NOT NULL, format_version integer NOT NULL, manifest jsonb NOT NULL
);
CREATE TABLE data_import_plans (
  plan_id uuid PRIMARY KEY, artifact_id uuid NOT NULL REFERENCES data_artifacts(artifact_id),
  manifest_digest text NOT NULL, target_mode text NOT NULL,
  owner_validations jsonb NOT NULL, expected_targets jsonb NOT NULL,
  required_bindings jsonb NOT NULL, pending jsonb NOT NULL, created_at timestamptz(6) NOT NULL
);
CREATE TABLE data_receipts (
  operation_id text PRIMARY KEY, actor_scope_digest text NOT NULL,
  operation_name text NOT NULL, request_digest text NOT NULL,
  result jsonb NOT NULL, recorded_at timestamptz(6) NOT NULL
);
```

selection成员/pin由实际领域owner保存到其私有表，与该owner cut在同事务封存；共享Data owner不跨查私表。计划是不可变验证结果，执行前仍重验当前授权/目标修订/源digest；改变输入创建新plan。data_receipts保存正式导入/清除/分支等结果和无正文PurgeReceipt，DBOS拥有进行中的执行状态。Artifact保留引用在同库事务采用，字节先落地；孤立字节和取消工作按既定Blob规则回收。

## Subject Bundle 格式

```ts
interface SubjectBundleManifest {
  format:'nous-hept-subject'; version:1;
  bundleId:string;
  mode:'restore'|'fork'|'share';
  subject:{id:string;name:string;branchedFrom?:Ref};
  sources:{product:'nous'|'hept';installationId:string;productVersion:string}[];
  createdAt:TimePoint; // real
  cuts:OwnerCut[];
  clockReceipts:Ref[];
  components:{owner:string;schemaVersion:number;path:string;digest:string;bytes:string}[];
  blobs:{path:string;digest:string;bytes:string;mediaType:string;holders:Ref[]}[];
  requiredBindings:BindingRequirement[];
  pending:PendingResource[];
  effects:EffectContinuationSummary[];
}
```

本文的 ArtifactRef 是共同 Ref 的类型别名，指真实不可变DataArtifact/Blob对象，不新增引用包装。主要成员结构为：

```ts
interface OwnerCut {
  owner:string;
  subjectId?:string;
  realRecordedCut:string;
  cursors:Record<string,string>;
  selectionRef:Ref;
  clockReceipts:Ref[];
}
interface BlobExportEntry {
  blobRef:Ref; digest:string; bytes:string; mediaType:string;
  holders:Ref[]; path:string;
}
interface BindingRequirement {
  id:string;
  kind:'secret'|'provider'|'channel_account'|'time_authority'|'native_runtime'|'resource';
  logicalName:string;
  sourceRef?:Ref;
  capabilities:string[];
  expectedIdentity?:{protocol?:string;accountId?:string;installationId?:string};
}
interface PendingResource { owner:string; ref?:Ref; reasonCode:string; operationId?:string }
interface EffectContinuationSummary {
  effectRef:Ref;
  state:'completed'|'not_sent'|'dispatched'|'unknown';
  nativeRefs:OriginIdentity[];
  receiptRefs:Ref[];
  continuation:'none'|'reconcile'|'explicit_resume';
}
interface ImportPlan {
  id:string; artifactRef:Ref; manifestDigest:string;
  targetMode:'restore'|'fork'|'share';
  ownerValidations:{owner:string;schemaVersion:number;compatible:boolean;problems:Problem[]}[];
  expectedTargets:{ref:Ref;expectedRevision?:number}[];
  requiredBindings:BindingRequirement[];
  pending:PendingResource[];
}
interface PurgeReceipt {
  id:string; selectionRef:Ref; recordedAt:TimePoint;
  cleared:{owner:string;count:string;bytes?:string}[];
  pending:PendingResource[];
}
```

ImportValidation/OwnerImportResult/PurgeSelection是该owner围绕上述plan、selectionRef与实际结果的内部类型；HTTP只传正式plan/引用和有界摘要。大量成员留在按owner的selection成员表/记录流，不把全部对象放一个API数组。

根目录含manifest、按owner分开的记录流和Blob对象；路径是包内逻辑路径。所有必须的schema版本、源关系、时间域/段/修订与必要参考内容在包内，不能靠某台开发机目录或历史聊天解释。

| 内容 | Subject Bundle规则 |
|---|---|
| 认知/来源/实际接触/修订 | 所选对象及必要闭包，保留五轴、稳定身份、形成/证据及当前Policy |
| World/Calendar/RealizedEvent/Life | 同一cut的定义、规则修订、例外、参与/覆盖、Clock与高水位/捕获回执 |
| Message/Media/Conversation/人物 | 完整原件和引用树、账号/会话稳定事实、生命周期、字节与派生；按导出授权过滤 |
| WorkContext/Active Cognition/Task | 原目标、进展/精确引用、native关联和待看结果；导入后均待显式恢复 |
| ModelInvocation/费用/预算 | 原调用、Provider/Model/Role/Prompt/价格版本、实际/未知usage与费用、预留/结算和BudgetAllocationReceipt；按授权范围导出，原账目owner唯一 |
| Pursuit/Commitment/Claim/Expression/Effect | 当前与历史正式状态、真实听众/外部目标、精确物理回执和unknown |
| Prompt/配置 | Subject/Role稀疏覆盖、所依赖的明确Prompt版本；安装级资源以逻辑需求/可移植描述导出 |
| 原生执行资料 | 只包含该Subject获准的完整session/entry/call身份、选定工作空间与结果；不能用recent history代替完整导出 |
| 可重建索引/缓存 | 默认省略；保留space/producer/算法profile等重建信息；可选保留获准且完整的只读研究资产 |
| 秘密和机器路径 | 默认不含；以SecretRef/BindingRequirement描述需重新绑定的项目 |
| 日志与诊断 | 默认不含跨Subject/安装日志；必要的受限调用诊断按显式选择和授权附入 |

只读分享包默认不包含可执行任务与真实发送授权。原envelope/原字节和选定派生各有独立身份。缺原件、失效外部URL、不可导出范围和未安装能力进入pending，并说明实际缺口。

## 截点与闭包

单产品在repeatable-read快照中用INSERT…SELECT封存heads/修订身份与owner变更水位到不可变ExportSelection成员，取得Blob引用清单。之后按选定成员分页读取不可变正式修订并流式打包，SQL事务不跨文件复制/网络等待。它是数据保留引用，不保存运行步骤、租约或工作队列；即使后续复制失败，已选正式数据和原件仍可继续取得。完成、取消或清理时释放相关保留引用。

ExportSelection保留内容，不冻结权限。每批复制、跨产品源读取和最终包Artifact交付前重新核验当前scope/Policy；来源撤权或purge先关闭受影响export的新读取/下载，取消同一DBOS工作，关闭并清理已形成的临时/部分包，释放该selection的保留引用。无法立即撤回的已交付副本按真实范围报告pending；不能让自己的export pin无限阻止源清除，也不能以旧快照许可继续披露。Artifact最终下载继续执行当前数据授权。

需要联合一致主体包时：

1. Hept暂停该Subject的新前台/自主派发，协调已接纳的效果和native工作；收件可继续，但cut之后的新消息不混入已冻结视图。
2. WorldClock用同一operationId捕获并持久高水位；Hept封存本次领域水位、实际效果和原生资料选择。
3. Nous暂停相应写入型维护，按已有完整接触和同一Clock receipt封存认知cut及依赖。双方把跨产品refs闭包交回各自owner校验。
4. 参与者返回已提交的ExportSelection，协调者记录联合manifest；任一失败按同一operationId继续，不重新取半份新cut。
5. 解除该Subject的短期封存。不可变内容可继续流式归档，Blob保留引用防止并发回收；不为整个大包复制时间一直锁数据库。

两个数据库没有全局事务。要形成联合cut就显式协调参与者；独立产品包标明只含哪一侧及外部依赖。查询“故事中当时已知”与“数据库现实cut”保留不同字段，不能用一个createdAt冒充二者。

## 导入、同一身份恢复与分支

空安装先调用安装级`data.uploadImportArtifact(ctx,stream)`，HTTP为`POST /v1/import-artifacts`标准二进制上传，返回`{artifactRef:Ref,digest:string,bytes:string}`。Data owner使用现有Blob流与安装级ImportArtifact holder保存正式包，校验data.import权限和包体积限额；无需创建占位Subject，也不套用普通媒体64MiB上限。未采用的上传按24小时临时保留清理，已被ImportPlan引用的包保持到该操作收尾；读取仍检查当前安装数据权限。

`data.importPreview({artifactRef})`先安全提取到temp，检查格式/版本/路径、体积、摘要、owner闭包、当前授权和资源依赖，不启动Subject或发网络效果。

路径处理用成熟归档库的安全选项，拒绝绝对路径、`..`逃逸、越界符号链接/硬链接、重复覆盖和展开体积超限。manifest成员必须实际存在；引用/producer/Prompt与schema版本按所属owner验证。选择依赖或扩展安装是独立显式动作。

同一身份restore要求目标没有另一个继续运行的同Subject，导入其正式身份与历史。若目标已有记录，按明确replace/restore计划处理，不默默merge另一主体。fork创建新Subject和branch来源，保留分支点允许共享的历史，之后独立发展。

本地对象引用的installation/Subject变化由`RefMap`一次重写；原生平台账号、原消息ID、providerRequestId和已经发生的外部效果身份保持原来源。时间域的同一性由其owner决定，不能把旧域数字改成新世界域后宣称历史相同。

已完成外部效果保持completed/accepted。未结束、dispatched和unknown不自动排回发送或付费队列；先核实原native/远端结果及当前授权。导入后Subject为paused，展示BindingRequirement、pending和可明确恢复的工作。

预算分配回执是原Task、原安装/Consumer和childOperation的额度事实。restore/fork保留其历史及未结占用，不能经RefMap把targetInstallation/Consumer改写成新授权。跨安装继续须由实际Task owner核实原费用和unknown，再明确释放/结算原额度并签发新的限定分配；未核实部分保持占用。fork默认不继承可执行分配，实际调用费用仍归原Invocation，不能在新分支重复入账。

## 安装备份与Restic

默认将一个产品的业务与DBOS系统状态放在同一产品数据库中的隔离schema，`pg_dump -Fc`取得同一数据库一致视图。使用不同系统库的部署必须先drain并分别记录一致封存点，不能把独立dump称为原子两库快照。[PostgreSQL SQL dump](https://www.postgresql.org/docs/18/backup-dump.html)。

安装备份流程：drain获准工作→封存Clock/外部效果→dump业务及DBOS→取得Blob与Prompt资源清单→调用原生backup→写备份manifest→成熟归档或Restic备份。产品Secret material默认只保存引用，账号/session等认证数据库仍属于受控备份；需要重建认证的恢复计划在执行前说明。

OpenClaw现有完整state备份会包含config、oauth/credentials和所有agent roots，接口只有includeWorkspace/onlyConfig，没有excludeSecrets。选择完整native archive必须显式选择`includeSecrets:true`并使用Restic或成熟加密归档；manifest和每个artifact必须如实标记含秘密。默认引用模式遇到需要完整原生备份的安装，返回`backup.native_secrets_required`并给出实际范围，等待明确选择；不能把含秘密原包标记为已脱敏。普通Subject Bundle使用下述窄范围native.data导出，不借完整state备份混入其他主体和凭据。需要完整native且排除秘密的后续部署，应在上游backup resource-policy owner实现正式secret-selection，再采用其返回范围，不能由产品解包删几个目录后宣称完成。

Restic使用正式 `init / backup / snapshots / restore / forget / prune`，密码与存储凭据通过withSecret提供给受限child环境或受限密码文件；缓存目录显式指向Paths.cache，命令行和日志不放原始密码/带凭据URL。[Restic repository初始化](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html)。Restic本身处理加密、分块与远端机械，产品不再实现一套云备份协议。

```ts
interface BackupArtifact {
  kind:'pg_dump'|'blob_archive'|'native_archive'|'configuration'|'secret_archive';
  artifactRef:Ref; path:string; digest:string; bytes:string; encrypted:boolean;
  containsSecrets:boolean;
  schemaVersions?:Record<string,number>;
}
type RedactedBootstrap = Pick<Bootstrap,'formatVersion'|'product'|'installationId'|'paths'|'listen'|'service'>
  & {database: {mode:string;connectionRef:string}};
interface InstallationBackupManifest {
  format:'nous-hept-installation';version:1;
  installationId:string;
  productVersion:string;
  schemaVersions:Record<string,number>;
  realCut:string;
  databases:BackupArtifact[];
  blobs:BackupArtifact[];
  native:BackupArtifact[];
  bootstrap:RedactedBootstrap;
  secrets:{included:boolean;requiredRefs:string[]};
  externalEffects:EffectContinuationSummary[];
}
```

恢复先验证并解到新目标，按版本恢复数据库和文件，重新绑定秘密/网络/原生连接，再启动受限Host。DBOS输入、结果、durable streams和datasource也在恢复范围；业务回执仍是长期依据。首次恢复不自动启动Subject或发送旧队列。

备份晚于或早于外部平台真实状态时，恢复不能回滚平台已经发生的事。pending/unknown统一进核实视图；可用的平台历史由正式渠道补查，缺覆盖就保留未知，不生成一个新Effect来“重试成功”。

## 原生资料的真实owner

现OpenClaw基线已有：

- `src/commands/backup.ts::backupCreateCommand` 调用 `infra/backup-create.ts::createBackupArchive`；CLI `backup create --output <archive> --verify --json`，默认包含workspace。
- `commands/backup-shared.ts`从配置枚举全部agent roots。现有API没有Subject/指定agent子集参数，整安装备份可直接复用，Subject Bundle不能套用全部state。
- `commands/backup-restore.ts::backupRestoreCommand`先verify并恢复到新的staging目标，拒绝覆盖live state；随后由受权bootstrap停Gateway、切换state并doctor。
- `sessions.get`是有limit的近期视图，不能当完整迁移。`plugin-sdk/agent-sessions`的SessionManager.getEntries可取得原entry，但还不足以覆盖retained/version/queue/unknown及工作空间闭包。
- `server-methods/sessions-delete.ts::deleteGatewaySession`已有drain/生命周期规则；普通session的deleteTranscript会archive并返回归档路径，物理purge还需清除这些归档。

因此为Subject级资料在原生SessionManager/backup/session lifecycle责任位置新增窄操作：

```ts
native.data.prepare({agentIds,sessionRefs,expectedLifecycles,workspaceRefs,mode})
  -> NativeExportSelection
native.data.export(selectionRef) -> NativeBundleArtifact
native.data.importPreview/restore({artifact,mode:'paused',bindings}) -> NativeRestoreResult
native.data.purge({selectionRef,includeArchives:true}) -> NativePurgeReceipt
```

这些是本轮需要建设的正式接缝，不声称上游已经提供。复用上游的SQLite一致快照、资源inventory、active-drain、expectedSessionId/lifecycleRevision、队列/成果和archive清理；产品不读取其私有表，也不自写native备份引擎。共享workspace、归档、worktree和offsite备份中无法本次清除的范围要明确返回pending。

native调用、unknown marker、真实terminal响应和已接受输出Ref在迁移中保持关联。恢复先可检查，取得当前权限并核实未决效果后才能继续运行。

## 物理清除

清除按授权作用于明确Subject/对象集合，先收紧新读取/使用并停止受影响派发，再由各owner计算和执行闭包：

1. 正式对象/修订、来源关系、实际接触、活跃上下文、形成成果、使用反馈及Subject/Role覆盖。
2. 原件、派生表示、模型受限诊断、durable streams、Lance/数值资产、posting/vector/support与内存缓存。
3. Hept世界、活动、消息、任务、Claim/表达/物理效果及原生session、queue、retained结果、workspace和archive。
4. DBOS通过官方list/cancel/deleteWorkflow(s)处理所属工作及children；datasource检查点按官方API一并清理，不跨读系统私表。
5. 共享Blob只有最后一个合法保留引用解除后调用内容库物理删除；清除选定缓存key而保留字节不算完成。
6. 备份目录和远端快照按当前保留/清除策略处理，不能声称一份不可访问或外部复制已被本机删除。

长期PurgeReceipt只保留必要的无正文结果与pending定位，不借诊断留下已清除私密内容。清除本身的DBOS输出也不能包含要删除的原文。中断后使用同一purge selection继续；读已被封闭，剩余字节删除进度仍可见。

## 软件发行与更新

ReleaseManifest包含程序版本、目标OS/架构、Node要求、普通SDK及platform版本、数据库迁移、默认Prompt/资源、napi/Lance/可选原生包与归属。程序和资源包按版本不可变，下载/安装显式进行，缓存/实验位于temp；普通serve不下载编译依赖。

`updates.prepare`取得并校验选定发行件与兼容要求、当前未完成DBOS/native工作和schema影响；返回具体计划。`updates.apply`由有机器权限的bootstrap/服务适配执行drain→备份→安装staging→迁移→切版本→启动/doctor。长期Host不能在仍处理调用的过程中覆盖自己的载入模块。

DBOS applicationVersion使用真实发行/工作流版本。未完成工作只有在新代码明确可恢复时才采用新版本；必要时保留完成它们的旧worker版本或明确取消/核实。不能长期固定spec-rebuild-1并让改变后的步骤序列自动重放。

程序切换与数据库回滚分别处理。新schema不适合旧程序时，回滚需要所选安装备份及受限恢复；已发生外部效果照样进入核实范围。源码、业务数据和当前运行配置的版本在管理中各自可见。

## 公共操作、配置与验证

```ts
data.export(ctx,{subjectId,selection,mode}) -> OperationRef
data.uploadImportArtifact(ctx,stream) -> {artifactRef:Ref,digest:string,bytes:string}
data.artifacts.read/readStream(ctx,{artifactRef}) -> Metadata|ReadableStream
data.selections.read(ctx,{selectionRef}) -> OwnerCut
data.importPreview(ctx,{artifactRef}) -> ImportPlan
data.import(ctx,{planId,expectedTargets,bindings}) -> OperationRef
data.fork(ctx,{subjectId,cut,selection,name}) -> OperationRef
data.planPurge(ctx,selection) -> PurgePlan
data.purge(ctx,{planId,expectedTargets}) -> OperationRef
backups.create/list/inspect/restore(ctx,input) -> Result|OperationRef
updates.inspect/prepare/apply(ctx,input) -> Result|OperationRef
```

HTTP、CLI与Web使用相同业务操作。CLI提供 `data export/import/fork/purge`、`backup create/list/restore`、`update inspect/prepare/apply`，离线bootstrap也能在Host损坏时调用PG/归档/服务工具进行有限恢复。高影响动作由明确计划和实际目标执行，不接收模型正文作为授权。

`platform.data`定义以下基础值；字段带单位、作用范围和next_call生效，备份目录/凭据为安装级。具体owner还可收紧本次授权限额。

| 字段 | 默认 | 含义 |
|---|---|---|
| maxBundleBytes | 1 GiB | 单Subject普通包上限，可明确提高 |
| maxExpandedBytes | 2 GiB | 解包后的总字节上限 |
| maxEntries | 100000 | 包内条目数上限 |
| export.includeSecrets | false | 普通Subject包只保留秘密引用 |
| export.includeServing | false | 默认省略可重建索引 |
| import.startSubject | false | 导入后paused，未决效果待核实 |
| temporaryRetentionHours | 24 | 失败/取消的非正式临时文件；有正式保留引用的成果不按此删 |
| backup.retention | 未配置 | 安装者明确选择本地/Restic保留，不默认清除已有备份 |
| backup.secretRef / repository | 未配置 | 不猜测远端仓库与密码 |

包通过资料owner授权的标准文件流上传/下载，import上传按maxBundleBytes和对应管理员权限，不套用普通消息附件较小限额。临时下载可重试，完整对象以最终摘要和原提交身份接纳；不自建分块上传协议。安装备份加密和远端策略由管理员明确配置。

用同一个有消息、媒体、认知、世界、任务及unknown效果的Subject完成export→新安装preview/import→检查原记录与暂停状态→恢复明确工作；再覆盖fork独立变化、取消后继续清除与安装backup恢复。少量路径逃逸/体积/RefMap/CAS规则足以保护边界，PG/Restic/归档/原生backup机械复用上游验证。
