# 网络与外部资源

## 真实复用与位置

共享工厂位于 `@nous-wave/platform/network`。HTTP 使用 Node 24 的 WHATWG Fetch、Request、Response、Headers、FormData、Web Streams 和 AbortSignal；连接、代理和流量接缝采用 Undici 8 的成熟实现。基线为已核实的 Undici 8.10.0 / commit `c8d80e6b2dcfab282557b08f51352937bc9e5692`，后续正常升级由 lockfile 固定。

Node 24 内置 fetch 的 Dispatcher 是 v1 合同。每资源 Agent8 经 Undici 官方 `Dispatcher1Wrapper` 传入原生 fetch；不能直接将 Agent8 传给它，也不能把 SDK 的原生 FormData 交给不同版本的 Undici fetch。具体实验见[底座研究](../../研究/基础设施与现有结构.md#三网络版本组合的实际行为)。

```ts
import {Agent, EnvHttpProxyAgent, ProxyAgent, Socks5ProxyAgent,
        Dispatcher1Wrapper} from 'undici';
const pool = new Agent({connections:8,connect:{timeout:10_000}});
const dispatcher = new Dispatcher1Wrapper(pool);
const fetchForResource:typeof fetch = (input, init) =>
  globalThis.fetch(input, {...init,dispatcher} as RequestInit);
```

工厂在这个公开 API 上增加本次资源授权、期限、日志字段及生命周期绑定。不要再实现代理协议、连接池、重连或 Fetch/FormData 转换。旧 Hept NetworkAccess 可复制其 credential-free URL/目标校验函数，移除只限 OpenAI POST、固定 requester 和整段 response 缓冲的路径。

## 消费者与权限来源

| 消费者 | 网络范围与配置来源 | 实际调用方 |
|---|---|---|
| AI SDK Provider | 已登记的 Provider 资源、API base、SecretRef 和 networkProfile | Provider 自带 fetch 注入点；LLM/Embedding/Rerank/ASR/TTS 均沿真实 SDK |
| URL/文档资源 | 受信资源连接与允许读取的 URL 范围 | Nous resources；结果进入正式 Material |
| 消息附件 | 已接收平台消息所给的受授权媒体位置与易失期限 | 原生渠道已有下载/媒体 API，或 Hept 受限下载客户端 |
| SDK 跨产品 | 固定对端 installation、baseURL、Subject 和服务委派 | 生成 Client 的 fetchApi/custom fetch |
| 原生 browser/tools/channel | 原生 sandbox、浏览器 profile、网络与账号配置 | OpenClaw 原实现；由其正式配置 API 管理 |
| 明确的远程扩展 | 能力声明的连接目标与网络策略 | 实际 MCP/原生扩展 SDK |

模型正文和工具输入只给业务目标。URL 授权由对应资源/工具 owner 结合当前委派建立，不接收模型声称的“允许访问所有网络”。同一资源内的模型协议路径由 SDK 生成，不以业务侧 if modelName 重写。

## 配置结构与默认值

定义由 Settings 注册到 `platform.network`，引用用稳定 profileId，保存值与生效按[配置与生效](配置与生效.md)。

```ts
interface NetworkProfile {
  proxy:
    | {mode:'direct'}
    | {mode:'environment';noProxy?:string}
    | {mode:'http';url:string;credentialRef?:string}
    | {mode:'socks5';url:string;credentialRef?:string};
  tls:{
    useSystemCA:boolean;
    caFileRefs:string[];
    clientCertificateRef?:string;
    clientKeyRef?:string;
    rejectUnauthorized:boolean;
  };
  timeout:{connectMs:number;headersMs:number;bodyIdleMs:number;totalMs:number};
  connections:number;
  pipelining:number;
  maxHeaderBytes:number;
  redirects:{mode:'deny'|'follow';maxHops:number};
  maxResponseBytes:number;
}
interface NetworkSettings {
  defaultProfileId:string;
  profiles:Record<string,NetworkProfile>;
}
interface ResourceNetworkScope {
  resourceId:string;
  profileId:string;
  allowedOrigins:string[];
  allowedPathPrefixes:string[];
  methods:string[];
  addressScope:'public'|'configured_private';
  allowedPrivateRanges?:string[];
  credentialOrigins:string[];
}
```

`platform.network`有效值为NetworkSettings，默认defaultProfileId为`default`，profiles.default含下表完整默认字段。profileId就是profiles的稳定key，不在同一对象重复保存id；资源的ResourceNetworkScope引用该key。新增profile必须提交完整有效配置，安装/资源允许的字段范围由Settings元数据定义；普通Role不能替换安装级代理/TLS授权。公开网络状态显示实际profileId、配置修订及当前连接，不另存一份可变profile表。配置示例见[稀疏配置](../../示例/稀疏配置.md)。

| 字段 | 产品默认 | 范围与生效 |
|---|---|---|
| proxy.mode | environment；没有相应代理变量时直连 | 安装默认，资源可指定受许可profile；新连接 |
| proxy.noProxy | 未设置时采用系统 NO_PROXY | 安装/资源；next_call |
| tls.useSystemCA | true | 安装；运行时/进程CA变更按实际适配restart |
| tls.caFileRefs | [] | 安装/资源；新连接 |
| tls.rejectUnauthorized | true | 安装/资源；显式受控实验修改，显示实际状态 |
| connectMs | 10000 | 资源；新连接 |
| headersMs / bodyIdleMs | 300000 / 30000 | 资源；next_call；模型总期限另取Role设置 |
| totalMs | 120000 | 资源；可被本次更短的真实deadline收紧 |
| connections / pipelining | 8 / 1 | 资源；新池 |
| maxHeaderBytes | 16384 | 安装/资源；新连接 |
| redirects | API默认deny；公共文档读取follow最多5跳 | 资源；next_call |
| maxResponseBytes | 64 MiB；模型JSON/管理响应可单独收紧 | 资源与具体资料owner；本次调用 |

HTTP(S) proxy 使用 `ProxyAgent`，系统环境使用 `EnvHttpProxyAgent`，SOCKS5 使用 `Socks5ProxyAgent`。URI 保存无凭据地址，用户名密码通过 SecretRef 取得；环境代理中的秘密同样脱敏。HTTP_PROXY/HTTPS_PROXY/NO_PROXY 的大小写和优先级沿用库，不另建一套解析规则。

网络配置不是每个 Subject 任意扩大的权限。资源选择可在 Subject/Role 范围覆盖，但只能选委派许可的 profile 与目标；安装对私网、代理、CA和证书的限制仍成立。

## 客户端接口

```ts
interface NetworkClient {
  fetch:typeof fetch;           // 返回完整标准Response及其body stream
  webSocket(url:string,options?:WebSocketOptions):WebSocket;
  metadata:{profileId:string;revisionRefs:RevisionRef[];resourceId:string};
  close():Promise<void>;
}
network.client(ctx,{resource:ResourceNetworkScope,deadline?}):Promise<NetworkClient>
network.inspect(ctx,{profileId?,resourceId?}):Promise<NetworkDiagnostics>
network.probe(ctx,{resourceId,kind:'dns'|'tls'|'http'}):Promise<ProbeResult>
```

服务组合时将 client.fetch 传给 AI SDK Provider、跨产品 SDK 或资源工具的正式 fetch 参数。业务拿标准 Response，不经过另一个只保留 status/body Uint8Array 的私有协议。

WebSocket 使用 Undici 自身的 WebSocket/Dispatcher 配套 API；不将它的 Dispatcher 误传给不接受该扩展的原生 WebSocket 构造器。浏览器流量仍通过 OpenClaw browser profile 原生管理，不能假定 Node HTTP profile 会改变浏览器代理。

## 请求、流与授权顺序

1. 真实业务 owner 解析资源与目标，将当前操作权限、purpose/audience和网络范围交给工厂。
2. 读取网络/资源配置快照和所需 SecretRef 版本；创建或复用同 revision 的池。池缓存用成熟 LRU，键包含资源、配置修订、秘密版本和TLS材料版本。
3. 用 WHATWG URL 规范化目标，禁止 URL 用户名/密码混入普通资料；按 origin、方法和路径边界授权，处理 IDN、IPv6 与规范化后的 IP。
4. 对需要地址约束的直连，在真实连接的 lookup/connector 上解析并检查地址，使用 `ipaddr.js` 识别 IP、mapped IPv4、回环/私网/link-local，避免只检查一次字符串后再让别处解析。
5. 以 `AbortSignal.any` 组合调用方取消与本次真实deadline，使用库的连接/头/体超时。保留 SDK 的流、multipart、文件和工具消息；不要通过 clone+arrayBuffer 缓冲整个上传或下载。
6. 每个实际 dispatch 运行对应资源的当前授权检查。重定向每跳仍通过相同策略，检查目标、方法和凭据范围；跨 origin 不携带原授权头或 cookie。API请求默认拒绝重定向。
7. 返回 Response stream。字节上限使用标准 TransformStream/成熟流量计数机制，在真正消费处限额并取消上游；raw bytes 写入 Blob，不塞入普通 JSON。
8. 网络 owner 返回实际阶段/状态/已读字节等诊断；模型/消息等业务 owner 判断重试与真实效果含义。

使用 native fetch 的重定向流程时，通过每请求闭包中的 Undici 策略 interceptor 检查每次 dispatch并计数；每个请求独立计数，不能在共享池上混用 mutable hop 计数。复用官方拦截/取消机制，项目只维护目标授权判断。

代理远程 DNS 的地址约束需要明确能力。对于必须限制公共地址的来源，采用能固定/验证目标地址的连接，或具备对应服务端 ACL 的可信代理；无法执行该限制的 profile 返回 scope_unavailable，不能把本机 DNS 预查当作代理实际目标的验证。管理员明确配置的本地模型/私网服务使用 configured_private 及精确范围，正常支持回环、容器和受权内网。

## 取消、错误和重试

网络层不为任意 POST 安装 RetryAgent。GET资料读取可以由资料工作流按明确限额重试；模型、物理发送和有副作用工具由真实 owner 结合 provider 的幂等/结果查询能力决定。SDK与DBOS的重试策略应在同一调用计划中明确，避免两层各自重试。

| 结果 | 传输事实 | 由谁处理 |
|---|---|---|
| 未取得授权/URL范围不符 | 尚未派发 | owner返回权限或配置错误 |
| DNS/TLS/connect失败 | 保存具体阶段；不能靠一个外层TypeError推断所有写请求均未执行 | 网络错误cause与阶段进入安全Problem |
| HTTP 401/403/429/5xx | 请求得到具体响应 | Provider/渠道解释，不由网络猜测费用或所有业务效果 |
| 发送后超时、连接中断或abort | 可能已有远端效果 | 模型/Effect保存unknown及原身份，不盲目换资源重做 |
| 下载超限/媒体失效 | 原消息仍存在，原件保存状态有缺口 | 材料owner保留范围/失败/可继续条件 |
| 客户端断开 | 取消该消费；已保存结果与外部效果继续由其owner掌握 | 不因Web连接断开删除真实业务结果 |

错误code保留 `network.dns_failed / tls_failed / connect_timeout / timeout / cancelled / unauthorized_target / response_too_large / scope_unavailable` 等具体原因，传输映射依共同 Problem。记录 URL 的安全 origin/path，清除 signed query、Authorization、Cookie、代理凭据和本机私人路径。

## 设置变化与生命周期

新请求采用新 profile 快照；旧调用保持原快照，受当前授权撤销约束。配置/秘密变化使新缓存键创建新池，旧池使用库的 close 优雅退出；强制撤销由对应 owner 取消其真实活动和请求。

Bootstrap不探测全部远端，更不发付费模型测试。Host启动可报告某 profile不可用而保留管理。`network.probe` 默认只做显式选择的 DNS/TLS/安全健康请求；模型生成测试属于有预算的 models.test。

Host停止取消未完成下载和可取消请求，保存其owner状态，再关闭池和WebSocket。Subject删除关闭该范围的资源使用/缓存，不删除其他 Subject 共享的授权资源。导出保留 profile逻辑引用和非敏感可移植值；代理秘密、CA私钥、安装路径与机器信任由新安装重新绑定。

## 管理入口与当前结构替换

API `GET /v1/network`、`POST /v1/network/probes`、Settings中的profile修改；CLI `network list/inspect/probe`；Web在Provider/资源/渠道页显示实际采用profile与连接诊断。各入口使用同一配置和授权owner。

迁入旧NetworkAccess的有效授权辅助函数，替换其固定OpenAI-only响应缓冲器；删除两个产品分别创建裸fetch、环境代理判断和超时错误映射的副本。原生OpenClaw自己的transport仍留在其原owner，通过正式配置和binding整合。

验证复用一次配置—真实模型/资料链，并保留当前已辨别版本错误的multipart/Request/stream小用例；再覆盖一条受限重定向与取消路径。代理协议、TLS和HTTP解析沿用Undici已有测试。
