# Nous 原生认知与交互设计

[项目宪纲](../项目宪纲.md)规定产品能力与认知语义；[整体架构与模块合同](整体架构与模块合同.md)规定 Nous 与 Heptalogos 的数据归属。本文件约定 Nous 内部应提供的完整认知能力、模型调用与对外交互方式。

## 认知域、身份与配置

**Namespace 是一个独立、持续的认知数据域。** 它拥有资料、认知、来源、修订、索引、工作状态、策略、权限与数据生命周期。普通记忆或知识应用直接使用一个 Namespace。

**Subject 是该认知域在主体模式下对应的长期个体身份。** 启用 Ego、Social、LanguageConvention、Motivation 等能力，沿用同一个认知数据域。身份与能力模式可分别配置；无需另建一层以 Subject 为主键的完整数据生命周期，也无需为每个会话、模型、子执行者或所认识的人分配一个 Subject。

一个长期主体跨越多个 IM 平台、设备和任务，仍绑定同一认知域及稳定主体标识。不同独立主体使用各自的认知域；共享外部资料通过来源授权实现，人物与群体归 Social 认识。Heptalogos 持有实际主体运行身份及平台账号事实，通过正式授权绑定 Nous；Nous 独立部署时自行维护认知域与调用权限。

配置由单一所有者使用可读 TOML 文件保存期望状态，进程内维护解析后的有效快照；修改来自 CLI、HTTP、SDK 时在同一处原子写回。数据库承载认知与运行状态，不再复制有效配置和全部覆盖历史。普通操作者可以查看来源、编辑配置；模型与索引参数按用途进一步展开。领域能力按需启用，关闭的能力停止相应后台工作及衍生索引。

## 认知数据与领域所有权

原始文档、图像、GIF、音视频与大字节放在内容存储；数据库保存稳定身份、原件定位、区域、观察、派生表示、认知修订、关系、工作状态及来源链接。查询首先定位文字片段、文档页、视频时间段或图片区域，再按需读取对应内容。向量与检索图作为可重建索引独立维护。

原件、实际接触、模型已读取内容、推断、认知采用和真实行为各有自己的事件语义。创作者 Seed 保留原文与创作来源；人格中的初始设定与后续亲身经历分别保存。模型多次摘要同一来源不会形成多个独立证据。

Memory、Episode、Journal、Schema、Concept、Entity、Association、Ego、Social 和 Motivation 对各自语义负责；共同认知机制集中处理身份、精确修订、证据、状态可见性、来源撤回和生命周期。一次领域操作提交已经决定的变更及相关持久工作，调用者无需自己修改各张表、向量、Context 和维护结果。

已有 `Authority` 负责统一 SQLite 读写事务、提交序号及事务内持久任务接纳；完整业务操作负责自己的判断和一次提交。普通写入直接完成事务，外部重复投递与持久任务通过真实事件身份去重；取消每条简单操作都保存完整请求与结果的泛化 receipt。相同状态和规则由唯一领域所有者修改，其他模块通过完整业务接口消费。重组 `CognitiveRecords` 巨型职责、`ImportService` 分散函数绑定、`RuntimeService` 过量协调与 `Application` 的网状依赖；合并无独立责任的薄包装与按行数拆散的文件，直接迁移实际消费者并删除旧路径。通用存储、模型、媒体、后台任务优先使用已有依赖。应用组合根只构造与管理生命周期。

## 模型与多媒体

模型调用配置分为提供方连接、模型实际能力、调用预设和任务角色。实际能力包含输入模态、结构化输出、工具、上下文限制、音视频处理、Embedding 模态及空间；调用预设包含温度、推理强度、Token 预算、超时、调用费用和可用路线。模型能力由配置和提供方事实确定；缺少能力时按请求所选严格或允许退化的策略执行。

媒体解释提供三种正式策略：

- **自由描述**：保存人类可读的画面、声音、动作、文本和语境描述。
- **直接结构化**：针对明确的简单对象，一次生成有界结构化结果。
- **先描述后结构化**：复杂资料先形成自由描述，再对原件与描述作结构化解释。

派生结果保存真实输入区域、模型身份、任务/Prompt/Schema 与输入输出摘要、内容、来源和表示类型；这些轻量生产信息随被采用的派生表示保存。移除付费调用预约、每日资源账本、历史付款托管、跨安装付费请求重放及其旧数据升级路径；保留可淘汰任务结果缓存、临时调试追踪、真实提供方用量和已完成业务任务结果。视频模型可以直接处理支持的格式；仅具备图像能力时使用 FFmpeg 提取有时间位置的画面并单独处理音轨。多模态 Embedding 消费真实图像、视频、音频及混合输入，与文本描述向量共同参与检索；不同向量空间分别索引并在排序阶段融合。

提示词编译的产物是**最终消息序列**，包括稳定任务说明、按角色安置的动态资料、媒体、结构化输出约束和提供方参数。自然语言任务说明应完整、清晰、适合模型理解；每次模型调用专注于有定义的语义工作。程序负责对象身份、版本、时间、索引、事务、预算、状态变更和持久化。结构化模型输出只承载该次语义任务必要的字段及局部短键，真实认知 ID 由程序绑定。

稳定前缀、连续消息与当前动态认知按最终提供方输入组织。缓存跟踪实际命中 Token 与费用；追踪 ID、当前时间和不断变化的状态不参与稳定提示前缀。调用记录能查看最终消息、实际模型、输出 Schema、媒体、参数、Token、耗时、缓存、费用和真实结果。

## Wave、NousQL 与查询语义

自然语言和 NousQL 都是一等完整查询。调用者**在已知信息允许时强烈建议先消解指代**：将已知人物、事项和时间写明，或传入已有精确引用。原始引用、代词、省略、不同语言的表达始终允许直接检索。程序解析 NousQL 的显式选择器、名称和引用；查询不会对普通文本执行代词正则扫描、自动替换或拒绝。

查询可附上明确可用的工作情境：当前任务、已知人物、时间、会话、已有认知引用、媒体及尚待解决的问题。这是可选的检索线索。没有宿主情境时，普通查询仍正常执行。VCP 自身使用查询向量、显式核心 Concept/Entity/Tag、临时语义线索和实际拓扑，可独立运行。

Wave 在一次请求下编译确定的执行计划：词项、语义向量、名称/实体、时间与历史、可选图拓扑扩展、融合和重排。各阶段共享统一候选与来源。支持单独启用、关闭与配置策略；已要求的能力不可悄悄退化，允许退化时返回实际执行模式与原因。可使用计算重排、专用 Reranker 或可选生成模型。索引按真实数据代际构建与更新，普通前台查询使用已有索引和确定的增量状态。

查询结果优先提供内容、必要关系、时间、来源和可读短引用；按需展开完整原件、图路径、精确修订与检索轨迹。媒体查询支持以图片/视频片段/音频作为线索，并能继续读取特定区域及来源。执行轨迹可展开实际条件、候选通道、融合、排序、降级及成本。

## 主动认知与模型上下文

Nous 的独特能力是持续认知运行：深度接入的宿主在第一次模型调用、工具续轮、模型切换、上下文压缩和恢复时，都自动取得适用的 Ego、Social、Motivation、相关记忆、当前工作与媒体。主体视角和专业执行视角具有不同的认知范围。

当前输入、工具返回、模型输出及真实交互反馈经宿主接入后进入对应材料与工作状态，后续形成与整理使用持久任务。模型回应的作者与来源保持原貌。长期认知、当前工作集、活跃居民、外部资料及实际模型消息通过正式引用关联，避免复制多份互相竞争的认知真相。

**Steward 维护当前认知工作集。** 程序负责检索执行、预算、居民状态、工作切换、来源绑定、摘要覆盖范围、存储和提交。LLM 负责有意义且边界明确的语义任务：从真实材料中判断与当前工作相关的内容、理解矛盾、生成按指定范围和用途的摘要、概括进展及待解问题。提示词应给足自然语言背景与判断标准，输出本次短键或可读文字。模型工具调用只有在宿主实际提供工具且任务需要时使用；接入的工具结果继续进入同一工作状态。

工作状态保存目标、已定决定、进展、引用、未解问题和恢复条件。内容压缩由程序确定范围、目标与 Token 预算，模型处理指定的真实原文；旧话题可退出当前窗口，仍能按引用重新取得。Journal 组织主体在相应时段真实经历的主观叙述；Dreaming 通过离线联想寻找模式、解释或待查问题，候选认识在形成时保留假设与来源状态。

## 对外交互与宿主集成

**SDK** 完整暴露类型化的原生领域、配置和管理能力。**HTTP** 区分普通认知、宿主运行和管理接口，提供可读的常用结果及按需原始数据/诊断。**CLI** 以人类真实操作组织命令，保存当前认知域与会话，默认显示精简可读结果并支持 JSON、短引用和帮助。**MCP** 以模型实际交互目标组织少量有意义的工具集合，避免暴露内部方法目录；身份与会话由连接绑定，查询、读取、来源、媒体和关系可连续使用。

Agent 和人的连续操作使用可复用的短引用与会话状态，完整 UUID、哈希、内部 Schema 保留在机器合同中。NousQL 使用说明随 CLI 帮助、MCP 资源、SDK 指南与 Agent Skill 提供，并把“已知指代优先明确”写作调用建议。

A-Memorix 的能力需求全部由 Nous 原生领域提供。**独立 A-Memorix 兼容适配器只消费正式 Nous SDK**，映射旧工具名、参数、返回、RPC 与可移植格式。兼容名词、专属身份或数据库规则不得进入 Nous 本体的领域、数据表和模型角色。MaiBot/Heptalogos 的平台 Hook、Dashboard 与通信集成由 Heptalogos 仓库维护，通过正式 SDK 调用 Nous。

## 工程推进的实际顺序

当前以 Nous PR #58 的有效实现为起点，先完成单一认知域、Authority 事务中心、认知/导入/Context 深模块收敛，随后简化模型执行与配置、统一材料派生、Wave/NousQL、主动上下文及用户交互。开发阶段无历史实例数据保留义务，直接采用当前正确 Schema，清除旧迁移、付费托管和内部兼容。移除当前被误纳入源码的构建调试产物。沿真实入口完成资料接纳、认知修订、来源读取、真实模型输入、工具续轮与后台持续工作；独立适配器通过正式 SDK 接通。成熟公开基准用于产品链路可用后的少量检索测评。Nous 完整可用后推进 Heptalogos 的主体内核和正式集成。
