# Nous 原生认知与交互设计

[项目宪纲](../项目宪纲.md)规定产品目的和领域语义；[整体架构与模块合同](整体架构与模块合同.md)规定 Nous 与 Heptalogos 的责任。本文件确定共享的数据与执行合同；[输入输出与持续形成 Spec](Nous输入输出与持续形成Spec.md)确定使用场景、事件归属、形成时机和认识变化的完整操作。产品实现状态和安装说明在 Nous 仓库维护。

Nous 首先成为架构、流程和日常使用都容易理解的完整认知产品。普通资料型应用可以直接导入、查询和修订认识；主体型应用在同一数据域中启用 Ego、Social、Motivation 与持续认知。SDK、HTTP、CLI 和 MCP 消费相同原生操作，随功能演进。独立 SDK 发行和 A-Memorix 适配开发在原生产品完整稳定后开展。

## 从一条真实操作组织能力

使用者选择 Namespace，导入文件并取得原件与处理状态；形成的各条认识进入检索，查询返回内容和短引用；继续阅读可以取得原文、时间和来源。明确纠正一条认识时保留其身份和修订，更新索引及当前工作所使用的认识。

宿主建立当前工作后，在实际模型调用前提交真实请求。ContextRuntime 取得相关认知、编译实际输入，宿主发送并报告完整回复和工具结果。最新输入和结果立即参与当前工作，后台再形成长期认识、Episode、Journal 或反思。下一轮继续同一任务，也能恢复另一个已有 Work。

这些是领域提供的完整操作。用户提交目标和内容，取得正式对象、可读状态及下一读取位置；解析、形成、投影与作业的内部组合由程序承担。

## 从输入到结果的完整交互

### 接入能力与访问方式

| 使用方式 | 调用者提供 | Nous 自动完成 | 交付形式 |
| --- | --- | --- | --- |
| CLI/MCP 工具调用 | 真实资料、明确问题、可选现有引用/媒体与任务线索 | 接纳、形成调度、Wave 查询、来源展开 | 可读结果、短引用、继续阅读的入口 |
| 交互事实接入 | 宿主掌握的真实事件、人物、会话、时间和附件 | 同一原生用例，按真实来源组织历史与形成 | 类型化结果、可读视图和异步处理状态 |
| 深度模型调用接入 | 已绑定的运行身份、原生模型请求、实际新事件、回复和工具结果 | 自动记录新事件、组织当前认知、检索、Steward、模型输入编译、后台形成与反馈 | 最终模型消息、Call 引用、长期任务状态及后续认知更新 |

SDK 是访问这些能力的方式，宿主可以渐进增加自动化；不同接口共用原生业务。`ingest` 接纳资料，`observe` 接纳真实事件及接触，`remember/correct` 明确保留或纠正认识，`query/read` 查找与展开，`runtime` 接入模型调用。工作与管理员操作按所属对象提供。具体输入、触发、输出及模块修改责任见[持续形成 Spec](Nous输入输出与持续形成Spec.md)。

输入支持自然语言、文件/字节、媒体引用和可流式接入的原件。媒体保留 MIME、帧/页/时段/区域及来源；纯文本与 NousQL 都能直接查询，现有情境与媒体是可选线索。调用者知道人物、事项和时间时应明确指代；程序只解析正式 NousQL、名称及精确引用，不以代词正则检查普通文字。

`ingest` 接收实际资料并返回正式原件与待处理状态；`observe` 接收宿主真实事件，可在一次调用中携带新内容或已有来源及发言者、接触者、实际事件与接触时间、会话、听众。服务内部完成原件保存及 Observation 接纳，调用者不用手工串联多个存储动作。宿主只是保存未被主体接触的历史时，保存其资料来源并保留接触状态；进入主体当前感知时才记录相应实际接触。

默认查询和记忆读取呈现正文、适用人物/时间、认识状态、必要来源和可复制的短引用。返回类型化 DTO 供机器使用，详细对象与检索 trace 由调用者主动展开。普通 AI 工具输出和结构化字段均限制到本次任务所需内容；大型原件、媒体字节、UUID 与向量空间只在精确读取或诊断时交付。查询结果引用能够跨紧接着的 read/correct/追问连续使用。

### 真实交往进入长期认知

每个实际新事件首先成为可查询的原始历史及当前工作线索，重播消息保留同一外部事件身份。模型最终输入中的历史副本与内部 Prompt 按本次调用保存。作者、观察者、执行用途和模型角色分别表达；主体实际看到、工具执行者读取、创作者提供设定和其他人发言各有来源归属。

后台 Formation 复用既有待处理接触合并与 DBOS 工作，按已完成交互组、工作边界及维护机会组织来源片段。程序提供参与者、时间、相关前文和少量旧认识；语义任务提炼并对照重复、补充、变化或冲突，程序组织领域采用。当前工作立即可用，长期整理不按每条短回应独立排模型任务。

模型提炼得到的 `notes` 是一次语言任务的临时结果。各条候选经已知来源和当前认识决定采用、修订或跳过；采用后成为正式 Memory，维护独立认知身份和来源。原文仍在 Material/Region；Episode 依据真实 Observation 和工作事件分段、可将 Memory 作为成员；Journal 在需要回顾一段实际经历时组织有来源的主观叙述。Social/LanguageConvention 根据具体交往认识人物、关系和社交符号；Ego/Motivation 按相应经历演化。Work 的任务摘要继续属于 Work，模型窗口压缩属于 Context 的派生表示。

例如某人先在群聊表示计划去大阪，后来明确取消：原消息分别保存；当前工作立即使用新消息；长期认识依来源与时间修订，旧说法可按历史读取。查询该人的现行计划优先返回取消状态及其出处。一次相关讨论可以形成一个 Episode；主体有真实写日记的需要时才整理为 Journal。

## 认知域与正式身份

Namespace 是唯一认知数据根，拥有资料、认知、来源、修订、索引、Work、运行状态、策略和生命周期。它有稳定 ID、可读 slug、显示名称、模式、可选 subject_key 与能力集合。普通记忆应用只需要 Namespace。

Subject 是主体模式下绑定的长期个体身份。会话、执行者、所认识的人和所配置模型各有自身引用；它们无需拥有另一份主体数据域。Heptalogos 持有主体运行及平台账号事实，Nous 持有认知域和绑定关系；Nous 独立使用时自行管理数据域及调用身份。

正式对象的身份包含所属 Namespace。Material、Observation、Representation、Region 使用 Namespace 与本地 ID；认知对象以 Namespace、ID 保持连续，kind 是该身份的稳定类型，精确引用携带 kind 和 revision。向量资产包含 Namespace、目标精确引用及向量空间。主键、唯一约束、读写条件、关联和索引键共同表达这一归属。

已绑定 Namespace 的客户端省略重复字段，服务端仍在绑定数据域中解释引用。只给查询增加 namespace_id 条件而保留全局 ID 主键，会继续阻止独立域复用身份，必须同步修改约束及实际消费者。

当前版本 Bundle 保存资料和认知的正式 ID、精确修订及来源关系。导入运行创建自己的 run ID，正式对象不因传输重新编号。同一目标域已有同身份同内容时复用，存在实质内容冲突时返回冲突，由使用者选择目标或进行正式修订。

## 对象、来源与领域所有权

| 对象或能力 | 保存内容与决定者 | 调用者使用的结果 |
| --- | --- | --- |
| Material | 原始字节、正文、MIME、内容身份与来源说明；Material owner 接纳 | 原件引用、读取及下载 |
| Region | 文本范围、页、时间段、矩形等精确选择；材料与媒体能力维护坐标 | 对应区域的正文或媒体 |
| Observation | 谁在何时通过何种渠道实际接触什么；接触用例接纳 | 接触事实、知情时间与来源 |
| Representation | 解析、转录、描述、结构化解释和媒体变换；派生 owner 保存输入和生产出处 | 可读产物及原件、区域对应 |
| Memory 等认知 | 被采用的认识、支持、时间、状态与修订；各领域决定内容 | 阅读、检索、纠正、留存及使用反馈 |
| WorkContext | 目的、决定、进展、未解问题、锚点与恢复条件；Work 操作维护 | 跨会话、跨执行者继续任务 |
| Session / Call | 当前居民、实际模型输入输出与调用事实；ContextRuntime 维护 | 宿主自动接缝、读取与续轮 |
| IndexGeneration | 检索资产、覆盖水位和向量空间；Wave 维护 | 已建索引及确定的当前增量 |

原件存在、主体接触、执行模型读取和长期认识形成分别保存。后台读取文件不自动成为主体经历；同一原件的不同真实接触各有 Observation，同一原事件的重复投递只接纳一次。多个摘要沿来源关系归到共同原件，保持证据依赖。

内容散列用于字节去重和缓存，正式引用由 ReferenceDirectory 管理。大字节通过内容存储下载、区域读取或流式交付。导出 ZIP、下载包和临时构建成果属于交付文件；使用者主动将其作为资料接纳时才成为 Material。

共同认知记录能力负责精确修订、证据解析、时间、当前可见性和正式写入。Memory 留存、Entity 属性解释、社会关系等规则归各自领域。跨领域用例组合共同 WriteTx。模块按真实职责组织，删除仅转发或维持旧形状的薄层；文件大小不决定责任边界。

## Authority、内容与持久工作

Authority 提供 SQLAlchemy Core/SQLite 读快照、短写事务、提交序号及关闭。完整业务操作打开 write(ctx)，事务参与者使用同一个 WriteTx。正式状态与 tx.enqueue(JobSpec(...)) 在同一事务接纳，DBOS 负责持久工作领取、继续、取消及状态；具体作业和业务结果归领域。

模型、Embedding、FFmpeg、网络及大字节准备在写事务外执行。内容准备返回租约；短事务登记原件、区域、派生或认知，结束后释放租约。模型产出通过后续短事务采用，读取其需要的当前业务事实并安排投影。

普通写入以事务提交完成，不要求 operation UUID、完整请求/结果 receipt 或事务结果标志。请求跟踪 ID 只承担诊断；真实重复投递由领域身份处理：

- Host 原事件使用 Namespace、可信 caller 和原始 event_id；Session 是关联情境。response_id、tool_call_id 保持协议原样。
- 导入单元采用使用 run_id 与 unit_id；重试继续该运行结果，明确重新处理创建新运行。
- 持久工作使用 workflow ID 和业务结果。任务入队与正式状态写入共用 Authority 事务。

同键再次提交时，领域读取自己的事件或结果记录，比较必要真实输入，并按当前读取范围返回。去重不复制成覆盖全产品的永久命令回执。

Application 是唯一组合根，构造明确依赖并管理启动与关闭。领域不通过全局 app 寻找能力，也不在启动后互相补字段。Material/Derived、Model、Cognition、Wave、Import、ContextRuntime 共用 Authority、内容和执行器。

## 导入：一个目的、一项完整操作

Import 接收文件、文本或已接纳来源、目标 Namespace、来源说明及本次用途。普通操作保持“导入后可查询”；只保存原件、提炼记忆和抽取关系有各自明确用途，默认策略来自有效配置。

ImportOperation 拥有本次输入、处理选择和结果。输入项保存文件、内容身份与来源；单元保存正式区域或已解析 Representation；UnitResult 保存采用的认知、派生产物和后续工作。Catalog 作为冻结输入清单只保存 header、unit_ids 及精确引用，单元正文从正式来源读取。

原件保存后即可返回引用。形成或向量工作未完成时返回真实待处理状态；缺模型时精确读取、已有词项与确定性能力继续可用。独立单元部分成功后继续未完成工作，已采用文字和后续向量状态分别表达。

同一进展不再经过 text request、catalog 子 request、profile request 和 manifest receipt 的平行状态链。内容去重按明确导入策略执行；实际接触事件身份独立。程序安排形成与索引，用户不用手动调用每个内部阶段。

### 自动认识直接成为 Memory

记忆任务输出有来源的候选陈述，并在已有候选时表达其语义关系。当前小合同及输入说明以[持续形成 Spec](Nous输入输出与持续形成Spec.md)为准；原事件和候选使用本次短键，正式身份由程序绑定。

每条 note 表达一个候选认识。Formation 根据真实来源、相关现行记忆和本次形成目的，决定采用为 Memory、修订已有认识或跳过重复内容。正式 Memory 具有自己的来源、时间、producer、留存和后续修订。作者、转述、否定、条件和推测保留在自然语言中；程序解析有足够依据的时间，原文中的未解析表达仍保留。

自动形成无需把整段原文先复制成 Memory。原文由 Material/Region 读取；图结果也可以直接引用 Observation、精确区域和本次实际使用的派生表示。删除保留短键 memory、records[0] 和单一原文 anchor 假设。

显式 remember 保存用户指定的完整内容，长文本与逐字采用均可成立。MemorySemantics 保存对已有 Memory 的独立解释、限定或重新理解，引用其精确修订及新证据。它按具体再解释目的产生，各条自动认识不会全部聚合进附属 interpretations 数组。

### 语言任务按目的组织

普通形成在一次有边界任务中提炼并对照少量旧候选；实体关系提取是另一个明确目的。图任务可在一份小型结果中表达实体名称、类型、明确别名，以及端点、关系和可独立理解的说明。程序按真实身份线索解析端点和来源，真正歧义交给带少量实际候选背景的消歧任务。

概念、Schema 和再解释按其目的触发。需要记忆和图两种结果时分别执行，保留各自 producer；共同提交时也不把不同调用产物套成一个生产出处。用户明确的手工 FormationDraft 继续表达领域提案，LLM response 使用当前任务所需的小合同。

## 模型任务、配置与执行

Provider 保存连接、凭据来源和实际 API 实现；Model 保存真实操作、模态、结构化/工具能力、上下文和向量空间；Preset 保存温度、推理参数、超时及单次资源限制；Role 选择用途所需资源。

RoleDefinition 拥有具体语言任务的输入、输出和模板。记忆、图提取及媒体任务共用 formation 资源和预设，各自使用任务模板。PromptService 提供有名称、版本及编辑入口的正式资源，用户无需为每个任务重新配置模型。

system 提供任务目标、判断标准、输出含义及有用的正反/空结果例；user 提供真实内容、必要背景、当次目标、局部短键和长度指引。UUID、完整 formation policy、切分参数、权重、修订目标及状态管理留在程序。说明按任务充分表达，输入输出受真实 Token 预算控制。

### 准备与发送同一个请求

prepare_generation 返回进程内 PreparedGeneration：已选模型/预设、已编译有序消息、媒体、输出合同和有效参数。execute_generation 只执行该对象；generate 组合准备和执行。对象不承担另一套持久调用或路由生命周期。

预览和实际执行使用相同请求。摘要覆盖有序消息、媒体内容与位置、实际输出 schema、连接方言、模型及有效参数。执行时不重新解释任务模板或自动换模型。明确允许的备用调用重新准备兼容资源；宿主接纳后的模型切换重新准备输入。

成功返回 ModelResult(output, producer, usage)。ModelProvenance 保存实际模型、任务、Prompt/Schema/输入/输出摘要及生成时间；采用者同时绑定实际来源引用。结果缓存和临时 trace 可淘汰，正式材料、派生及认知保持自身生命周期。付费预约、每日请求账本、调用托管和跨安装付费历史退出，后台继续使用 DBOS 业务工作状态。

### 供应商与媒体

业务输入表达任务、MediaReference 和 Region。Provider 连接选择实际 API 方言，常见服务由连接预设填好，未知兼容网关由管理员指定真实协议。ModelResource 不保存 video_url、HTTP 子路径等 wire 规则。供应商参数与实际请求可以在连接设置及诊断中查看。

Pydantic AI 已支持的模型直接采用。兼容视频只在模型边界补必要的 content part 映射，文本、图片、视频共用 Pydantic AI 的消息、NativeOutput/ToolOutput、结果和用量。其现有 [多模态支持范围](https://pydantic.dev/docs/ai/core-concepts/input/)和 [OpenRouterModel 的视频映射](https://github.com/pydantic/pydantic-ai/blob/main/pydantic_ai_slim/pydantic_ai/models/openrouter.py)提供实现依据；按实际方言复用映射方法，不把其他服务伪装成 OpenRouter。删除 complete_video 的第二条生成执行与手工 schema 链。供应商协议不会进入 Cognition、Formation、Material 或普通 SDK 任务合同。

原生视频能力取模型与连接实现的交集。只有图像能力时，FFmpeg 提取带时间位置的画面并按需要处理音轨，保留原件来源。媒体 resolver 提供实际尺寸、时长和页数，执行器按模型规则估算预算；某段短视频的固定估算不能变成任意视频的模型属性。真实 Token 与费用来自提供方结果。

多模态 Embedding 接收有顺序的文本/媒体组，返回每组在声明空间中的向量、实际模型及用量。标准文本批量与混合内容联合向量具有不同 API 合同；[Pydantic AI 的文本 embedding 客户端](https://pydantic.dev/docs/ai/guides/embeddings/)不能代替混合输入协议。供应商路径、内容映射和响应解析归具体执行实现，维度、归一化与空间由模型 owner 维护。

description_only 形成可读描述；direct_structured 执行当次明确目的的小任务；describe_then_structure 保存描述，再让当前任务同时读取描述与必要原媒体。已有描述直接复用，两次调用各有 producer 和实际输入链接。

## Wave、NousQL 与索引代际

Wave 接受自然语言或 NousQL、可选 QueryContext、媒体、目标域、时间/历史、预算及严格/允许退化策略，返回共同候选合同下的内容、引用、来源与执行信息。

自然语言是一等完整查询。已知人物、事项和时间时建议调用方明确指称；原始代词、省略和各种语言均可直接检索。程序解析显式选择器、引用和名称，名称歧义返回候选；不使用代词正则和自动替换模拟语言理解。

QueryContext 提供当前任务、已知实体、时间、已有引用、附件及未解问题，可由可信宿主自动携带。VCP 也能直接使用查询向量、明确 Concept/Tag/Entity 和实际拓扑，无需强制外加会话情境。

确定计划执行词项/精确、向量、实体/时间及图/VCP 候选，复用同次读取的来源事实，融合去重后重排和阅读。同一对象多路命中保留一个身份。确定性计算、专用 reranker 和可选生成重排消费相同候选，不修改正式认知。

IndexGeneration 保存检索资产、正式提交覆盖水位、空间和构建状态。采用认知时同事务安排投影，后台发布新代际；前台使用已有资产与确定增量，避免每次对全库哈希或重建图。新的逐条 Memory、直接来源图结果和修订进入同一更新路径。

Wave 的候选与查询执行只读，内部调用直接取得精确目标，不保存面向用户的 qN:n。ReferenceDirectory 在产品查询结果交付边界保留需要继续 read 的结果，CLI、MCP、HTTP 和 SDK 使用该完整操作；不增加让调用者控制内部保留过程的公共 retain 开关。保存查询句柄的提交不代表认知数据发生变化，不能触发新投影或图重建。IndexGeneration 的覆盖责任是正式资料和认知变更，更新由这些变更 owner 的投影请求驱动，不凭 Authority 时钟单独增长推断索引过时。

缺某个模型时已有通道保持正常用途；严格请求明确返回缺失能力。trace 展开 AST、绑定、通道、图路径、融合重排、覆盖及成本。普通结果只展示内容、必要时间、来源和继续阅读的位置。

语义吸积依据真实概念、共同来源、接触和有意义使用维护可重建检索中心与拓扑。长期关系、认识状态和来源继续由领域保存。不同向量空间分别索引，在融合阶段组合结果。

## ContextRuntime 与连续工作

Session 拥有状态、修订、当前 Work 引用、Resident 和宿主实例设置。Call 保存一次 invocation 的原始输入、实际发送输入、选择 manifest、来源绑定、measurement、父调用/代际、状态、完整输出及用量。prepare、sent、complete 修改同一 Call，删除 managed/preparation/admission/report/track 平行持久状态及消费循环。

WorkContext 有独立身份和修订，保存目的、决定、进展、未解问题、约束、锚点与继续条件。暂停或更换 Session 不改变任务本身，经授权的不同执行者可继续同一工作；临时 caller 和模型不会成为另一份工作数据根。

Resident 保存当前易于使用的资料及认知引用、进入原因、有效期和使用信息，由 Session owner 修改。长期认知、当前工作和实际模型窗口按引用连接，发送时的文本渲染不反向成为新的长期权威。

### 宿主正常循环

~~~text
绑定 Namespace、会话、实例、用途和听众
  → before_model(真实请求、原事件、当前任务)
  → prepare 返回实际输入与 call_ref
  → SDK 在真实发送位置记录 sent
  → 宿主执行模型和工具
  → after_model(完整原生回复、实际结果与用量)
  → 下一轮或切换工作
~~~

SDK 的 hook/模型 wrapper 自动接通此循环。模型不手工调用内部管理工具。宿主原生 assistant、tool、reasoning 结构与协议 ID 原样传输，输入编译不把它们扁平化为纯文本。call_ref 可读取实际输入及其精确来源。

HostEvent 保留原 event_id、role、完整 payload、可读文字和工具/响应身份，并共用事件作者、观察者、群体、时间及回复关系合同。before_model 可携带真实原事件；仅有原生模型请求时保存本次实际输入快照，保留未知人物与时间。接触事实由真实观察者及发送边界确定，协议 role 不承担此判断。

事件接纳共用 Material/Observation 完整操作，原件、明确接触事实、确定性表示及待形成范围同事务提交。Formation 消费来源范围，模型在事务外执行，领域采用在后续短事务完成。complete 接纳真实回复、更新同一 Call 及必要的居民/工作引用，不自行实现接触规则或逐事件模型调度。异常与恢复在同一状态上补全。

### 程序选择与 Steward

选择能力读取 Work、适用 Ego/Social/Motivation、Resident 和 Wave 候选，返回不可变选取结果。程序控制检索次数、候选规模、Token、来源、状态及最终输入。LLM 处理有完整背景的相关性选择、指定主题摘要和未解问题概括。

稳定任务、工具定义及稳定 Ego 保持前缀，本次用户内容、检索补充和工作变化进入合适的后续角色。每轮普通输入不强制增加一次总结。

压缩时由程序指定已完成原生消息的精确范围、覆盖引用和输出预算，模型阅读实际原文。未完成工具轮和调用/结果配对保留；Call 保存摘要及覆盖关系，退出窗口的原文仍能按引用取得，摘要不写成新的亲历。

## 长期领域与真实反馈

Ego 保存稳定自我认识、Seed、facet、知识能力范围、例外及叙事。Seed 保留创作原文与版本，设定经历具有创作来源。Host 执行角色属于本次用途，Work 属于任务事实，二者不自动变成主体人格和人生经历。

Social 保存具体人物、群体、方向/情境明确的关系与跨平台身份认识；账号原事实留在来源。LanguageConvention 根据真实解释、使用和纠正维护词语及媒体符号在特定圈子的含义。客观画面描述与社会含义分别形成，普通措辞无需全部升级为黑话。

Motivation 保存愿望、关切及可评价期望，表达达成、维持、避免、终止和 unknown。Nous 提供认识，Heptalogos 决定实际投入、追求及承诺。

Episode 直接从真实 Observation 和工作事件组织经过，Memory 可作为其中的认识成员。Journal 在回顾目的下组织实际经历；Work 摘要更新任务状态。反思比较新旧认识和反例，Dreaming 使用既有后台执行做有界模式探索，保留假设及来源。领域决定采用与修订，前台继续工作，后台消费相同材料和认知。

进入模型输入、模型实际接触、被引用、真正采用、产生结果及得到社会反馈分别记录。长期变化由这些实际材料支持，而不会把模型反复复述当成新增独立证据。

## 稳定引用与自然交互

### 可读地址与精确身份

ReferenceDirectory 使用现有 48 位、三组 CVCVC 的 Proquint 编码分配可读地址，例如 mem:badif-guhaj-kilom。地址随机分配并持久绑定，数据库唯一约束处理碰撞，不截取 UUID。字母表及编码参见 [Proquint 原始实现](https://github.com/dsw/proquint)。三组短词适合复制、逐组口述和核对；正式身份仍由目录解析。

对象地址如 mem:… 跟随同一认知身份，解析当前可见修订；精确地址如 memrev:… 绑定一个确定修订。Material、Region、Representation 等具有清楚的类型前缀。正式证据使用精确修订，同一地址不静默换绑另一对象。

地址在 Namespace 内解释。跨客户端使用时绑定相同数据域，跨域交付同时携带 Namespace 定位。slug 服务于选择认知域，显示名称和人物名字服务于阅读与查询，不承担唯一对象身份。

### 查询句柄与 Runtime 来源键

qN:n 表示第 N 个已保留查询结果中的第 n 项，n 从 1 开始，固定到该次返回的精确目标。N 使用现有唯一 query handle 编号，不要求它等于当前会话查询次数。目录按 Namespace、caller 和 qN 绑定结果；同一凭据跨命令、进程继续 read 无需额外引用会话身份。

后续查询不覆盖旧结果。每次 read 重新解析并按当前范围读取目标，不能使用全局“最近第二项”。CLI、MCP、SDK 均可交付同一句柄。需要继续读取的产品结果在交付边界保留句柄；内部 Wave 候选与 Steward 检索无需为此增加写事务或推进认知数据代际。

cN 是 Runtime 绑定会话内的来源缩写，作用域含 caller 与 Session，解析精确目标。跨会话交接、长期记录和分享使用对象/精确地址，临时往返使用 qN:n 或当前 cN。

### 规范操作与不同呈现

#### 共享数据合同与执行责任

MemoryBody、CognitiveRecord、TimePoint、正式引用及公开命令/结果是原生业务的数据合同。它们表达可交换的数据形状和通用值约束，例如时间范围有序、必需字段存在。公共数据形状由对应原生业务维护；认知修改、来源授权、修订冲突、采用策略与事务提交由服务端领域 owner 决定和执行。

公共值模型在 nous_sdk.contracts 保持单一定义。服务端与客户端均可直接使用这些纯 Pydantic 值，不为相同内容再造领域模型、HTTP DTO、SDK DTO 三份转换。SDK 的网络客户端、传输配置与连接生命周期留在客户端模块；导入公共合同不初始化网络客户端，也不加载 Nous 的数据库、执行器或服务组合根。纯值格式化与可读呈现函数可以共用。

外部集成者只需安装 SDK，使用客户端和公开值合同即可连接本地或远端 Nous。SDK 不依赖服务端；服务端领域只消费其中的纯合同，HTTP、SQLAlchemy、DBOS 等执行依赖由服务端自己持有。共享类型与运行客户端按模块责任分开，纯合同随 nous-sdk 分发，当前不新增 contracts 发行包。[Qdrant 本地执行实现](https://github.com/qdrant/qdrant-client/blob/master/qdrant_client/local/local_collection.py)也直接使用其客户端包中的公开数据模型，可作为复用单一数据合同的实际参考。

可信 CallContext 是服务端构造的执行上下文，包含认证身份、来源权限及本次调用范围；EpisodeRebuildIntent、PersonProfileRefreshIntent 等后台 Intent 保存恢复工作所需状态。这些类型归服务端对应 owner，迁移实际使用者后删除 SDK 旧定义与导出。客户端提交公开业务输入，服务端从认证与绑定建立可信上下文。领域异常服务于本体业务决定，公开错误码与负载属于协议合同，客户端异常负责远端调用失败；它们按实际构造与处理责任放置，共享必要错误数据。

#### 本地管理与远程操作

部署与调用按实际用途组织：

- nous init、serve 等本地安装和服务管理直接使用本机实例与原生组合根，完成初始化或启动，不需要先连接一个已运行的 HTTP 服务。
- 在线 CLI 命令使用 NousClient 连接所选地址，复用认证、序列化、上传下载、错误解释及公开操作。服务位于本机或远端时使用相同调用路径。
- MCP 面向 Agent 提供紧凑工具，由第一方 MCP 服务使用同一客户端连接 Nous。MCP 可以部署在 Agent 所在设备，认知数据和后台工作仍由所连接的 Nous 持有。
- HTTP 路由验证和解析公开输入，建立可信上下文，直接调用 Application 中的领域 owner。Cognition、Material、Wave、Runtime 及后台作业通过原生能力协作，不经 NousClient 向本服务再发送一轮 HTTP。

CLI/MCP 作为远程客户端复用 SDK，服务端内部复用领域操作，双方共用纯值合同。这一依赖方向保留一个业务实现与一套客户端传输机制，无需为了让所有入口看起来相同而统一成网络调用。

#### 连续操作与结果

SDK 绑定连接、身份及 Namespace 后调用 remember、ingest、query、read、correct、history、work 和 runtime，返回类型化完整结果；工作会话仅在相关操作绑定。删除同一操作的历史别名和重复读法，客户端不读取本体私有表。

HTTP 使用 /api/knowledge、/api/runtime、/api/manage，分别提供知识操作、真实宿主运行和管理能力。完整 DTO、可读视图与 trace 按需要展开，不建立平行业务实现。

CLI 保存连接、当前 Namespace 和 Work，允许显式覆盖。正常流程是：

~~~text
nous init
nous use <namespace-slug>
nous import ./notes.md
nous query '这份资料对事务所有权作了什么决定'
nous read q123:2 --sources
nous correct mem:<可读地址>
nous work show
nous work resume <work-ref>
~~~

默认结果有正文、短引用、必要时间、来源和处理状态；JSON 输出完整 DTO，trace 展开执行。普通操作无需手写 UUID、operation_id、哈希或大份请求 JSON。

MCP 围绕查询、阅读、记住、纠正、导入、关系、媒体、工作与状态提供少量工具。description 说明何时调用、引用从哪里取得、修改什么及怎样继续。content 和 structuredContent 均用紧凑视图，详情通过 read/资源链接取得；内部模型调用步骤与全量管理方法不进入普通工具目录。

NousQL 手册随 CLI 帮助、MCP 资源和 SDK 指南提供，覆盖自然语言、引用、时间/历史、实体/Tag、关系、媒体和继续阅读。安装与使用指南随真实入口维护。

## 配置、来源生命周期与演进

TOML 保存期望配置，ConfigurationValues 为各消费者共享校验后的有效快照。default、instance、Namespace 按明确范围合并。CLI/HTTP/SDK 修改经过同一 owner 校验、原子写文件并发布整份快照，读取提供有效来源与生效信息。

文件读写退出认知 SQL 事务。模型、形成、检索、NamespaceLimits 共用快照；一项操作在所用配置下完成自己的业务判断。备份直接保存当前 Namespace TOML，恢复通过配置 owner 校验发布。SQL 配置副本、泛化历史和旧 restore_in 路径退出。

正式资料、认知和已采用模型结果按业务生命周期保存。来源 owner 根据正式依赖计算受影响的区域、派生和认知，在一次 Authority 事务提交来源可见性、必要认知变化及清理工作；不由 Application 手工遍历所有服务拼装删除。读取依据权威当前状态，索引尚未清理的候选也要经过同一来源读取。原件字节在正式引用解除后由内容 owner 回收。缓存、trace、导出和索引各自保留或淘汰，当前版本备份、Bundle 和导出服务实际迁移。

开发中的内部接口、数据和协议没有兼容保护义务。修改定义者并迁移全部生产者、消费者、动态注册、配置及文档，删除旧接口、内部别名、桥接、旧 schema 升级和专属支撑。A-Memorix 公共协议及实际供应商 API 属于外部边界，按其真实合同实现。

以已有可运行能力继续完善 Nous：原生数据与操作、模型、Wave、长期领域及四类入口沿完整使用共同修改；清尽全仓旧结构不成为下一项功能前置。正常产品完整后，补必要异常与边界、小规模公开测评、跨平台安装与交付说明。独立 SDK 发行与 SDK-only A-Memorix 适配后移，Heptalogos 随后在自身仓库完成主体循环、MaiBot Hook、Dashboard 和 Nous 接线。
