# 整体架构与模块合同

## 产品目的与确定的形态

Nous Wave 是长期认知服务，既能独立提供 memory-only，也能按需启用完整人格与认知领域。Heptalogos 是持续主体的世界、生活、交往与行为系统。两者拥有同一个逻辑 Subject 身份，各自持有业务事实、数据库、配置实例与生命周期。

产品采用两个 TypeScript 7 / Node 24 模块化服务。普通模型工作直接用 AI SDK；持久等待、长工作及恢复使用 DBOS；数据库与事务采用 PostgreSQL/Kysely；完整专业执行继续由 OpenClaw 负责。原算法的 Rust 数值代码作为普通同进程 native 库保留，不再启动旧 Kernel/RPC 服务群。

这一形态承接[宪纲](../项目宪纲.md)、[完整能力清单](../研究/目的与能力保全.md)和本轮源码研究。语言与内部划分可以随明确复用收益调整。已经选择的技术与移植切口见各基础设施 Spec，后续不以语言统一为由重写成熟执行器或丢弃有效算法。

## 部署与发行单元

| 单元 | 作用 | 自身的数据与运行 |
|---|---|---|
| Nous Host | 认知业务、资料、查询、形成/维护及管理API | 独立产品库、Blob、Serving与运行资源 |
| Hept Host | 世界生活、主体前台、交往、任务、表达效果及管理API | 独立产品库、世界/消息/任务与原件 |
| @nous-wave/contracts / client | 公共纯值与Nous正式SDK | 无业务状态；普通ESM发行包 |
| @nous-wave/platform | 成熟依赖的共同组合与必要通用机械 | 每产品各自创建实例和存储，不保有两边业务状态 |
| @nous-wave/management-ui | 从AstrBot改编的通用Vue/Vuetify管理功能组件 | 纯呈现与传入Client，独立许可和来源 |
| retrieval-kernel | 原Native/VCP数值、矩阵、图与内部ANN实现 | 无权威业务状态；napi-rs标准addon |
| OpenClaw runtime | 原生任务、工具、Computer Use、Skills、历史、沙箱和channel | 原生state、session/run和工具环境 |
| 默认OneBot channel | 现成OpenClaw OneBot源码fork，接入Hept的完整消息与效果 | 平台连接与原生交付机械；Hept保业务事实 |
| AstrBot可选插件 | 既有通信接入成果 | 明确选择时使用其原生渠道；不作为Hept产品宿主 |

没有第三个持有两边业务状态的通用服务。标准外部PostgreSQL、模型服务或原生运行器是实际采用的依赖，不代替产品语义owner。无渠道和专业工具需求的独立Nous安装不需要OpenClaw或AstrBot。

## 代码组织

Nous仓库的计划结构：

```text
apps/server/       产品HTTP、认证适配、静态Web与组合根
apps/cli/          确定性CLI及离线入口
apps/web/          Nous专有页面与可嵌入认知视图
packages/contracts/  纯共同值及Nous公开Zod合同
packages/client/     OpenAPI生成Client与共同Problem中间件
packages/platform/   共享基础模块的普通库
packages/management-ui/  实际复用的Vue功能组件
packages/nous/src/
  identity/ material/ source/
  memory/ episode/ journal/ schema/ concept/ association/
  self/ social/ language/ motivation/
  cognition/ work-context/ formation/ resources/ retrieval/
packages/retrieval-kernel/  原数值内核的最小Rust库与napi绑定
packages/nous/migrations/  Nous业务迁移与本产品platform表迁移
packages/nous/prompts/     本产品角色的默认资源
integrations/      OpenClaw认知插件及选定源码改编差异
```

Hept仓库保留自己的apps/contracts/client/migrations/prompts/integrations；领域位于`packages/hept/src/`下的identity、world、calendar、living、attention、agency、work、communication、narrative、pursuit、commitment等真实职责。源码中的小函数可以同模块合并，不为每个概念强制建一个package或转发文件。

共同库按独立入口导出：bootstrap、settings、credentials、network、models、prompts、storage、operations、telemetry、time、data与纯contracts。入口只加载自身所需依赖，浏览器不会因导入共同类型而引入pg/文件/原生包。库没有PlatformKernel/万能Manager，也不替产品注册业务能力。

platform直接迁入Hept的AGPL-3.0-only代码，整体采用AGPL-3.0-only发行，并保留原Nous Apache-2.0文件的来源与许可。management-ui保留AstrBot AGPL来源；产品组合发行使用相容的AGPL许可。未包含Hept代码的纯contracts/client可独立保留Apache-2.0。具体文件来源随复制清单保存，不为许可证标签统一而重新实现成熟代码。

业务操作、领域类型和事务留在产品。基础库保存的是本实例的配置、通用资源修订和连接机械；Role内容、资料政策、期望条件、世界映射、成长、任务和表达含义不进入共享底座。产品组合根静态组装真实依赖。

## 领域的唯一责任

| Nous owner | 正式长期事实与操作 | 直接消费者 |
|---|---|---|

| Material/Source | 原件、表示、区域、派生谱系、来源根、当前来源读取与实际接触 | 形成、查询、模型、媒体、数据清除 |
| Memory | 同一认知事项、立场/角色、来源、修订/支持反驳、可访问性 | Query、Context、Reflection |
| Episode/Journal/Schema | 多轨分段、成员/层级、日记视角、模式/例外与变化 | Query、反思、自述、维护 |
| Concept/Association | Tag身份/含义、membership、合并/拆分、真实关联证据 | 绑定、通道、数值Serving与维护 |
| Self/Knowledge Profile | 自我事项、叙事、知识范围、认识充分性及例外 | 审议、表达、学习、Context |
| Social/Language | 定向关系、社会scope、人物认识与语言惯例 | 注意、理解、听众和表达 |
| Motivation | Desire/Concern/DesiredCondition、条件与覆盖评价 | Hept追求、机会、反思 |
| Cognition/WorkContext | 活跃工作集、目标、当前问题、引用、继续线索与完整语义投影 | SDK调用前prepare、查询与持续任务 |
| Formation/Maintenance | 实际经历的形成编排、原成果、原子采用组与局部冲突继续 | 成长、日记、整合、反思与有界探索 |
| Query/Retrieval | NousQL、绑定/查询计划、候选通道、排序、结果继续；可重建Serving资产 | CLI/MCP、Context、形成、Hept |

各领域保有自己的Zod对象和完整修改操作，公共读取汇聚可以根据真实kind分派到owner。通用revision SQL是私有机械；`knowledge.create/revise`这样的万能写入口不再替代Self/Social/Motivation等领域规则。

| Hept owner | 正式事实与规则 | 与认知的交接 |
|---|---|---|
| World/Clock/Calendar | 世界/人物、带域分段映射、日历、计划与已实现事件/见闻 | 提供实际世界来源、TimeCaptureReceipt及知情范围 |
| Living/Activity | 身体活动、精力/负荷、渠道和设备、切换/恢复 | 当前生活情境与真正参与结果 |
| Attention/Reactor | 多来源机会、通知/扫视/阅读区别、同一主观前台与决定 | 取适用认识、提交实际消费与反馈 |
| Pursuit/Commitment | 已采纳投入、进展、特定听众责任、改约与履约 | 关联Motivation和真实结果 |
| Work/Native Task | 正式任务目标、范围/预算/returnTarget、native run与待看成果 | 精确发布并实际查看的内容进入接触 |
| Communication/Media/Identity | 完整消息和平台身份、原件、转发、补拉及当前政策 | 正式来源，不将收件当已读 |
| Narrative/Renderer/Claim | 可披露意图、原表达、生活细节采用、具体说法与后续澄清 | 使用相应认识；实际对外结果回流 |
| Effect/Delivery | 每次物理提交、当前发送授权、accepted/not_sent/unknown | 已发生效果先保存，后续整理独立继续 |

## 底座合同与依赖方向

| 底座模块 | 提供 | 谁定义语义 |
|---|---|---|
| bootstrap | 逻辑Paths、启动/服务、依赖获取和离线管理适配 | 产品生命周期与OS权限 |
| settings | Schema目录、稀疏覆盖/求值、修订/来源/生效视图 | 各模块定义字段、范围和变更反应 |
| credentials | Better Auth、服务委派、SecretRef及withSecret | 产品授权操作和资源/资料owner |
| network | 成熟Dispatcher/代理/流/取消的资源客户端 | 目标资源及当前委派 |
| models | SDK Provider/Model/Role、调用快照、用量与费用机械 | Role owner的任务、输出合同与授权 |
| prompts | 文件资源迁入、版本/覆盖、渲染/预览/激活 | Role拥有Prompt正文与变量含义 |
| storage | pg/Kysely/官方datasource、迁移和普通事务 | 各领域的表、完整操作和实际不变量 |
| operations | DBOS状态、等待/取消/恢复与可读投影 | 实际长工作的owner及效果恢复规则 |
| time | Temporal、微秒/区间与期限纯运算 | Nous通用认知时间；Hept世界映射各归owner |
| telemetry | Pino/OTel、稳定Problem、安全本地诊断 | owner定义错误、费用、来源与状态含义 |

方向为入口→完整业务操作→必要底座。Query读取领域的正式元数据/内容；Context使用Query与领域describe；Formation调用模型并采用各领域命令；领域变更返回正式cursor，提交后由DBOS父工作继续Serving更新。领域对象不反向依赖具体Lance/Provider实现。

只为不同实现、外部系统或实际跨owner边界设置接口。普通私有helper不生成Service/Adapter/Bridge/Facade链。内部SQL和文件路径从不成为另一个业务owner的调用知识。

## 两产品连接

共享的是Subject身份与正式纯值。跨产品连接保存对端installation、baseURL和授权引用，通过版本化Client协作；禁止读取另一产品数据库、secret路径或开发源码。

Hept独立模式使用自己的种子资源和近期事实，长期认知能力明确不可用。绑定Nous后由其正式Cognition/Query提供长期认识和当前Self等视图；原种子仍是创作来源，不再把当前Self复制回Hept可变配置。连接中断时显示受影响能力，不偷偷改用另一份过时人格。

Hept为Nous提供实际Message/Event/成果来源的当前权限和WorldClock捕获。Nous在读取、查询结果返回和实际模型派发时按原owner当前限制校验；来源引用和一次复制的Policy不是永久授权。独立Nous的资源来源仍由其自身Material/资源连接owner管理。

联合Web通过正式SDK访问两产品，分别使用它们的真实用户会话/授权；管理组件只展示聚合视图。服务级广域密钥不进入浏览器。

## 模型、上下文与原生执行的真实时序

普通角色使用AI SDK的完整消息/工具循环，平台只处理资源/Prompt/配置与实际调用边界。Context准备在本次实际输入确定后执行；输入变化时重新准备。保留原step.messages、工具调用/结果、有效历史及角色来源，不用占位user消息覆盖它们。

每次真实调用都关联Consumer、Role、Provider/Model、Prompt版本、配置快照、当前认知贡献、原生/SDK运行和实际结果。输入准备不产生Subject经历；结果/实际消费被所属owner接受后再形成对应Encounter。worker、author与maintenance的私有过程保持原范围，选定成果发布/查看后才进入Subject自己的接触。

OpenClaw负责专业任务的原生loop、子代理、压缩和保存。在真实prepare/dispatch/terminal持久保存/accept位置改编，辅助压缩调用同样经过本次职责。只有一个认知slot和一个实际计费owner。原生历史保存自己的消息，Nous仅保存所需来源/消费引用与选定正式材料。

当前限制变化必须作用于后续原生输入；原生压缩结果保留来源依赖。无法安全排除已撤权历史的harness暂停该调用或在原owner建立合法新上下文，不能靠再次注入一句提示抵消旧正文。

## 事务与恢复边界

普通读取与短修改由领域Kysely事务直接完成。同库需要原子采用时由真实编排者传入同一事务client，领域完成各自规则；不让调用方自行写其内部表。

只有长期工作、模型/外部调用、持久等待与恢复进入DBOS。官方datasource使业务采用与该步骤检查点同事务提交。模型与网络不在SQL事务中；跨库不宣称全局事务，接收方按同一operationId提供幂等完整结果。

ModelInvocation、EffectReceipt、ClockCapture和原子采用结果是有产品含义的长期事实；DBOS的临时checkpoint与运行状态不替代它们。原生/远端已执行而结果未知时保留原身份，核实后继续后续工作，不生成新的请求假装是恢复。

这些规则的具体SQL、序列化和源事实已在[存储事务](基础设施/存储事务与缓存.md)、[模型调用](基础设施/模型供应与调用.md)、[时间](基础设施/时间与调度.md)、[媒体效果](基础设施/媒体与材料基础.md)中确定。

## 源码搬入与替换

1. 先复制原Nous PromptRegistry和资源、NousQL三文件、数值模块/配置/判别样例、时间/引用纯值和有效领域合同；在真实owner改import、储存和接口，避免先从简化草稿补缺。
2. 迁入旧Hept保真消息、forward/media/history/calendar/living等有效处理；默认Channel在现成OneBot插件真实HTTP/WS和物理call owner改编，不搬旧传输/队列/fence。
3. 共享底座直接采用成熟库，通用Vue功能组件从AstrBot真实组件与依赖闭包改编；可复用的MaiBot Focus/表达算法归Hept相关owner。保留原许可证和来源。
4. 删除旧Core/Kernel私有RPC、重复DTO和无消费者运行支架；替换当前重建的FIND DSL、硬编码Prompt、单一Chat模型资源、泛化内容对象和单公式时钟。
5. 当前有效流式Blob、批量/游标读取、实际模型成功结果保存、私有成果发布和小型真实场景继续迁入；新消费者同步使用正式结构，旧接口/转换和相关支架随之退出。

逐文件处理和算法闭包见[能力保全与纠偏](能力保全与现有代码纠偏.md)。源码改编维护必要差异，普通依赖由包管理器和锁文件更新。

## 规划到施工

先让两个产品各自初始化和管理底座可调用，再配置/权限/秘密→网络/模型/Prompt→时间/执行→诊断→管理→数据/发行，最后接回完整领域消费者。每个单元交付其真实服务和少量能区分重要失败的场景，细节见[施工顺序](../施工顺序.md)。

当前研究与设计已提交，基础设施施工由当前工程直接实施。先完成[23类基础能力](基础设施/施工总览.md)的真实底座和消费者接线，再恢复完整领域功能施工，保留全部既有能力和最小必要自有机制。
