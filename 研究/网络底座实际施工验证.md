# 网络底座实际施工验证

2026-10-21，Node 24.21.0，Undici 8.10.0；生产实现位于 Nous 的 `packages/platform/src/network/`。共享代码直接消费 Undici Dispatcher/Agent、Node 原生 Fetch 与 Web Streams。SOCKS5 使用 Undici 的实验性接口；SDK 对 IP 目标 TLS SNI 的弃用提示仍按原生状态输出。

- Undici 8.10.0 / `c8d80e6b2dcfab282557b08f51352937bc9e5692` 的 `lib/dispatcher/env-http-proxy-agent.js` 路由函数复制到 `network/environment.ts`。保留其 NO_PROXY 的域名、端口、IPv6、大小写与空值规则，只将选中的 Agent 改为返回选中 URI；MIT 许可已包含于 platform/NOTICE。

## 真实场景结果

完整实验脚本在工作区 `temp/network-infrastructure/scenario.mjs`，使用新建 `hept_network_infra` PostgreSQL 18 数据库中的真实 Auth、Settings、SecretRegistry。测试宿主只监听本机随机端口，结束时关闭全部监听、连接与计时器。测试代理使用 Node HTTP 的真实转发/CONNECT；SOCKS 和 WS 的服务端采用临时安装的 `socksv5 0.0.6`、`ws 8.22.0`。

| 链 | 实际结果 |
|---|---|
| 保存 Network profile → 注册消费者 → 创建客户端 | 使用真实 Settings CAS/冻结修订；报告实际 applied |

## 实施中核定的接口事实

`ResourceNetworkScope` 使用真实 `resourceRef` 和宿主指定 `operation`。`network.client(ctx,{resource,scope?,deadline?})` 返回原生 fetch、异步 `webSocket()`、metadata 和 `close()`；`withClient` 包住实际 SDK/流消费期。客户端关闭取消其活动请求；池生命周期中的秘密保持在正式回调内，每次派发还重验当前 generation。

`EnvHttpProxyAgent` 没有公开 route 查询方法，因此采用上述源码改编。HTTP/HTTPS/NO_PROXY 同一次快照既用于其原生构造，也用于地址能力判断及池缓存键。只有实际选中的远端 DNS 代理线路需要 `authorizeProxyRoute`，本机直连沿真实 connector lookup 校验。

SOCKS5 的 `proxyTls` 一旦给出，Undici 就按 TLS 代理连接。plain `socks5://` 不传此项，目标证书通过 `requestTls` 提供；这个区分已经由真实 HTTP/TLS 场景核定。
