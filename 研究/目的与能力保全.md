# 产品目的、已有能力与重整对象

## 重建要改善什么

项目要维持跨模型、会话、平台和时间的同一个主体，并让通用记忆应用也能独立使用 Nous。主体的身份、认识、生活、社会交往和已经作出的行动各自延续；软件本身能安装、配置、诊断、恢复和更新。这些是重建完成后的产品结果。

重整的对象是实现这些结果的内部结构。原实现中，完整操作被拆到多个 package、私有 RPC、Host 回调与持久步骤之间；同一规则有多处调用方解释；相同事实经多个 DTO、缓存、事务对象与展示结构循环转换。删除这些机械后，既有功能与研究仍应有明确消费者和操作入口。

[宪纲](../项目宪纲.md)第 1、3、13、15、18、19、33、45—48 节定义这一目标。当前工作先研究目的、原源码及可直接采用的第三方，再完成基础设施方案。研究与实施由当前工程继续推进。

## 两个产品的独立价值

| 产品形态 | 用户能够完成的事情 | 基础设施必须支持 |
|---|---|---|
| 独立 Nous，memory-only | 为普通 Agent 建主体，接纳资料和实际消费，形成与修订记忆，自然查询、精确读取、追溯来源和历史，导出继续使用 | 无须启动 Hept、人格、世界或 OpenClaw；完整配置、Provider/Model/Role、来源权限、查询时间、持久状态与管理入口 |
| 完整 Nous | 在同一主体上组合 Memory、经历、日记、图式、概念、社会、自我和动机，按情境进入实际模型输入并持续维护 | 领域可选供给、领域专有类型、统一来源/修订机械、知识立场、Prompt 资源、实际消费反馈和可重建 Serving |
| 独立 Hept | 创建主体与世界，使用日历、会话、注意、活动、任务、表达和管理；按自身资料与近期事实运行 | 本地身份、世界时间与状态不依赖 Nous 可用；对外认知连接作为明确能力启用 |
| 联合主体 | 同一 Subject 的生活、实际接触、长期认识、选择、行动与反馈连续发生 | 两个数据 owner、正式生成 Client、独立构建 SDK、当前政策/来源时间与引用，无跨库共享内部表 |

Nous 的独立性包括不具有世界的人、工作流和 Agent 的时间需求；Hept 的独立性包括没有长期认知连接时仍可管理和运行自己的世界与交往。完整人格组合不应成为 memory-only 的启动门槛。

## 已有功能的保全依据

保留的默认对象是用户可观察的能力、精确语义、有效算法、实际资源和研究成果。是否移动目录、改语言或替换数据库形状，依据其职责和维护成本选择。

| 能力族 | 必须继续表达的含义 | 主要消费者 |
|---|---|---|
| Material / Source / Occurrence | 原件、版本、选区、派生、真实来源与来源独立性；资料存在、系统取得和 Subject 实际消费分开 | 形成、检索、模型输入、媒体、管理、清除 |
| Memory | 同一认知事项的身份、认识角色、立场、支持/反驳、修订、抑制及删除 | 查询、上下文、反思、知识范围 |
| Episode / Journal | 多轨道/层级事件组织、可修订分段、实际日记与当时立场 | 回忆、日末整理、自述和长期学习 |
| Schema | 有情境、支持与反例的模式，收窄、拆分和修订 | 判断、探索、学习和反思 |
| Tag / Semantic Concept | 稳定概念身份、可演化含义、direct membership、语义词与概念吸积 | NousQL 绑定、通道、图与维护 |
| AssociationEvidence | 明确关系、支持来源、共同根、独立性和有意义使用 | 拓扑、排序、解释和认知维护 |
| Self / Knowledge Profile | 身份、价值、偏好、能力范围、经验程度、疑问与认识充分性 | 审议、表达、学习和可读人格 |
| Social / LanguageConvention | 定向/情境关系、人物资料、账号线索、群体语境、语言约定的形成与修正 | 注意、消息理解、听众选择和表达 |
| Motivation | 愿望、关切及 achieve/cease/maintain/avoid 条件；充分/不足观察下的满足、违反、未知 | Pursuit、机会、反思、长期评价 |
| Active Cognition / WorkContext | 刚接触内容、当前易想起内容、多个持续任务的目标、进展、引用和恢复线索 | 模型每步准备、查询、工具后续、跨会话继续 |
| Accessibility / Accretion | 使用与来源证据分别作用，可访问程度与真值不同；概念中心可演化 | 检索、反思、维护、显式精确读取 |
| Consolidation / Reflection / Growth | 根据真实经历与反馈组织、形成、比较、修订、保留疑问和有界探索 | 前台后续、后台机会、预算和诊断 |
| NousQL / Retrieval | 自然语言与原正式语法岛、身份绑定、歧义、五轴与历史、返回域、投影、继续展开；完整多通道与研究算法 | Agent 工具、官方 Client、认知准备、独立应用 |
| WorldProfile / WorldClock | 世界设定、时间域映射、修订分段、暂停/速率/离线、高水位与期限投影 | 日历、事件、Life、Reactor、历史 |
| Calendar / RealizedEvent | 计划与已实现历史分别存在；原实例、例外、参与结果、局部视角与未实现缺口 | 世界推进、主体生活、情境与查询 |
| Activity / Attention / Reactor | 身体生活、主观前台、通知与实际阅读、切换和恢复；全部来源竞争同一个主体 | 消息、世界、任务、追求、承诺和自主机会 |
| Pursuit / Commitment | 心中愿望、正式投入、对特定听众承担的责任分开；条件、期限、改约、履行与未知 | 生活计划、审议、表达与评价 |

## 少数完整路径决定底座形状

### 修改设置后执行一次真实模型工作

管理员在 CLI 或 Web 改 Role 参数或 Prompt 覆盖。产品保存稀疏修改与修订；当前工作取得一份有效配置和确切 Prompt 版本；Provider 创建适合资源权限的网络客户端。上下文 owner 只提供自身负责的语义贡献，最终 SDK 消息、历史、工具仍完整存在。实际调用结果关联模型、Prompt、参数、来源与用量。后续修改作用于新的调用快照。

这里要统一的是配置求值、Prompt 资源、Provider 工厂和诊断关联。世界作者、主体审议者、成长模型和 worker 的输入授权仍由各自 owner 定义。

### 一条消息与持续生活相遇

平台保全完整消息与易失媒体，世界推进到相应的已过区间，通知参与注意竞争。主体打开选定内容后，实际模型输入与消费记录关联，后续形成长期认识。日历计划、实际见闻、后台已下载内容与形成认识具有各自身份和时间。

这个路径要求完整消息与媒体、带域时间、当前世界/活动、实际消费和来源通路同时成立；把所有数据都压成 `{content:string}` 会让后续补回成本更高。

### 后台执行、成果查看和对外后果

主体正式决定开始任务。OpenClaw 保留工具循环、子代理、历史、浏览器与隔离环境；Hept 只保有自己的目标、资源与原生任务关联。完成后成果待查看，主体实际查看选定结果才形成自身接触。表达经当前权限交给真实平台发送；accepted、确定未提交和 unknown 的后续行为各自清楚。

执行框架负责恢复运行，领域 owner 负责结果意味着什么。一次已发生外部效果后的认知整理失败，不重新发送原内容。

### 改钟、重启和历史查询

Hept 改变一段世界时间映射，既有已实现事件和引用仍可解释；待发生世界期限重新投影为现实等待。停机按明确政策协调。Nous 查询“故事中当时已知”与“现实数据库当时已记录”可以给出不同结果。纯历史读取不为填空白而生成新事件或付费模型工作。

这个路径决定时域、分段、修订、五轴、真实调度和领域高水位的合同。一个当前投影公式只承担其中一次数值计算。

## 真正复用的选择方法

先检查已有完整模块能否直接承担机制，再确定项目特有语义的最小改动位置。采用分为直接依赖、原模块迁入、复制改编和确有独有含义的自研；每项最终设计写明选定方式与文件。

- 模型协议与多步工具调用使用 AI SDK；专业任务使用 OpenClaw 原生实现。
- 日期、时区与重复日程使用 Temporal 与成熟 RFC 5545 实现，保留已经写出的正确业务规则与纯计算。
- 网络复用 Undici 的连接、代理、流和取消，产品维护授权资源与网络策略的绑定。
- 配置校验、对象合并、数据库事务、Schema/Client、日志、追踪和本地化使用成熟库，产品定义字段、作用范围、采纳与生效含义。
- 原 Nous PromptRegistry、原 Hept 日历/消息纯处理和已形成算法优先直接迁入，再改它们与新 owner 之间的依赖。MaiBot、AstrBot、QQContextBot 的可采用模块在研究文档定位到真实源文件。

语言属于实现选择。采用现有模块时比较依赖闭包、运行部署、接口数量和改编量，选择能真正减少整体维护的组合。不会为维持某一种语言而重写一个成熟执行器，也不会为了一个无独立生命周期的小函数额外部署整个宿主。

## 何时有理由退出一项旧机制

当某项内容只是另一 owner 的可变副本、转发包装、手工实现的库能力、已被成熟框架承担的运行步骤，或已不存在真实产品消费者时，在新结构中整体移除。原事实、有效纯函数、算法和真实产品场景由负责 owner 承接。

对于仍有消费者的行为，先确定由谁提供完整结果，再删除原路径。当前查询、时间、认知和 Hept 生活功能的缺失，属于本轮需要恢复的设计，不是功能退出依据。
