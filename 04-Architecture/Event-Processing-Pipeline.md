# 事件处理管线

## 阶段

1. **接收**：验证来源、记录原始载荷、生成接收 Trace。
2. **规范化**：转换消息段、平台动作和时间字段。
3. **去重排序**：幂等键、序列和延迟事件处理。
4. **身份解析**：平台身份、人物、会话和 Agent 自身。
5. **事实提交**：事件先写入 Ledger，再触发后续处理。
6. **确定性投影**：消息可见状态、成员、任务和发送状态。
7. **会话路由**：进入对应 Mailbox。
8. **观察聚合**：合并消息和派生结果。
9. **唤醒判断**：行动、等待、静默、取消或暂停。
10. **认知与行动**：上下文、行为、工具和表达。
11. **Outbox**：延迟、取消、发送和回执。
12. **后台沉淀**：记忆候选、情节、统计和评估样本。

## 顺序原则

事件必须先持久化再产生不可逆副作用。状态更新和发送不能依赖仅存在于内存中的模型响应。

## 背压

群聊突发流量时，Mailbox 可执行：窗口延长、低价值事件摘要、媒体延后、最大并发限制和过载静默。背压策略本身需要进入 Trace。
