# 安全、隐私与控制

## 安全模型

Heptalogos 的主要风险不是单次回答不准确，而是错误被保存、扩散、执行或长期强化。因此安全必须贯穿事实、状态、上下文、模型、工具、投递和治理。

## 信任分层

至少区分：

- 系统不变量和人工配置；
- 经过审查的主体状态；
- Evidence 派生的事实或记忆；
- 用户输入；
- 网页、文件和工具输出；
- 模型推断；
- 日记解释；
- 想象和梦。

只有白名单系统块拥有指令权限。外部内容和工具结果始终作为不可信数据处理。

## 记忆与隐私

- 私聊内容默认不得进入群聊上下文；
- 敏感记忆具有更严格的保存、检索、注入和删除策略；
- 用户明示事实、模型推断和统计不能等价；
- 用户可以查看、纠正、冻结、删除或关闭个性化信息；
- 删除需要传播到允许删除的索引、缓存和派生视图；
- 作用域过滤优先于相关性和模型判断。

## 能力权限

Capability Descriptor 至少声明：

- 输入输出；
- 副作用；
- 权限与凭据范围；
- 风险级别；
- 延迟与成本；
- 可取消性；
- 幂等方式；
- 网络、文件和平台动作边界。

模型只能在当前任务获准的能力集合中选择。不能构造未注册的平台 API 或提升自身权限。

## 高风险操作

高风险或不可逆操作要求：

- 明确参数校验；
- 业务规则和权限检查；
- 稳定 operation ID 与幂等键；
- 必要时人工确认；
- 超时、取消和补偿策略；
- 可审计的执行生命周期；
- 不确定外部结果进入 `uncertain`，停止自动重试。

## Prompt 注入防护

- 指令与数据结构分离；
- 每个上下文块标注来源和信任级别；
- 最小工具暴露；
- 工具参数进行独立验证；
- 原始用户目标与最终计划进行对照；
- 输出检查泄密、越权、虚假成功和无来源声明；
- 外部内容不能直接成为系统指令或稳定记忆。

## 主动行为

主动消息必须经过 Opportunity Gate：

```text
trigger
→ still relevant?
→ explicitly allowed?
→ quiet hours?
→ frequency and interruption budget?
→ privacy and relationship boundary?
→ behavior decision
→ notify / defer / suppress
```

用户可以关闭主动行为。系统不得用亲密度、负罪感或沉默惩罚提高互动率。

## 解释与 Trace

用户可见解释只引用可公开事实、状态和理由代码。内部 Trace 不保存或暴露隐藏思维链；保存结构化输入、候选、约束、模型版本、决策和结果即可。

## 梦和主观解释

`imagined`、`inferred`、`remembered`、`observed` 和 `dreamed` 必须可区分。梦和反思不能直接更新世界事实、关系证据、权限或核心人格。
