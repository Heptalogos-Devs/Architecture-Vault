# 设计原则

## P1 事实优先于状态

事件和外部结果是事实记录；状态是从事实计算出的可重建视图。不要让某个当前 JSON 快照成为唯一历史。

## P2 状态优先于 Prompt

人格、关系、任务和承诺首先是可查询、可约束、可版本化的状态。Prompt 只是某次推理时对状态的临时投影。

## P3 行为优先于文本

先决定是否行动、行动目标和社交姿态，再生成文本。沉默、等待、取消和表情反应也是行为。

## P4 每个长期结论都要有来源

记忆、关系变化和用户画像必须能追溯到事件、提取器版本和置信度。

## P5 异步结果重新进入事件流

工具完成、定时器到期、媒体分析和发送回执都应形成事件，不通过隐藏回调直接修改上下文。

## P6 核心领域不感知平台和模型 SDK

平台特性与模型差异通过端口和能力描述进入核心。平台字段仍然是领域事实，但具体 SDK 类型不能泄漏。

## P7 受控自主

主动机会、权限决策和具体行动是三件事。主动行为必须经过预算、风险和关系边界检查。

## P8 可回放优先

无法重放的系统难以研究。关键决策输入、状态版本、检索依据、模型版本和行动结果都应进入 Trace。

## P9 渐进式复杂度

只有当实验显示简单机制不足时，才引入图记忆、多 Agent、分布式事件总线或复杂心理模型。

## P10 术语不绑定实现

领域概念、组件名称、数据库表和公开 API 分开演化。当前工作名称不构成长期兼容承诺。

## Interaction Gateway 对原则的具体化

- **证据先于解释**：平台 bytes 先成为 Evidence；Canonical 是可追溯解释，不覆盖
  原始观察。这是 P1、P4 和 P8 的共同落点。
- **权威边界先于部署边界**：Evidence、Canonical、Feed、Intent、Plan、Outcome
  分开建模，即使它们暂时运行在同一进程。微服务不是边界成立的前提。
- **诚实表达不确定性**：外部调用不存在本地 exactly-once。request 已记账而 response
  缺失时使用 `uncertain`，宁可人工对账，也不以自动重试制造重复副作用。
- **派生最小化，原始可回放**：allowlist 限制进入认知和资产管线的内容，不删减
  Adapter 已观察到的 raw evidence。
- **复杂度由故障语义驱动**：SQLite、轮询和单包多角色是当前刻意选择；只有吞吐、
  隔离或团队边界被测量证明不足时，才引入 broker 或微服务。
