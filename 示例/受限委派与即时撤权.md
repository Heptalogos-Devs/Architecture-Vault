# 受限委派、私有结果与即时撤权

沿[身份权限与密钥](../设计/基础设施/身份权限与密钥.md)的 DelegationScope、Actor、Consumer 和 TargetScope；对象及时间直接使用[共同值](../设计/基础设施/共同值与调用上下文.md)。

## 阅读任务的服务范围

System 管理员为一个已采纳任务签发下面的 scope。subjectId、taskRef、messageRef、mediaRef、clockRef 都来自 Hept 正式对象，runtime/session 绑定由真实 OpenClaw 宿主取得。凭据由 Better Auth 保存，业务 scope 由 product delegation 持有。

```ts
const scope:DelegationScope = {
  plane:'subject',
  operations:['messages.read','media.read','clock.read','clock.capture'],
  subjectIds:[subjectId],
  consumer:{kind:'worker',host:'openclaw',id:'study-reader'},
  purposes:['task.read'],audiences:[],
  targets:[
    {kind:'object',refs:[messageRef,mediaRef],actions:['read']},
    {kind:'object',refs:[clockRef],actions:['read','capture']},
  ],
  inputRefs:[messageRef],taskRef,
  nativeBinding:{runtimeId:'openclaw-main',sessionId,rootTaskId:taskRef.id},
  notBefore:{domainId:'real',at:'2026-10-21T00:00:00.000000Z'},
  expiresAt:{domainId:'real',at:'2026-10-21T01:00:00.000000Z'},
  mayDelegate:false,
};
```

入口从实际 apiKeyId 找到 active delegation，并核对这个 scope 与本次目标。模型提交任务业务输入，无法改 Consumer、Subject、purpose、目标和有效期。普通 authorization 或 clock.read 不写 TimeCapture；真正消费/形成时由执行 owner 分别使用稳定阶段身份调用 clock.capture。

连接 Nous 时另由 Nous 签发自己的受限服务委派，绑定同一 worker Consumer 和选定 Material；两产品 SDK 分别使用各自凭据，不共用一个跨安装万能 key。

worker 可读获准输入并保存自己的私有结果。它没有发布或外部发送操作；已有 taskRef、runId 或秘密引用都不会增加范围。可信 worker 宿主若另有 `materials.publish` 授权，可选定已保存区域发布给同一 Subject，保留来源限制；主体真正选读后才有自己的接触。

## 等待期间撤权

管理员撤销 parent delegation。后续读取、模型调用和原生工具 handoff 重新取得当前 parent/child 状态并停止。仅有旧冻结输入、队列位置或原 API key 字符串不使其继续有效。

另一项已获发送权的表达若在 staging 后遭撤权，真实平台 handoff 前的当前授权检查使尚未派发的 call 停止。已保存 accepted 的 call 只补交后续事实；unknown 沿原 intent 核实。检查凭据有效期使用 real，世界倍率和暂停不会延长有效期。

SecretRef 留在实际资源配置。withSecret 只在实际 SDK 回调中交付秘密，明文不进入任务输入、Prompt、DBOS checkpoint 或 trace。正常管理不可用时，本机 Recovery 验证安装所有者和固定引导范围后执行指定认证修复，再通过真实登录确认结果。
