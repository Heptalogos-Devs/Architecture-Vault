# 时钟变速、重投影与阶段捕获

使用[时间合同](../设计/基础设施/时间与调度.md)的 TimePoint、ClockRef、ClockSegment 和 TimeCaptureReceipt，以及[共同 Ref](../设计/基础设施/共同值与调用上下文.md)。以下数值是一条可复算场景；操作名和字段沿正文，不另设执行协议。

## configure 与变速

时间域为 `world:study`，操作者已获该域的时间管理权。首次 `clock.configure` 以 expectedRevision=0 建立 head；初始坐标为 `2026-01-01T08:00:00.000000Z`，rate=`'60'`，offlinePolicy 为 freeze。成功返回 Clock revision 1，初段 realAnchor 为 `2026-10-21T00:00:00.000000Z`。ClockRef 的 revision 从 1 开始。

一项活动的世界 due 是 `{domainId:'world:study',at:'2026-01-01T08:30:00.000000Z'}`。`clock.projectDeadline` 对当前 snapshot 的纯计算得到现实 `2026-10-21T00:00:30.000000Z`；Hept 保存该节点的 clockRevision=1、segmentRef 和稳定 workflowId，再交 DBOS 等待。

现实十秒后，在线单调推进到世界 08:10。操作者用原 ClockRef、expectedRevision=1 调用 `clock.configure`，把 rate 改为 `'2'`。事务先取得旧段当前点，把原段的 closure 保存到 clock_changes.receipt，再建立下面的新段；head 与修订原子提交，原锚点对象不改写。

```ts
const segment:ClockSegment = {
  ref:{product:'hept',installationId:'hept-study',kind:'ClockSegment',
       id:'019a0000-0000-7000-8000-000000000002'},
  clockRef:{product:'hept',installationId:'hept-study',kind:'Clock',
            id:'019a0000-0000-7000-8000-000000000001',revision:2},
  domainId:'world:study',revision:2,
  domainAnchor:'2026-01-01T08:10:00.000000Z',
  realAnchor:'2026-10-21T00:00:10.000000Z',rate:'2',
  startedByOperationId:'study/change-rate',reason:'change_rate',
};
```

剩余二十个世界分钟按 rate 2 投影，新的现实 due 为 `2026-10-21T00:10:10.000000Z`。改钟后原 DBOS 工作流持有的传播步骤为该节点启动新修订的等待。旧等待在 00:00:30 醒来，读取到 clockRevision=2，结束自己的旧安排；它不执行活动。新等待到期后仍检查节点、Clock、当前来源和行为权限。

## read、observed 与 formed

`query.prepare` 只预览。新 `query.run` 用一次 `clock.read` 固定相对时间，expand/续页沿该 run；这些读取不生成 capture receipt。

主体稍后实际把材料交给一次模型调用。父操作为 `study/answer`，第 1 步的两个正式捕获使用不同稳定子身份：

| 边界 | 时间操作身份 | 正式结果 |
|---|---|---|
| 输入真正被本次执行采用 | `study/answer/step1/observed` | 保存观察点与 TimeCaptureReceipt |
| 原模型成果形成并保存 | `study/answer/step1/formed` | 保存该成果自己的形成点与另一份 TimeCaptureReceipt |
| observed 响应丢失后恢复 | 仍为 `study/answer/step1/observed` | 返回原 captureRef 和原 point |
| 采用已保存成果 | 复用原 formed receipt | recorded 使用这次现实提交点 |

每个 captureRef 都是时间 owner 生成的 TimeCapture 产品 Ref，clockRef 固定相应正修订，segmentRef 指向实际不可变段。captureId 与父模型 operationId 分别保存。SDK 的稳定提交身份经 Idempotency-Key 形成 ctx.trace.operationId，业务 body 不复制它。HTTP 纯读取为 `POST /v1/time/read`，configure 为 `POST /v1/time/clocks/configure`，捕获为 `POST /v1/time/captures`；Clock 对象 inspect/history 使用 `/v1/time/clocks/{clockId}` 及 `/history`。独立应用域可省略 subjectId。

独立 Nous 直接用 real 域时，正式 receipt 可以没有 Clock/ClockSegment；captureRef 仍定位实际 Nous 时间 owner。Subject Bundle/恢复纳入这些 receipt 及引用段，映射高水位覆盖已保存捕获。
