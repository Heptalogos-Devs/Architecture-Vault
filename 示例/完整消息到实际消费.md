# 完整消息、媒体保全与主体消费

使用[媒体合同](../设计/基础设施/媒体与材料基础.md)中的 MessageRevision、MessagePart、MediaRevision、Representation 和 Coverage。[时间合同](../设计/基础设施/时间与调度.md)规定实际观察与形成的独立捕获。

## 原生收件与正式消息

OneBot 收到一条群消息。完整 raw payload 先保存为 Blob；其中 message 数组按原顺序含文字、at、图片、forward 和一个插件暂不理解的 native 段。原生连接保留账号 `qq-main`、会话 `group:20001`、平台消息 `70001`，不把平台数字装入产品 ObjectId。

接纳后形成如下正式 MessageRevision。这里的 rawRef、imageMediaRef、forwardRef 均为本安装实际创建的共同 Ref；rawRef 指向完整原件，另外两项分别定位 Media 与 Forward。imageMediaRef/forwardRef 的修订由它们各自 owner 保存。

```ts
const message:MessageRevision = {
  ref:{product:'hept',installationId:'hept-study',subjectId,
       kind:'Message',id:'019a0000-0000-7000-8000-000000000011',revision:1},
  origin:{type:'platform',adapterId:'onebot',accountId:'qq-main',
          conversationId:'group:20001',messageId:'70001'},
  direction:'inbound',
  authorSnapshot:{user_id:10001,nickname:'青鹤',card:'青鹤'},
  platformSentAt:{domainId:'real',at:'2026-10-21T00:00:00.000000Z'},
  receivedAt:{domainId:'real',at:'2026-10-21T00:00:00.140000Z'},
  parts:[
    {partId:'text-0',nativePointer:'/message/0',kind:'text',text:'看这张图和转发。'},
    {partId:'mention-1',nativePointer:'/message/1',kind:'mention',accountId:'10002'},
    {partId:'image-2',nativePointer:'/message/2',kind:'image',mediaRef:imageMediaRef,
     nativeType:'image'},
    {partId:'forward-3',nativePointer:'/message/3',kind:'forward',referenceRef:forwardRef},
    {partId:'unknown-4',nativePointer:'/message/4',kind:'unknown',nativeType:'vendor-widget',
     rawRef:{...rawRef,selector:{kind:'node',pointer:'/message/4'}}},
  ],
  rawRef,policy,lifecycle:'present',
};
```

实时重收与历史补拉用同一个 platform origin 幂等接纳，返回原 Message；编辑/撤回另走 `messages.change`。补拉覆盖和缺口保存于 history 的 Coverage，不把历史收到点当主体过去已经阅读。

## 保全、展开与派生

1. `media.preserve` 按原图片来源取得实际 GIF 字节。MediaRevision 从 pending 经实际获取变为 available，保存 blobRef、digest、bytes、declared/detected 类型和现实 recordedAt。若 URL 已过期则保存 expired，留待同来源核实。
2. `messages.references.expand` 取得原生 get_forward_msg 的真实结果，保留作者、发送点、父子 pointer、完整 parts 和 raw。若本步到达限额，返回 partial Coverage 与 continuation，原消息不变。
3. 需要理解 GIF 时，正式派生角色取得采样帧，生成 Representation。它保存 inputRefs、producer、formed:TimeCaptureReceipt 和 sampled Coverage；原动画字节继续保留。

收件、上述保全和后台派生只产生资料及待看通知。主体此时尚无这条消息的实际消费记录。

## 选定并真正消费

主体选择打开 Message revision 1 的 image-2。选区是同一消息上的 `{kind:'part',partId:'image-2'}`；Media read 返回当前获准的固定媒体修订。接入 Nous 时，正式 `materials.capture` 保存选定原件或表示，并以精确 Hept Ref 建立 source.inputs；传播限制沿当前源 owner 查询。

本次模型最终输入若只包含 GIF 的采样帧，则执行 owner 保存这些实际帧/表示的 fixed portions 和 sampled Coverage。实际派发点用该步 observed 子身份取得 TimeCaptureReceipt；结果保存后 encounters.accept 记录真实 Consumer、portion 和 invocation。若随后形成记忆或新视觉描述，各成果取得自己的 formed receipt。

未选择的转发节点与 unknown 段仍可继续打开；它们没有因本次图片读取而整体变为已读。图片说明在 worker 私有范围产生时，先由受信 worker 宿主 `materials.publish` 选定已有结果；主体选看 publishedRef 后，按同一实际消费链记录。

表达若包含文字和文件，原生 sender 保存逐次物理调用及 expressionPartRefs。一项 accepted、一项 unknown 时，Hept 保留各自事实和原生 intent；恢复只核实 unknown，不重复提交已接受文字。
