# 更新规则

## 代码变化

更新 `Current-State.md` 和相关 `04-Engineering` 文档。

## 目标或理念变化

更新 `01-Vision` 或 `03-Concepts` 的主文档，不追加平行版本。

## 系统边界变化

更新 `02-System`；若影响多个模块和长期数据，再更新或新增 Decision。

## 实验结果

记录在 `06-Research`，并把被证实或否定的认识回写正式主题。

## 未整理输入

放入 `07-Inbox`。不需要分类正确，后续直接整理。

## 过时内容

优先删除或改写。只有仍需在当前树中解释时才标 `archive`；普通历史由 Git 保存。
