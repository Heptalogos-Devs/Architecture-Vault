# 认知领域与知识边界

- **状态**：Concept
- **主题**：限制基础模型知识，使其符合具体角色

## 1. 问题

基础模型被训练为容纳广泛知识，但真人并非对所有领域都同样了解。

如果不进行约束，可能出现：

- 儿童人格却能够系统解释高级物理；
- 普通人对陌生专业表现得像专家；
- 资深游戏玩家反而不知道自己常玩游戏的基础操作；
- 同一角色的专业水平随当前问题任意变化；
- 所有角色最终都表现为同一个基础模型。

因此必须区分：

```text
Foundation Model Capability
```

和：

```text
Agent Epistemic State
```

基础模型代表潜在生成能力；  
认知状态代表该主体实际上知道、相信、掌握和能够表达的内容。

## 2. 认知状态不应是二元值

一个主题至少可以区分：

### Unknown

完全不了解，甚至没有听说过。

### Aware

听说过，但缺少具体认识。

### Familiar

具备普通交流所需的一般理解。

### Expert

拥有系统知识、实践经验和深层判断能力。

还可补充：

- 错误认知；
- 模糊记忆；
- 不确定；
- 曾经知道但当前难以召回。

## 3. 知识领域需要分解

不能简单记录：

```text
games = expert
```

同一领域可能包含：

- 基本操作；
- 剧情和世界观；
- 竞技策略；
- 社区文化；
- 开发历史；
- 亲身经验。

一个角色可能熟悉剧情却不擅长操作，也可能操作很强但不关心设定。

## 4. 知识来源

知识应尽量具有符合角色经历的来源：

- 学校学习；
- 职业训练；
- 长期兴趣；
- 亲身实践；
- 他人告知；
- 阅读或观看；
- 网络搜索；
- 当前推理。

来源会影响表达方式和可信程度。

例如：

```text
我自己玩过。
```

与：

```text
我刚查了一下。
```

应表现为不同的认知来源。

## 5. 一般推理能力与领域知识分离

不知道某领域，不等于缺乏一般推理能力。

主体仍然可以：

- 提出问题；
- 使用常识；
- 进行类比；
- 识别明显矛盾；
- 在解释后快速理解。

因此应分别建模：

```text
General Reasoning Capacity
```

和：

```text
Domain Knowledge
```

## 6. 知识边界对行为的影响

当主体被问到陌生问题时，可以有不同反应：

- 承认不知道；
- 表达模糊印象；
- 请求解释；
- 主动搜索；
- 没有兴趣继续；
- 出于人格原因装懂。

“是否主动获取知识”本身也应受人格、关系和当前活动影响。

## 7. 知识越界审查

仅依赖 Prompt 通常不够可靠。  
较稳妥的概念流程是：

```text
识别问题所属领域
  ↓
查询主体的认知状态
  ↓
限制允许使用的知识深度
  ↓
形成初步内容
  ↓
检查是否越界
  ↓
必要时降级或重写
```

需要检查的越界表现包括：

- 过高术语密度；
- 不合理的精确细节；
- 复杂推导；
- 不符合经历的熟练操作；
- 无来源的权威式结论。

## 8. 工具知识与自身知识

未来主体可以使用搜索、计算和其他工具，但应区分：

- 原本就知道；
- 刚刚查到；
- 别人告诉；
- 当前推断；
- 不确信的记忆。

使用工具后，不应表现为主体一直拥有该知识。

## 9. 与其他系统的关系

认知边界应参与：

- 回复生成；
- 生活事件合法性检查；
- 兴趣和目标；
- 关系互动；
- 日记与记忆；
- 自我叙事。

例如，一个几乎不懂编程的角色，不应在自己的生活时间线上声称刚刚完成复杂编译器调试。

## 10. 实现参考

早期可用“领域 + 熟悉度 + 来源 + 置信度”的轻量模型。  
不必立即构建完整知识图谱，但必须确保基础模型的全部知识不会未经限制地直接暴露为角色知识。
