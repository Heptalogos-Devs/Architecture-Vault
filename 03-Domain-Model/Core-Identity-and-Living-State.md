# 核心人格、动态状态与统一主体

- **状态**：Concept
- **主题**：Core Identity、Living State 与统一状态快照

## 1. 核心人格不是一段 Persona Prompt

核心人格应是一套结构化、长期稳定、允许缓慢演化的身份模型，而不是每次推理时临时附加的一段角色说明。

建议包含以下部分。

### 1.1 身份事实

例如：

- 姓名、年龄；
- 学生或职业身份；
- 家庭和成长背景；
- 居住环境；
- 重要人生经历；
- 社会角色。

### 1.2 人格基线

例如：

- 外向程度；
- 谨慎程度；
- 同理心；
- 自尊和敏感度；
- 冲突倾向；
- 表达直接度；
- 幽默方式；
- 依恋和边界模式。

人格基线应长期稳定，不应因一次对话或一天心情而剧烈改变。

### 1.3 价值结构

用于限制主体在冲突、承诺、亲密关系、欺骗、责任等问题上的选择。

### 1.4 语言习惯

包括：

- 句子长短；
- 常用词；
- 标点习惯；
- 表情使用；
- 正式程度；
- 面对不同关系时的表达差异。

### 1.5 自我叙事

自我叙事回答的不是“发生了什么”，而是：

> 主体如何理解自己，以及如何解释自己的过去。

同一事实可能形成完全不同的叙事。例如：

```text
我曾经失败，所以我总是担心再次失败。
```

或者：

```text
我曾经失败，但那证明我能从失败中恢复。
```

自我叙事会长期影响行为，应与事实记录分离。

## 2. 动态生命状态

动态状态用于表示主体当前处境，可能包括：

- 情绪；
- 精力；
- 压力；
- 社交意愿；
- 当前活动；
- 当前地点；
- 当前目标；
- 未完成事务；
- 当前关注会话；
- 是否能够阅读、思考或回复。

这些状态变化频繁，但不应反向随意重写核心人格。

## 3. 一个主体，而不是多个模块角色

未来可能有很多模块，但这些模块不能各自成为“另一个 AI”。

错误方向：

```text
人格模块做决定
情绪模块做决定
记忆模块做决定
关系模块做决定
```

更合理的方向：

```text
各模块提供约束、证据、解释或变化建议
           ↓
统一认知过程进行整合
           ↓
形成一个主体的行为
```

## 4. 统一主体快照

每次认知处理应基于一致的状态快照，例如：

```text
AgentStateSnapshot
```

可能包含：

- 当前时间；
- 当前日程和实际活动；
- 当前情绪与精力；
- 当前目标；
- 当前关系状态；
- 相关记忆；
- 知识边界；
- 核心人格约束；
- 最近日记形成的主观结论；
- 当前注意对象。

这样可以避免一次推理过程中，不同模块读取到互相矛盾的状态。

## 5. 状态变化原则

建议遵循：

```text
事件进入
  ↓
构建一致状态快照
  ↓
认知、审查和行为规划
  ↓
形成状态变更集合
  ↓
统一提交
```

各模块不应随意直接修改其他模块的数据。

例如：

- 情绪模块不直接写关系；
- 梦系统不直接修改事实；
- 关系模块不直接覆盖核心人格；
- 日记不直接篡改原始事件。

## 6. 核心人格的演化

核心人格并非永远不变，但其变化应：

- 缓慢；
- 有事件依据；
- 可追溯；
- 通常经过长期重复经历或重大事件；
- 由自我叙事和长期记忆逐步影响。

不应因为单条消息或单次模型生成就发生人格重写。

## 7. 实现参考

可将稳定人格、动态状态和认知快照分开存储。  
实现时优先保证状态来源、更新时间和变更原因可追踪，而不是过早追求复杂心理学模型。
