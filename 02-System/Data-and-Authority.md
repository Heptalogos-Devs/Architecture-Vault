# 数据、事实与权威边界

## 数据不是一个万能事件表

Heptalogos 将不同问题交给不同权威记录：

| 数据 | 回答的问题 |
|---|---|
| Evidence | 某个边缘适配器实际观察或执行了什么？ |
| Canonical | 平台中立层认定发生了什么交互事实？ |
| Feed | 哪些事实尚未被某个认知消费者确认？ |
| Subject State | 主体当前身份、活动、关系、任务和认识是什么？ |
| Memory | 哪些经历或知识可以在未来影响认知？ |
| BehaviorIntent | 主体决定采取什么行为及其社会目标？ |
| ActionPlan | 哪些可执行、可取消、有时效的步骤已获批准？ |
| DeliveryPlan | 具体平台端点将如何执行通信意图？ |
| Outcome | 外部副作用最终可被确认为什么状态？ |
| Trace | 一次行为基于什么输入、版本、模型和策略形成？ |

不要用一个 JSON 同时表达观察、解释、决定和结果。

## 追加和投影

优先追加保存：

- 原始观察；
- 规范事实；
- 修正和删除命令；
- 状态变更原因；
- 行为、计划和外部结果；
- 人工管理操作。

当前状态、索引、会话视图和统计通常是投影。无法重建的字段必须明确标识，不能隐含在快照里。

## 主体状态

主体状态按生命周期拆分：

- Core Identity：稳定身份、价值和边界；
- Living State：当前活动、精力、压力、情绪和注意；
- Relation State：特定人物、群体或会话的社会状态；
- Conversation State：当前话题、窗口和未解决事项；
- Task State：任务、承诺、计划和执行状态；
- Epistemic State：主体知道、相信或掌握什么；
- Narrative State：生活时间线、自我陈述和自传解释。

这些状态不能由单次自然语言输出直接覆盖。

## 记忆不是历史数据库的别名

原始事件、长期记忆、用户画像和检索索引是不同数据产品：

- 原始事件用于审计和重新解释；
- 记忆是有来源、作用域和生命周期的经验表示；
- 用户画像是面向用途的当前视图；
- 索引是可重建投影。

## 作用域

任何可注入认知的数据都必须先通过作用域过滤，再计算相关性。至少考虑：

- 主体；
- 人物；
- 会话；
- 群体；
- 平台；
- 数据敏感度；
- 允许用途；
- 有效时间。

高语义相似度不能覆盖隐私边界。

## SQL 和存储策略

早期以 SQLite WAL 和本地 CAS 为主：

- 事务用于状态、游标、lease、Outbox 和幂等；
- FTS 用于全文和混合检索；
- 媒体与大对象进入内容寻址存储；
- 向量数据库、图数据库和消息代理只有在实验或负载证明必要后引入。

物理上可以合并数据库，但数据所有权和 Repository 边界仍应明确。
